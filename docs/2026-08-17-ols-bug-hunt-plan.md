### Wave 1 — Functional (ล่าบั๊กที่ลูกค้ากำลังจะเจอ)

#### W1a · Task-delta sweep — ปิดรูที่ใหญ่ที่สุด

**เป้า:** Task `[Improve]` ทุกใบที่แตะหน้าจอผู้ใช้ ที่ Done ใน 30 วัน (~45 ใบ) + Task ค้าง 19 ใบ
**วิธี:** ต่อ 1 Task → ตอบ 3 คำถาม แล้วเทสจริง

1. **มันไปแก้หน้าไหน** (surface) — ไม่ใช่แค่ AC ของใบนั้น
2. **หน้านั้นเคยมี TC ของ Story ไหนคลุมอยู่** — ถ้ามี ให้รัน TC ชุดนั้นซ้ำ (นี่คือ regression ที่หายไป)
3. **หน้านั้นมี state อื่นอีกกี่แบบ** (role × สถานะเนื้อหา × ว่าง/มีข้อมูล/ข้อมูลล้น) — เทสให้ครบ ไม่ใช่แค่ happy path

**สิ่งที่ต้องได้ออกมา:** TC ใหม่ต่อ Task ที่ยังไม่มี → เข้าชุด regression ถาวร
(ไม่งั้นรอบหน้าก็หลุดเหมือนเดิม — นี่คือการแก้ที่ต้นเหตุ ไม่ใช่ไล่จับรายตัว)

**ตัวอย่างเคสจริงที่ต้องเทส:**
- OLS-318 ชื่อยาวเกิน 2 บรรทัด → ต้องเทสชื่อยาวสุด/สั้นสุด/1 คำยาว/ภาษาผสม บนการ์ด **ทุกชนิด** (สื่อ·คอร์ส·LP·badge) ไม่ใช่แค่การ์ดเดียว
- OLS-362 sidebar ตามสิทธิ → เทสครบ **5 role** + role ที่ถูกลดสิทธิระหว่าง session
- OLS-404 ชื่อสิทธิบน nav bar → ผู้ใช้ที่มีหลาย role พร้อมกัน แสดงอะไร
- OLS-400 ไม่โชว์สื่อที่เรียนจบไว้ลำดับแรก → บัญชีที่เรียนจบ 0 / บางส่วน / ทั้งหมด

#### W1b · Cross-surface sweep — เลิกเทสแค่ AC

**ปัญหาที่พิสูจน์แล้ว:** บั๊ก 134 ของลูกค้า — เราเทส *การ์ด* ผ่าน แต่บั๊กอยู่ที่ *หน้ารายละเอียดคอร์ส*
เพราะขอบเขตตรวจ = AC ของใบนั้น ไม่ใช่ทั้ง flow

**วิธี:** เดินเป็น **user journey เต็มเส้น** ไม่ใช่ต่อ ticket — 8 เส้นหลัก

| เส้น | เดินจาก → ถึง | role |
|---|---|---|
| J1 | เข้า landing → เลื่อนดูทุก section → คลิกการ์ดทุกชนิด → กลับ | guest |
| J2 | login → feed → เลือกกลุ่มเป้าหมาย → เข้าสื่อ → เรียนจบ → badge | learner |
| J3 | ค้นหา → กรอง → เรียงผล → เปิดรายละเอียด → บันทึก/ถูกใจ/แชร์ | learner |
| J4 | สร้างสื่อ (ทุกประเภท) → ส่งตรวจ → แก้ → เผยแพร่ → ยกเลิกเผยแพร่ | creator |
| J5 | สร้างคอร์ส → ผูกสื่อ → สร้าง LP → ผูกคอร์ส → เผยแพร่ | creator |
| J6 | live: เริ่ม → แชร์จอ+กล้อง → จบ → ระบบสร้าง draft → เผยแพร่ → ดูย้อนหลัง → กดข้าม | creator + learner |
| J7 | รายงานเนื้อหา → ชุมชนคัดกรอง → admin อนุมัติ/ปฏิเสธ → สถานะกลับ | learner + admin |
| J8 | โปรไฟล์ของฉัน / ช่องของฉัน → แก้ข้อมูล → ดูเนื้อหา/ติดตาม/badge | learner + creator |

**กติกาของทุกเส้น:** ทุกหน้าที่ผ่าน ต้องเช็ค 5 อย่างเสมอ แม้ไม่มี AC บอก
(ล้นขอบ · ทับซ้อน · ปุ่มกดไม่ติด · state ว่าง · state ข้อมูลล้น)

**fixture ต้องไม่ขั้นต่ำ** — RCA พบว่า fixture 1 คอร์ส 1 สื่อ ทำให้ layout ไม่มีทางล้น จึงไม่เจอบั๊ก
→ ต้องมีบัญชีที่มี **เนื้อหาเยอะพอจะล้น** (badge > 4 ใบ · การ์ด > 1 แถว · ชื่อยาว · คอมเมนต์เยอะ)

#### W1c · Fixed-bug regression — 147 ใบที่เพิ่งแก้

### Wave 2 — Non-functional (มิติที่บอร์ดแทบไม่มี)

วัดด้วยตัวเลข ไม่ใช่ "ดูแล้วโอเค" — ทุกข้อมีเกณฑ์ผ่าน/ไม่ผ่านชัด

#### W2a · Responsive — **รายงานอย่างเดียว ห้ามเปิด Bug ticket** (มติ 17 ส.ค.)
- breakpoint: **320 · 375 · 599→600 · 899→900 · 1280** (เกณฑ์มาจาก OLS-325 เอง: hamburger < 900, dialog เต็มจอ < 600)
- หน้า: 12 หน้าหลักจาก J1–J8
- เกณฑ์ผ่าน: `document.scrollWidth <= innerWidth` **และ** ไม่มี element ที่ `rect.right > innerWidth`
- วิธีนี้พิสูจน์แล้วว่าใช้ได้ (เคยจับ element ล้น 6 ชิ้น ปุ่ม right=378 > 375)

#### W2b · Performance
- **หน้าเว็บ:** LCP · CLS · INP · TTFB ต่อหน้า (Playwright + web-vitals) — ตั้ง budget แล้ววัดซ้ำทุกรอบ
- **API:** p95 latency ของ endpoint หลัก (feed · media list · search · course detail)
- **จุดที่รู้ว่าเสี่ยงอยู่แล้ว:** personalized feed (OLS-440 tuning ยังไม่ทำ) · live → draft publish ช้า (OLS-516 open)
- **ข้อมูลเยอะ:** หน้าที่มีการ์ดหลายร้อยใบ / คอร์สที่มีสื่อหลายสิบ / LP ที่มีคอร์สหลายสิบ

#### W2c · Security (คุยกับ OLS-379 ก่อน กันซ้ำ)
เน้นสิ่งที่ pentest tool มักไม่จับ = **authz ตาม business logic**
- **เมทริกซ์สิทธิ 5 role × endpoint หลัก** — ยิง API ตรงด้วย token ของ role ต่ำ ไปที่ของ role สูง
- creator A แก้/ลบเนื้อหาของ creator B ได้ไหม (horizontal escalation)
- เปิด URL ตรงของเนื้อหา DRAFT / UNPUBLISHED / FLAGGED ของคนอื่น
- บัญชีถูกระงับ (ban) ยังใช้ token เดิมยิง API ได้ไหม
- สิทธิที่เปลี่ยนกลางคัน (creator → learner) session เดิมยังทำของเดิมได้ไหม

#### W2d · Reliability / data integrity
- **นับ view:** อ่าน `viewCount` จาก API ก่อน/หลังดูจริง (เคยพบไม่ขยับ 1→1)
- **progress:** OLS ผูก progress **ต่อสื่อแบบ global ไม่ใช่ต่อการลงทะเบียน** → เรียนคอร์สเดียวกันใน LP อื่นต้องนับตาม ยืนยันว่าไม่เพี้ยน
- **report → flag:** 3 รายงาน = auto-flag → นับถูกไหม, สื่อที่ถูกรายงานยังนับ view อยู่ไหม (OLS-515 open — ห้ามเปิดซ้ำ)
- **live pipeline:** จบ live → draft → เผยแพร่ ครบทุกครั้งไหม, ใช้เวลาเท่าไร (OLS-516)
- **สถานะเนื้อหา:** ใช้ `status` ตัดสินเสมอ **ห้ามใช้ `reviewStatus`** (ค้างที่ APPROVED ไม่ตามสถานะจริง)

#### W2e · i18n / ข้อความ
- ชื่อไทยยาว/สั้น/คำเดียวยาว/ไทย+อังกฤษผสม/อักขระพิเศษ/emoji → ตัดคำ, ตกบรรทัด, ล้นกรอบ
- ข้อความ error/toast ครบทุกภาษาเดียวกันไหม, มีที่ยังเป็นอังกฤษค้างไหม

#### W2f · Cross-browser — **อยู่ในขอบเขต** (มติ 17 ส.ค.)
ลูกค้าเทส **Chrome + Edge** → รันชุด J1–J8 เดียวกันทั้ง 2 เบราว์เซอร์ แล้ว **diff ผลทีละหน้า**
สิ่งที่ต่างกันเท่านั้นที่เป็นของจริง (ไม่ใช่ไล่ดูทีละหน้าด้วยตา). Safari = ช่องว่างที่ยังไม่มีใครดู — เสนอเป็นรอบถัดไป

#### W2g · Accessibility — **อยู่ในขอบเขต** (มติ 17 ส.ค.)
axe-core อัตโนมัติ + คีย์บอร์ดล้วน + contrast บน 12 หน้าหลัก
**ยังไม่มีเกณฑ์ของโปรเจกต์** → ยึด **WCAG 2.1 AA** เป็นข้อเสนอ แล้วส่งลิสต์ให้ PO เคาะว่าอันไหนนับเป็นบั๊ก
ก่อนเปิด ticket — ห้ามเปิดรัวโดยยังไม่มีสเปครองรับ (กฎ: สเปคไม่ชัด = คำถาม ไม่ใช่บั๊ก)

## 4. แผนที่ test type (ตาม testing pyramid)

| ชั้น | ใครทำ | คลุมอะไรของแผนนี้ | ความถี่ |
|---|---|---|---|
| **E2E (บน)** | Playwright ใน `ols-qa-e2e` + self-hosted runner ที่รันอยู่แล้ว | J1–J8, responsive, web vitals, a11y scan | ทุก deploy + nightly |
| **Integration / API (กลาง)** | script ยิง REST ตรง | เมทริกซ์สิทธิ 5 role, data integrity, p95 latency | nightly |
| **Unit (ล่าง)** | ฝั่ง dev | นอกขอบเขต QA รอบนี้ | — |
| **มอนิเตอร์ต่อเนื่อง** | launchd ที่รันอยู่แล้ว | daily-health (เว็บขึ้น/login/API/หน้าไม่ขาว) · name-guard (ชื่อ+ปก) · login-check | 2×/วัน · 11:00+17:00 |

**ของที่มีอยู่แล้วไม่ต้องสร้างใหม่:** repo `ols-qa-e2e` + runner + daily-health + name-guard + SFD heartbeat
**ของที่ต้องสร้างใหม่:** ชุด responsive sweep · เมทริกซ์สิทธิ · web-vitals budget · a11y scan · dedup index

## 7. ลำดับลงมือ (พอเคาะ Wave 0 แล้ว)

1. สร้าง **dedup index** จากบั๊ก 208 ใบ (เก็บนอก repo) — ก่อนเทสอะไรทั้งสิ้น
2. **W1a Task-delta sweep** — เริ่มจาก Task ที่ยังค้าง 19 ใบ แล้วย้อนของที่ Done ใน 30 วัน
3. **W2a responsive** ขนานไปด้วย (อัตโนมัติทั้งหมด ไม่กินเวลาคน)
4. **W1b J1–J8** เรียงตาม P0 ก่อน: J1 landing · J8 profile/channel · J4–J5 creator
5. **W2c เมทริกซ์สิทธิ** + **W2d data integrity** (ยิง API ล้วน รันคู่ขนานได้)
6. **W1c fixed-bug regression** ตาม surface
7. **P2 โมดูลจุดบอด** — NDLP · Backoffice CMS · Dashboard · Social
8. สรุปผล → เปิดบั๊กที่ผ่านประตู 4 ชั้น → **TC ใหม่ทุกอันเข้าชุด regression** (ไม่งั้นรอบหน้าหลุดซ้ำ)

## ภาคผนวก — วิธีวัดที่พิสูจน์แล้วว่าใช้ได้ (ไม่ต้องใช้ตาคน)

| อาการ | วิธีวัด |
|---|---|
| ล้นขอบจอ | `rect.right > innerWidth` **และ** `document.scrollWidth > innerWidth` |
| ข้อความทับกัน | กล่องข้อความ 2 กล่องมีพื้นที่ตัดกัน > 3px |
| นับ view ไม่ขึ้น | อ่าน `viewCount` จาก API ก่อน/หลังดูจริง |
| หน้าขาว / error boundary | Playwright เช็ค DOM ว่าง + JS exception |
| ปุ่มสองทิศทาง (เช่นสลับโหมด) | **ยืนยันสถานะเริ่มต้นก่อนกด** ไม่งั้นได้ผลของทิศตรงข้าม |
