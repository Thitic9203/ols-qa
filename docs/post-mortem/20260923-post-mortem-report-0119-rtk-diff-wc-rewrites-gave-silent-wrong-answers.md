## สรุปสั้น (Executive Summary)

หลังเจ้าของงานอนุมัติมาตรการ #0116 P2 เวลา 14.16 น. config ของ `rtk` ยกเว้น `find` `ls` `grep` ไม่ให้ถูกเขียนใหม่ — เฉพาะ 3 คำสั่งที่เคยพลาด
ระหว่างทำมาตรการต่อ subagent พบว่า `rtk` ยังเขียน `diff` และ `wc` ใหม่แล้วให้คำตอบผิด: `rtk diff` พิมพ์ `[ok] Files are identical` กับไฟล์ที่ต่างกันจริง 1 บรรทัด · `wc -l < file` พิมพ์ `0` กับไฟล์ 20 บรรทัด (`/usr/bin/wc` ได้ 20)
เจ้าของงานอนุมัติเพิ่ม `diff` `wc` ในรายการยกเว้น (14.22.58 น. มี backup ของ config ก่อนแก้) เธรดหลักยืนยันหลังแก้แล้ว
ต้นเหตุคือการปิดคลาสด้วยรายชื่อคำสั่งที่เพิ่งพลาด แทนที่จะวัดทุกคำสั่งที่ rtk เขียนใหม่ในรอบเดียว — รอบนี้เพิ่ม `tools/rtk-known-answer/` ที่วัดแบบนั้น และการรันจริงครั้งแรกพบคำสั่งที่ 3 แล้ว: `head -5` ตัดบรรทัดทิ้ง

## 1. ปัญหา (Problem Statement)

- config ของ `rtk` ก่อน #0116 P2 (backup `config.toml.bak-20260923-141606`): `exclude_commands = []`
- หลัง #0116 P2 (backup `config.toml.bak-20260923-142258`): `exclude_commands = ["find", "ls", "grep"]`
- subagent (ระหว่างทำมาตรการ #0116) วัดได้: `rtk diff` กับไฟล์ที่ต่างกัน 1 บรรทัด → `[ok] Files are identical` · `wc -l < file` ผ่าน hook → `0` ขณะที่ `/usr/bin/wc -l` → `20` (ตามแถว ledger `PM-2026-09-23-07`)
- config ปัจจุบัน (อ่านรอบนี้): `exclude_commands = ["find", "ls", "grep", "diff", "wc"]` · `diff` ระหว่าง backup 142258 กับปัจจุบันต่างกันบรรทัดนี้บรรทัดเดียว
- วัดรอบนี้ด้วย `rtk rewrite`: `find` `ls` `grep` `diff` `wc` → exit 1 (ไม่เขียนใหม่) · `cat` `head` `tail` `git status/log/diff` `rg` `curl` `du` `tree` `ps` `pytest` → ยังถูกเขียนใหม่

**สิ่งที่ควรจะเป็น:** มาตรการของคลาส "rtk เปลี่ยนคำตอบ" ต้องวัดทุกคำสั่งที่ rtk เขียนใหม่ด้วยคำตอบที่รู้ก่อน ไม่ใช่ยกเว้นทีละตัวที่เพิ่งพลาด — `CLAUDE.md` §1 ข้อย่อย #0003 "ปิดคลาสต้องไล่ไฟล์ข้างเคียงรอบเดียวกัน" และ "ปิดคลาสต้องมีตัวเลขที่นับได้"

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

`rtk` ออกแบบมาให้ย่อเอาต์พุต ซึ่งบางครั้งเปลี่ยน "คำตอบ" ไม่ใช่แค่ "ความยาว" (identical แทนต่าง · 0 แทน 20 · ตัดบรรทัดกลางไฟล์)
มาตรการ #0116 เลือกยกเว้นตามรายการคำสั่งที่เคยเห็นพัง จึงปลอดภัยเฉพาะคำสั่งที่ถูกพิสูจน์ว่าพังแล้ว คำสั่งอื่นที่ rtk เขียนใหม่ยังไม่มีใครวัด

### 5 Whys

1. **ทำไม `diff`/`wc` ให้คำตอบผิด?** — เพราะ hook เขียนเป็นคำสั่งของ `rtk` ที่ย่อเอาต์พุตจนเปลี่ยนความหมาย
2. **ทำไมยังถูกเขียนใหม่หลังแก้ #0116?** — เพราะ #0116 P2 ยกเว้นเฉพาะ `find` `ls` `grep` ที่เคยพลาด
3. **ทำไมเลือกยกเว้นแค่ 3 ตัว?** — เพราะรายการมาจาก "คำสั่งที่เคยเจอปัญหา" ไม่ได้มาจาก "คำสั่งที่ rtk เขียนใหม่ทั้งหมด"
4. **ทำไมไม่มีใครวัดคำสั่งที่เหลือ?** — เพราะไม่มีเครื่องมือที่ถามทุกคำสั่งพร้อมกันว่า "เขียนใหม่แล้วยังได้คำตอบเดิมไหม" — การวัดแต่ละครั้งทำด้วยมือเมื่อสงสัย
5. **root cause:** **การปิดคลาส "rtk เปลี่ยนคำตอบ" ใช้รายการจากเหตุที่เคยเกิด ไม่ใช่การวัดที่ครอบทุกคำสั่งด้วยคำตอบที่รู้ก่อน** — จึงปิดได้ทีละเหตุ และเหตุถัดไปต้องรอให้มีคนพลาดก่อน

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- #0116 P2 (รายการยกเว้น) — ครอบแค่ 3 คำสั่งตามชื่อ
- #0116 P1 (สคริปต์ค้นแบบมีตัวควบคุม `scripts/find-files.sh`) — ครอบการค้นไฟล์ ไม่ครอบ `diff`/`wc`
- #0116 P3 (ข้ออ้างเชิงลบต้องใช้คำสั่งที่ไม่ผ่านตัวกรอง) — ใช้กับข้ออ้าง "ไม่มี" ไม่ครอบข้ออ้าง "เหมือนกัน" / "จำนวน N"
- ชั้นที่จับได้จริงคือ subagent เทียบกับ `/usr/bin/wc` เอง — เป็นพฤติกรรม ไม่ใช่ด่าน

## 5. แนวทางการแก้ไข (Fix)

- เจ้าของงานอนุมัติ · config `exclude_commands` เพิ่ม `diff` `wc` (backup `config.toml.bak-20260923-142258` อยู่ข้างไฟล์)

- รอบนี้วัดซ้ำ: `rtk rewrite "diff a b"` และ `rtk rewrite "wc -l a"` → exit 1 ไม่เขียนใหม่ · `tools/rtk-known-answer/known_answer.js` → `diff` ได้ `line6-changed` rc=1 · `wc -l` ได้ 7 จากไฟล์ 7 บรรทัด

**ยืนยันแล้วด้วย:** `node tools/rtk-known-answer/known_answer.js` → `DIVERGENT: 11/11 measured · 6 rewritten by rtk · 1 lost the answer` — `diff` และ `wc -l` อยู่ในกลุ่ม `raw` และให้คำตอบถูก · ตัวที่เสียคำตอบคือ `head -5` (ดู P3)
