## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

`triage.jsonl` เขียนเหมือนรายงานที่ตรวจแล้ว ทุกบรรทัดมีหัวข้อ `root_cause` · `fix` · อ้างชื่อไฟล์และชื่อ hook ในโค้ด
และวางอยู่ในโฟลเดอร์เดียวกับ `verdicts.json` ซึ่งเป็นผลวัดจริง สองไฟล์นี้หน้าตาเป็นข้อมูลชนิดเดียวกัน
แต่ไฟล์หนึ่งเป็นผลที่เครื่องวัด อีกไฟล์เป็นข้อสรุปของ agent ที่ไม่มีใครตรวจ ตอนตอบคำถาม ผมอ่านทั้งสองแบบเป็นหลักฐานระดับเดียวกัน
คำขอว่า "ช่วยแนะนำที" ทำให้ผมมองงานเป็นการให้คำแนะนำ ไม่ใช่การตรวจสอบปัญหา จึงไม่ได้เริ่มจากขั้น 1

### 5 Whys

1. **ทำไมบอกเจ้าของงานว่าไม่มีบั๊กของระบบใน 23 เคส?** — เพราะคัดข้อสรุปจาก `triage.jsonl` มาพูดตรงๆ
2. **ทำไมคัดมาโดยไม่ตรวจ?** — เพราะไฟล์นั้นมีรายละเอียดระดับโค้ด อ่านแล้วดูเหมือนตรวจมาแล้ว และวางคู่กับผลวัดจริง
3. **ทำไมความละเอียดของข้อความถึงถูกใช้แทนการตรวจ?** — เพราะไม่มีอะไรในไฟล์บอกว่าบรรทัดไหนตรวจแล้วโดยใคร เมื่อไหร่ · ทุกบรรทัดดูเท่ากัน
4. **ทำไมกฎที่มีอยู่ไม่หยุดไว้ก่อน?** — เพราะคำขอถูกตีความเป็นงาน "แนะนำ" ไม่ใช่งาน "ตรวจสอบปัญหา" จึงไม่เข้าเงื่อนไขที่ทำให้นึกถึงกฎ 5 ขั้น
   และ hook ตรวจสอบปัญหาดูจากคำใน prompt เท่านั้น ข้อความ "ช่วยแนะนำที" ไม่มีคำที่ติดธง
5. **ทำไมทั้งกฎและ hook ปล่อยผ่าน?** — เพราะทุกชั้นที่มีตัดสินจาก **สิ่งที่ผู้ใช้พิมพ์** ไม่มีชั้นใดตรวจจาก **สิ่งที่ผมกำลังจะพูด**
   ข้อความที่ประกาศสาเหตุหรือคำตัดสินของเคส ออกไปได้โดยไม่มีอะไรถามว่าตรวจแล้วหรือยัง — นี่คือต้นเหตุระดับคลาส

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- กฎข้อแรกสุดของ `CLAUDE.md` ครอบเรื่องนี้ตรงตัว แต่เป็นตัวหนังสือ ใช้ได้เท่าที่นึกออกตอนพิมพ์
- investigation-guard ชั้น 2–3 ติดธงจากคำใน prompt · "ช่วยแนะนำที" ไม่ติดธง Stop hook จึงไม่บังคับให้เรียก systematic-debugging
- มาตรการของ #0076 ครอบเฉพาะ "ข้ออ้างเชิงลบเรื่องบัญชีที่มาจาก subagent" ซึ่งแคบกว่าคลาสจริง คือ "ข้อสรุปของแหล่งอื่นใดๆ ที่ถูกพูดต่อเป็นข้อเท็จจริง"
  ปิดจุดเดียวไม่ใช่การปิดคลาส (บทเรียน #0012) — คลาสเดิมจึงกลับมาในวันเดียวกัน

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- คำตอบแรกเรื่อง "สั่งอะไรไปบ้าง" มาจากไฟล์จริง และบอกตรงๆ ว่า exploratory ยังไม่มีผลบนดิสก์
- เมื่อถูกทัก ถอนคำพูดทั้ง 2 จุดทันที จดหนี้ในเทิร์นเดียวกัน และตรวจเองก่อนพูดเรื่องสาเหตุอีก

### สิ่งที่ต้องปรับปรุง
- ความละเอียดของข้อความในไฟล์ไม่ใช่หลักฐานว่าตรวจแล้ว · ไฟล์ที่วางคู่กับผลวัดจริงไม่ได้กลายเป็นผลวัดตามไปด้วย
- คำขอ "แนะนำ" ในเรื่องที่เป็นความล้มเหลว คืองานตรวจสอบปัญหา ต้องเริ่มขั้น 1 เสมอ
