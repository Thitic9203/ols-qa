## สรุปสั้น (Executive Summary)

session ของ 2 บัญชีตายเพราะ VPN tunnel ค้าง 21:18–22:03 (log keepalive: `tunnel-dead (scutil Connected, http=000)` · `ppp0 did not answer within 5s`) job จึงไม่ได้ touch session ราว 70 นาที เกินเกณฑ์ server ตัด 30 นาที หลัง VPN กลับมา บัญชีหนึ่งยังไม่ถูกฟื้น เพราะโปรเซสค้างของเลน (สคริปต์ node + headless Chrome ค้าง 58 นาที) มีชื่อบัญชีอยู่ใน command line ตัวตรวจ "ใช้อยู่" จึงเลื่อนทุกรอบ หยุดโปรเซสแล้วตัวตรวจตอบ false และฟื้น session ด้วย relink ได้ (ไม่ใช้รหัส) เพิ่มกฎให้เลนรันสคริปต์ใต้เวลาจำกัด และให้ขั้น merge ตรวจโปรเซสค้างด้วย `lane-lease-check --procs-tags`

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมบัญชีไม่ถูกฟื้น?** — ตัวตรวจเห็นชื่อบัญชีใน command line ของโปรเซสที่ยังรันอยู่
2. **ทำไมโปรเซสยังรันอยู่?** — สคริปต์ของเลนรอ element ด้วย timeout แต่เบราว์เซอร์ค้างโดยไม่มีเวลาจำกัดรวม และเลน agent ตายไปก่อนจะปิด
3. **ทำไมไม่มีใครเห็น?** — ขั้น merge ตรวจเฉพาะ lease ไม่ได้ตรวจโปรเซส
4. **ทำไม session ตายตั้งแต่แรก?** — VPN tunnel ค้างทั้งที่ scutil บอกว่า Connected · job ข้ามแบบเงียบตามกฎเดิม
5. **root cause** — กฎของเลนไม่บังคับเวลาจำกัดของสคริปต์และการเก็บกวาดโปรเซส จึงไม่มีอะไรรับประกันว่าเลนจบแล้วจะไม่มีของค้าง

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** lane-lease-check ดูแค่ไฟล์ lease · dispatch guard ไม่ตรวจเรื่องเวลาจำกัดของสคริปต์
