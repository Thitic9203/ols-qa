## สรุปสั้น (Executive Summary)

เจ้าของงานให้ย้ายการเตรียมข้อมูล Content_TC_007 ไป pre-prod ผมเลือกบัญชีจากไฟล์ `accounts_preprod.json` ในเครื่อง
บัญชีแรกคือ บัญชี A ซึ่งในชีต Account_Test เป็น Env "Dev" อย่างเดียว เจ้าของงานจึงล็อกอินไม่ได้
memory `reference_ols-env-hosts-and-login-portals` ระบุไว้แล้วว่าบัญชีต้องมาจากชีต Account_Test เท่านั้น ห้ามใช้ roster ในเครื่อง
เจ้าของงานส่งลิงก์ชีตมาถามว่า "ใช่มะ" จึงพบ

## 1. ปัญหา (Problem Statement)

**สิ่งที่เกิดขึ้น:** roster ในเครื่องมีบัญชี 13 รายการโดยไม่มีช่อง env · ผมใช้โดยไม่เทียบกับชีต
**สิ่งที่ควรจะเป็น:** อ่านชีต Account_Test สด เลือกเฉพาะแถวที่ Env ตรงกับ env เป้าหมาย แล้วสร้าง roster จากแถวนั้น

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. ทำไมล็อกอินไม่ได้ — บัญชี A ไม่มีบัญชีบน pre-prod ตามชีต
2. ทำไมเลือก บัญชี A — หยิบจาก `accounts_preprod.json` ซึ่งมีชื่อนี้อยู่
3. ทำไมใช้ไฟล์นั้น — ชื่อไฟล์บอก env จึงเชื่อว่าตรง โดยไม่เปิดชีต
4. ทำไมไม่เปิดชีต — ไม่ได้ค้น memory ก่อนเลือกบัญชี ทั้งที่มีบันทึกเรื่องนี้โดยตรง
5. ทำไมเครื่องมือไม่กัน — `session_capture.js` รับ roster ใดก็ได้ ไม่ตรวจว่าแถวของบัญชีนั้นมี env ตรงกับ `OLS` ที่ระบุ

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** กฎมีแค่ใน memory ไม่มีชั้นเครื่องใดตรวจ env ของบัญชีเทียบกับเป้าหมาย

## 4. ผลกระทบ (Impact)

- เจ้าของงานเสียรอบล็อกอิน 1 รอบ · ไม่มีการเขียนข้อมูล

## 5. แนวทางการแก้ไข (Fix)

- สร้าง roster ใหม่จากชีตสดเฉพาะ Env "Dev / Pre-prod" (14 แถว ไม่มีรหัสผ่าน) ในโฟลเดอร์งาน แล้วเปิดหน้าต่างใหม่

**ยืนยันแล้วด้วย:** log บันทึกครบ 6 บัญชี · `GET /api/auth/get-session` บน pre-prod ได้ ALIVE 6 จาก 6 บทบาทตรงชีต
