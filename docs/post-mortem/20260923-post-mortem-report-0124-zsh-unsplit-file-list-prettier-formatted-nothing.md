## สรุปสั้น (Executive Summary)

ระหว่างแก้ชุด e2e ให้ mint session ใน child process เธรดหลักเก็บรายชื่อไฟล์ 8 ไฟล์ไว้ในตัวแปรสตริงเดียว `F="a b c …"` แล้วสั่ง `npx prettier --write $F` ใน zsh
zsh ไม่แยกคำของตัวแปรที่ไม่ได้ใส่ quote (ต่างจาก bash) prettier จึงได้อาร์กิวเมนต์เดียวทั้งก้อน ตอบ `No files matching the pattern` และไม่ได้ format ไฟล์ใดเลย
เธรดหลักจับได้จากบรรทัด error ก่อนสรุปผล แก้เป็น array `F=(…)` + `"${F[@]}"` แล้ว prettier ผ่านครบ 8 ไฟล์
นี่คือคลาสเดียวกับ #0118 (และสายก่อนหน้า #0117 · #0097 · #0009) — มาตรการของ #0118 (`tools/zsh-split-guard/`) ยังไม่ได้ผูกเป็น hook จึงไม่ได้ครอบคำสั่งนี้

## 1. ปัญหา (Problem Statement)

- คำสั่งที่รัน: `F="<8 paths>"` ตามด้วย `npx prettier --write $F` ในเชลล์ zsh (บันทึกในแถว PM-2026-09-23-11 ของ `PENDING.md`)
- ผลที่ได้: prettier พิมพ์ `No files matching the pattern` — ไม่มีไฟล์ใดถูก format
- มาตรการของ #0118 คือ `tools/zsh-split-guard/` ซึ่งรายงาน #0118 ระบุว่า "ผูก hook รอเจ้าของงาน" — ณ เวลาเกิดเหตุจึงไม่มีชั้นใดตรวจคำสั่งนี้ก่อนรัน

**สิ่งที่ควรจะเป็น:** รายการอาร์กิวเมนต์หลายตัวใน zsh ต้องเก็บเป็น array และขยายด้วย `"${F[@]}"` (บทเรียนเดียวกันที่ #0117/#0118 บันทึกไว้แล้ว)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

zsh ปิด `SH_WORD_SPLIT` เป็นค่าเริ่มต้น การขยาย `$F` จึงได้คำเดียวทั้งก้อน รูปแบบ "เก็บลิสต์ในสตริงแล้วขยายไม่ใส่ quote" เป็นนิสัยแบบ bash ที่ถูกนำมาใช้ซ้ำ ทั้งที่รายงาน 4 ฉบับก่อนหน้าชี้เรื่องนี้แล้ว

### 5 Whys

1. **ทำไม prettier ไม่ format ไฟล์ใดเลย?** — เพราะได้อาร์กิวเมนต์เดียวที่เป็นชื่อไฟล์ 8 ชื่อคั่นด้วยช่องว่าง ซึ่งไม่ตรงไฟล์ใด
2. **ทำไมได้อาร์กิวเมนต์เดียว?** — เพราะรันใน zsh ซึ่งไม่แยกคำของ `$F` ที่ไม่ได้ใส่ quote
3. **ทำไมยังเขียนแบบนี้ ทั้งที่ #0118 เพิ่งปิด?** — เพราะบทเรียนของ #0118 อยู่ในรูปรายงาน + เครื่องมือตรวจที่ต้องเรียกเอง ไม่ได้อยู่ในทางเดินของคำสั่งทุกคำสั่ง
4. **ทำไมเครื่องมือของ #0118 ไม่ทำงาน?** — เพราะ `tools/zsh-split-guard/` ยังไม่ถูกผูกเป็น PreToolUse hook (รายงาน #0118 ระบุว่ารอเจ้าของงานอนุมัติการผูก hook) จึงไม่มีอะไรตรวจคำสั่ง Bash ก่อนรัน
5. **ทำไมการผูก hook ค้างอยู่?** — เพราะการแก้ `.claude/settings.json` เป็นการเปลี่ยน config ถาวรที่ต้องขออนุญาตก่อน และยังไม่ได้ยกคำถามนี้ขึ้นให้เจ้าของงานตัดสินพร้อมตัวเลขว่าคลาสนี้เกิดซ้ำกี่ครั้งแล้ว (root cause: มาตรการที่แข็งพอมีอยู่แล้วแต่ไม่อยู่ในเส้นทางบังคับ)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** `tools/zsh-split-guard/` มีเทสต์ผ่านแต่ไม่ได้ผูกกับเส้นทางรันคำสั่ง · ไม่มี hook อื่นตรวจรูปแบบ `$VAR` ที่ไม่ใส่ quote · ชั้นที่จับได้จริงคือการอ่านบรรทัด error ของเธรดหลักเอง

## 5. แนวทางการแก้ไข (Fix)

- เปลี่ยนเป็น array `F=(…)` แล้วขยายด้วย `"${F[@]}"` — prettier ผ่านครบ 8 ไฟล์ (ตามแถว PM-2026-09-23-11)

**ยืนยันแล้วด้วย:** ผลของ prettier รอบที่สอง (8 ไฟล์) ตามที่บันทึกในแถว `PENDING.md` · รายงานฉบับนี้ไม่ได้รันซ้ำ

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

มาตรการของ #0118 เป็นเครื่องมือที่ต้องเรียกเอง ชั้นใหม่ที่แข็งขึ้นต้องอยู่ในเส้นทางบังคับ

| # | มาตรการ | ชนิด | สถานะ |
|---|---------|------|-------|
| P1 | ผูก `tools/zsh-split-guard/` เป็น PreToolUse hook ของ Bash ที่**ปฏิเสธ**คำสั่งที่ขยาย `$VAR` ไม่ใส่ quote ในตำแหน่งอาร์กิวเมนต์ของคำสั่งหลายไฟล์ (ต้องขออนุมัติเจ้าของงานก่อนแก้ `.claude/settings.json`) | hook | ยังไม่ได้ทำ — รอเจ้าของงานอนุมัติ |
| P2 | เพิ่มเคสทดสอบของ guard ให้ครอบรูป `cmd --flag $F` (รูปของเหตุนี้) นอกจาก `set -- $V` ของ #0118 | เทส | ยังไม่ได้ทำ |
| P3 | เมื่อคลาสเดียวกันเกิดครั้งที่ 5 ให้ยกคำถามผูก hook ขึ้น AskUserQuestion พร้อมจำนวนครั้ง แทนการรอ | กฎ | ยังไม่ได้ทำ |

**กฎที่เพิ่มจากเหตุนี้:** ไม่มีกฎข้อความใหม่ เพราะกฎเดิม (array + `"${F[@]}"`) มีอยู่แล้วตั้งแต่ #0117 — ช่องว่างคือการบังคับ ซึ่งเสนอไว้ใน P1 (ยังไม่ได้ทำ)

## 7. การตรวจจับปัญหา (Detection)

- **ใครจับได้ / จับได้ยังไง:** เธรดหลักอ่านบรรทัด `No files matching the pattern` ก่อนสรุปผล
- **ใช้เวลาเท่าไหร่กว่าจะรู้:** ทันทีหลังคำสั่งจบ (ไม่มี timestamp วัดไว้)
- **รอบหน้าอะไรจะจับได้เร็วกว่านี้:** hook ตาม P1 จะปฏิเสธก่อนรัน ไม่ต้องพึ่งการอ่าน error

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- อ่านบรรทัด error ก่อนสรุปผล จึงไม่มีการรายงานว่า format แล้วทั้งที่ไม่ได้ทำ

### สิ่งที่ต้องปรับปรุง
- เครื่องมือกันซ้ำที่ไม่อยู่ในเส้นทางบังคับ ไม่นับเป็นชั้นป้องกัน ต้องผลักให้ผูกหรือยกขึ้นถามทันที
