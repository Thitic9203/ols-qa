## สรุปสั้น (Executive Summary)

NDLP_TC_003 ต้องแก้คำอธิบายสื่อ NDLP 81467 แต่ฟอร์มถูกปิด ผมตามโค้ดเจอ `checkEditableLearningMedia` ที่ห้ามแก้สื่อ ACTIVE แล้วสรุปต่อเองว่า "สลับเป็น INACTIVE แล้วจะแก้ได้" บอกเจ้าของงาน และสั่ง agent เพิ่มขั้นสลับสถานะ
ฟังก์ชันเดียวกันเรียก `checkApproveFlowEditEligible` ต่อท้าย ซึ่งห้าม INACTIVE ด้วย (`learning-media.utils.ts:2048-2055`) agent เป็นคนจับได้ ผมตรวจยืนยันเอง ยกเลิกคำสั่ง และแก้คำพูดกับเจ้าของงาน ไม่มีการเขียนข้อมูลเกิดขึ้น

---

## 1. ปัญหา (Problem Statement)

- ผมอ่าน `checkEditableLearningMedia` ถึงบรรทัด "If learning media is published, it cannot be edited" และเห็นบรรทัด `if (!this.checkApproveFlowEditEligible(item))` แต่ไม่ได้เปิดอ่านฟังก์ชันนั้น
- ผมเขียนถึงเจ้าของงานว่า "ถ้าสื่อไม่อยู่สถานะเผยแพร่ ฟอร์มจะกลับมาแก้ได้ ซึ่งการสลับนี้ย้อนคืนได้"
- ผมสั่ง agent ให้เพิ่มขั้น "toggle 81467 to INACTIVE" ในสคริปต์อัด
- ข้อเท็จจริง: `checkApproveFlowEditEligible` คืน false เมื่อสถานะเป็น `WAIT_FOR_APPROVAL` หรือ `INACTIVE` (pluton-monorepo origin/main `b668e2e8e6` `learning-media.utils.ts:2048-2055`)

**สิ่งที่ควรจะเป็น:** อ่านทุกเงื่อนไขในเส้นทางที่ตัดสินผลให้ครบก่อนพูดว่าเปลี่ยนสถานะแล้วจะได้ผลอะไร (CLAUDE.md §0)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมบอกว่า INACTIVE แก้ได้?** — เพราะสรุปจากเงื่อนไขแรก (ห้ามเฉพาะ ACTIVE) ของฟังก์ชัน
2. **ทำไมสรุปจากเงื่อนไขแรก?** — เพราะหยุดอ่านเมื่อเจอคำตอบที่ต้องการ แล้วไม่ตามฟังก์ชันย่อยที่อยู่ในเส้นทางเดียวกัน
3. **ทำไมไม่ตาม?** — เพราะรีบตอบเจ้าของงานที่เร่งให้งานเดิน และคิดว่าเจอเส้นทางแก้แล้ว
4. **ทำไมไม่ติดด่านใด?** — เพราะข้อสรุปนี้ยังไม่ได้ไปเขียนข้อมูลบน env จึงไม่มีด่านเขียน/ledger มาหยุด ด่านที่มีคือความรับผิดชอบของผู้พูดเองเท่านั้น
5. **ทำไมไม่มีกลไกบังคับ?** — root cause: ไม่มีขั้นบังคับว่า "ก่อนพูดว่าการเปลี่ยนสถานะจะทำให้ X เป็นไปได้ ต้องแสดงรายการเงื่อนไขทั้งหมดในเส้นทางนั้น (ทุก return false) พร้อม path:line"

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** investigation-guard ตรวจแค่ว่าเรียกสกิลแล้วหรือยัง ไม่ได้ตรวจว่าอ่านครบ · write_guard/ledger ทำงานตอนเขียนจริง ซึ่งยังไม่เกิด

## 5. แนวทางการแก้ไข (Fix)

- ส่งคำสั่งยกเลิกขั้นสลับ INACTIVE ให้ agent และให้ถอดโค้ดส่วนนั้นถ้าใส่ไปแล้ว
- แก้คำพูดกับเจ้าของงานในแชทพร้อม path:line
- ให้ agent ค้นเส้นทางจริงที่ทำให้สื่อ ACTIVE กลับไปอยู่สถานะที่แก้ได้ พร้อม path:line ทุกขั้น ก่อนแก้สคริปต์ใดๆ
