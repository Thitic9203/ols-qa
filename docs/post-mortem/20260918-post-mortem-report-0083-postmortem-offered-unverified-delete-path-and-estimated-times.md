## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

ตอนเขียน #0081 ผมเปิดไฟล์ `media-status.vo.ts` เพื่อยืนยันว่าสถานะใดลบได้ แต่ไม่ได้อ่านตารางการเปลี่ยนสถานะว่า Unpublished ไปที่ไหนได้บ้าง ·
การอ้างเลขบรรทัดทำให้ข้อความดูเหมือนตรวจครบ ทั้งที่บรรทัดที่อ้างพิสูจน์ได้แค่ครึ่งเดียวของทางที่เสนอ ·
เวลาในไทม์ไลน์เขียนจากความจำเพราะไม่ได้เปิด log ก่อนเขียน

### 5 Whys

1. ทำไมรายงานเสนอทางที่ใช้ไม่ได้ — เพราะตรวจแค่ปลายทาง (สถานะที่ลบได้) ไม่ได้ตรวจเส้นทางไปถึงปลายทาง (Unpublished → ?)
2. ทำไมไม่ได้ตรวจเส้นทาง — เพราะทาง "ยกเลิกเผยแพร่ก่อน" ฟังดูเป็นลำดับปกติ จึงถูกถือว่าเป็นไปได้
3. ทำไมคำว่า "ตรวจแล้ว" ผ่านออกไป — เพราะมีเลขบรรทัดแนบ ซึ่งถูกอ่านเป็นหลักฐานของทั้งประโยค
4. ทำไมไทม์ไลน์ใช้เวลาประมาณ — เพราะเขียนรายงานต่อทันทีโดยไม่เปิด ledger และ log ของเลน
5. ทำไมไม่มีชั้นไหนจับ — `check.js` ตรวจโครงสร้างรายงาน ไม่ได้ตรวจว่าตัวเลือกหรือเวลาในเนื้อความผ่านการวัด

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** กฎของ #0081 ผูกกับ "คำถามถึงเจ้าของงาน" ไม่ได้ผูกกับ "ทางเลือกที่เขียนในรายงาน" · กฎของ #0060 เขียนสำหรับบอร์ดสด ไม่ได้ครอบไทม์ไลน์ในรายงาน post-mortem · ตัวตรวจรายงานไม่อ่านเนื้อความ

## 4. ผลกระทบ (Impact)

- ถ้าเจ้าของงานเลือกทาง "ยกเลิกการเผยแพร่ แล้วค่อยลบ" ตามรายงาน สื่อจะติดที่ Unpublished และยังลบไม่ได้ — เป็นรอบที่ 3 ที่ทางแนะนำใช้ไม่ได้
- ไทม์ไลน์ผิดทำให้ดูเหมือนเลน C1 ลงมือก่อนได้รับอนุมัติ ซึ่งไม่ใช่สิ่งที่ log แสดง
- ไม่มีข้อมูลบน dev ถูกแก้จากรายงานนี้

## 5. แนวทางการแก้ไข (Fix)

- แก้ #0081 หัวข้อ Fix: เปลี่ยนเป็นทาง Published → RequestEdit → PendingEdit → ลบ ระบุว่าทางยกเลิกเผยแพร่ใช้ไม่ได้ และระบุข้อจำกัด LIVESTREAM ว่ายังไม่ได้ตรวจ
- แก้ #0081 ไทม์ไลน์: ใช้เวลาจาก ledger และ log (21:38 · 21:48:59 · 21:51 · 21:52:59–21:54:04) แถวที่ไม่มีบันทึกเวลาระบุเฉพาะลำดับ

**ยืนยันแล้วด้วย:** `git show f4bd185af:apps/api/src/modules/learning-content/media/domain/value-object/media-status.vo.ts` (ols-monorepo) · fixture ledger ของเลน R3 และ log ของเลน C1/C2 ในโฟลเดอร์งานนอก repo

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

1. **ทุกทางเลือกที่รายงานเสนอให้เจ้าของงาน ต้องตรวจกับตารางการเปลี่ยนสถานะทีละขั้น และอ้างบรรทัดที่อนุญาตแต่ละขั้น** ไม่ใช่อ้างเฉพาะปลายทาง
2. **ทุกเวลาในรายงานต้องมาจาก ts ของ log หรือ ledger** ห้ามใช้ `~` · ไม่มีบันทึกให้เขียนว่าไม่มีบันทึกเวลาและระบุเฉพาะลำดับ
3. สิ่งที่ยังไม่ได้ตรวจ (เช่นกรณี LIVESTREAM) ต้องเขียนว่า "ยังไม่ได้ตรวจ" ในประโยคเดียวกับทางที่เสนอ

**กฎที่เพิ่มจากเหตุนี้:** สรุปไว้ใน `CLAUDE.md` หัวข้อ Post-mortems (Report #0083) — *ทุกทางเลือกในรายงานต้องชี้บรรทัดที่อนุญาตทุกขั้นของการเปลี่ยนสถานะ และทุกเวลาในรายงานต้องมาจาก ts ของ log/ledger ไม่ใช่ `~`*
