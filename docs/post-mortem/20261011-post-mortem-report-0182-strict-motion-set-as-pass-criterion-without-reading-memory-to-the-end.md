## สรุปสั้น (Executive Summary)

ช่วงเช้ารอบ RTT เธรดหลักสั่งทุกเลนว่า "ห้าม PASSED ถ้าคลิปไม่ผ่าน `--strict-motion`" ส่งต่อค่า "อัด 8 fps" ที่เอามาจากเลนเดียว และสั่งให้ลดแถว PASSED เป็น EVIDENCE_PENDING กฎของเจ้าของงานที่บันทึกไว้ (23/Sep แก้เพิ่ม 25/Sep) บอกว่าคลิปที่เห็นครบทุกจุดของ ER = PASS แม้ strict-motion ไม่ผ่านเพราะภาพนิ่ง/ขยับน้อย — ตัวชี้วัดเป็นสัญญาณให้เปิดดูเฟรม ไม่ใช่คำตัดสิน สาเหตุจริงคือเธรดหลักตั้งเกณฑ์จากชื่อ flag ของตัวตรวจกับ post-mortem เก่า โดยไม่อ่านรายการ memory ให้ถึงบรรทัดสุดท้ายที่จำกัดขอบเขตของตัวชี้วัด แก้แล้วด้วยกฎเกณฑ์ยอมรับรอบนี้ (ACCEPTANCE_RULE.md) ที่ส่งถึงทุกเลน และแก้ memory แล้ว ส่วนการเข้ารหัสกฎลงตัวตรวจและเทสต์รออยู่ใน PR ที่ขอไว้

## 1. ปัญหา (Problem Statement)

- เวลาประมาณ 07:5x–08:2x เธรดหลักสั่งทุกเลน: ห้ามตัดสิน PASSED ถ้าคลิปไม่ผ่าน `verify_video.py --strict-motion`
- เธรดหลักส่งต่อค่า "อัดที่ 8 fps" ซึ่งมาจากเลนเดียว ทั้งที่วิธีที่ใช้ผ่านได้เมื่อ 23/Sep คือ fps 12 + เลื่อนหน้าต่อเนื่อง
- เธรดหลักสั่งให้เลนลดแถว PASSED เป็น EVIDENCE_PENDING (ประมาณ 22 แถว ภายหลังคืนกลับ)
- การตรวจที่ 08:40 พบ: จากคลิปของแถว PASSED 60 คลิป มี 48 คลิปไม่ผ่านเพียง "too little motion" และ 11 คลิปมีภาพค้างจริง
- เลนวนทำท่าเรียกความขยับ (เลื่อนหลายรอบ กดปุ่ม เปลี่ยน fps) ใช้ fixture หมดไปกับคลิปที่ต้องทิ้ง และเลนหนึ่งใช้ราว 50 นาทีโดยไม่มีคลิปที่ยอมรับได้แม้แต่คลิปเดียว

**สิ่งที่ควรจะเป็น:** กฎของเจ้าของงาน (memory บันทึก 23/Sep แก้ 25/Sep ประมาณ 00.0x): "ถ้าตรงเคสเราโอเค ไม่ติดไร" — คลิปที่แสดงทุกจุดของ ER = PASS แม้ strict-motion ไม่ผ่านเพราะขยับน้อยหรือค้างเกิน 5% ตัวชี้วัดใช้เป็นสัญญาณให้ตรวจเฟรม เฉพาะความล้มเหลวแข็งของตัวตรวจ (เช่น หน้าว่าง/โหลดค้าง/เนื้อหาหาย) จึงตัดสินให้ไม่ผ่าน คำสั่งสดของเจ้าของงานเช้าวันเดียวกัน ("ถ้าครบตาม ER แต่มีบางช่วงตัดขัดเช่นภาพค้าง ต้องไปแก้ระดับสกิล") ชี้ทางเดียวกัน

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

จุดตัดสินใจที่ผิดคือการ "ตั้งเกณฑ์ยอมรับ" จากสิ่งที่ตัวตรวจรายงาน (ชื่อ flag `--strict-motion`) บวกบทเรียนเก่า (#0113/#0114 ที่ทำ strict-motion เป็นค่าเริ่มต้นเพราะคำเตือน "too little motion" เคยบังภาพค้างจริง 35–60%) ตอนนั้นดูถูกเพราะบทเรียนเก่าอธิบายว่าทำไม metric นี้สำคัญ แต่มันตอบคำถาม "ตัวตรวจควรเข้มแค่ไหน" ไม่ใช่ "อะไรคือเกณฑ์ PASS ของเจ้าของงาน"

### 5 Whys

1. **ทำไมเลนเสียเวลาและลดแถว PASSED ผิด?** — เพราะได้รับคำสั่งว่า PASSED ต้องผ่าน strict-motion
2. **ทำไมเธรดหลักสั่งแบบนั้น?** — เพราะอนุมานเกณฑ์จากชื่อ flag และ post-mortem #0113/#0114
3. **ทำไมอนุมานแทนที่จะใช้กฎของเจ้าของงาน?** — เพราะอ่านรายการ memory ไม่จบ บรรทัดสุดท้าย (25/Sep) ที่จำกัดว่าตัวชี้วัดตัดสินอะไรไม่ได้อยู่ในส่วนที่อ่าน
4. **ทำไมอ่านไม่จบแล้วยังลงมือ?** — เพราะไม่มีขั้นบังคับให้ค้นชื่อ metric ใน memory/CLAUDE.md แล้วอ่านทุก hit ถึงท้ายก่อนตั้งเกณฑ์ และคำสั่งสดของเจ้าของงานเช้าวันนั้นไม่ถูกนำมาเทียบ
5. **ทำไมไม่มีขั้นนั้น?** — **root cause:** เกณฑ์ยอมรับ (acceptance criterion) ถูกตั้งด้วยดุลยพินิจของเธรดหลักโดยไม่มีแหล่งอ้างอิงที่ตรวจได้ ตัวตรวจ (`tools/result-gate`) เองก็ไม่แยกว่า motion-only ต่างจากความล้มเหลวแข็ง และเทมเพลตสั่งงานเลนไม่มีบรรทัดระบุแหล่งกฎ จึงไม่มีอะไรบังคับให้เกณฑ์ต้องมีที่มา

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- กฎข้อ 0 ใน CLAUDE.md ("ห้ามเดา / re-verify") ครอบคลุมข้ออ้างข้อเท็จจริง แต่ไม่ครอบคลุมการ "ตั้งเกณฑ์" ที่ส่งต่อเป็นคำสั่ง
- memory ถูกโหลดเป็นดัชนีบรรทัดเดียว (ชื่อ + สรุปสั้น) ไม่บังคับให้เปิดไฟล์เต็ม
- ตัวตรวจ strict-motion ให้ผลเป็นผ่าน/ไม่ผ่านเดียว ไม่มีสถานะ "ต้องดูเฟรม"
- ไม่มีชั้นใดตรวจเกณฑ์ที่เธรดหลักตั้งก่อนกระจายถึงเลน

## 5. แนวทางการแก้ไข (Fix)

- 08:45 ออก `ACCEPTANCE_RULE.md` ในโฟลเดอร์ผลรอบ (ไม่ commit — ไฟล์ปฏิบัติการของรอบ): คลาส A/C = PASSED เมื่อผู้ตรวจยืนยันเฟรมครบทุกจุด ER · คลาส B (ภาพค้างจนบังจุด ER) = อัดใหม่ 1 ครั้ง · ความล้มเหลวแข็งของตัวตรวจ (หน้าว่าง ฯลฯ) ยังไม่ผ่าน · ส่งถึงทุกเลน
- แก้ memory ของกฎเดิมให้บรรทัด 25/Sep ชัดว่าตัวชี้วัดตัดสินอะไรไม่ได้
- ขอ PR ให้ result-quality-gate ฝังกฎเป็นโค้ดพร้อมเทสต์ (ยังไม่ merge ณ วันที่รายงาน)
- PR ตัดช่วงค้างระดับสกิลที่เจ้าของงานอนุมัติไว้แก้ปัญหา stutter ที่ต้นทาง

**ยืนยันแล้วด้วย:** ผลตรวจรวม 08:40 (48/60 motion-only, 11 ค้างจริง) เป็นฐานการแบ่งคลาส · การออกกฎและการแจ้งทุกเลนเกิดตามไทม์ไลน์ข้างต้น · การฝังกฎในตัวตรวจ **ยังไม่ได้ทำและยังไม่ได้ยืนยัน** (ดู Action Items)
