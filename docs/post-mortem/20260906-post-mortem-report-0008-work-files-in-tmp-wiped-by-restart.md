## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

ประเด็นที่ต้องอธิบายให้ได้ ไม่ใช่ "ลืมกฎ" เพราะกฎถูกใช้อยู่ในรอบเดียวกันนั้นจริง
คำถามที่ถูกต้องคือ **ทำไมกฎเดียวกันจึงคุ้มครองไฟล์บอร์ด แต่ไม่คุ้มครองไฟล์ข้างๆ ที่อยู่ในรอบเดียวกัน**

คำตอบอยู่ที่รูปประโยคของกฎ กฎขึ้นต้นด้วย **ชื่อของสิ่งที่ต้องคุ้มครอง** คือ "ไฟล์ HTML และไฟล์ JSON ของบอร์ด"
แล้วค่อยตามด้วยสถานที่ที่ห้าม เมื่ออ่านแบบนี้ สมองจะจับคู่ว่า "ของชิ้นนี้ ห้ามอยู่ที่นั่น"
ไม่ได้จับคู่ว่า "ที่นั่นไม่ปลอดภัยสำหรับของทุกชิ้น" ผลคือของชิ้นอื่นในรอบเดียวกันไม่เคยถูกตั้งคำถามเลย

ยิ่งไปกว่านั้น สภาพแวดล้อมของเซสชัน **แนะนำให้ใช้โฟลเดอร์ชั่วคราวนั้นเป็นค่าปกติ**
สำหรับ "ไฟล์ชั่วคราว ผลลัพธ์ระหว่างทาง และไฟล์ที่ไม่ควรอยู่ในโปรเจกต์" ซึ่งคลิปที่ดาวน์โหลดมา
และไฟล์ผลตรวจระหว่างทางเข้าข่ายคำอธิบายนั้นทุกคำ จึงไม่มีอะไรสะกิดให้ฉุกคิด

### 5 Whys

1. **ทำไมงานถึงหาย?** — เพราะไฟล์อยู่ใต้ `/private/tmp` ซึ่งถูกล้างเมื่อเซสชันรีสตาร์ต
2. **ทำไมไฟล์ถึงไปอยู่ตรงนั้น?** — เพราะเป็นเส้นทางที่สภาพแวดล้อมแนะนำไว้สำหรับไฟล์ชั่วคราวและผลลัพธ์ระหว่างทาง
3. **ทำไมคลิปกับผลตรวจถึงถูกจัดว่าเป็นของชั่วคราว?** — เพราะจัดประเภทไฟล์จาก **ความรู้สึกว่ามันเป็นของระหว่างทาง** ไม่ใช่จาก **ราคาที่ต้องจ่ายถ้ามันหาย**
4. **ทำไมกฎที่มีอยู่ถึงไม่ห้ามไว้?** — เพราะกฎผูกกับ **ชื่อไฟล์ประเภทหนึ่ง** ไม่ได้ผูกกับ **ตัวโฟลเดอร์** กฎที่ระบุของชิ้นเดียวจะไม่ขยายตัวเองไปคุ้มครองของชิ้นอื่น
5. **ทำไมถึงปล่อยให้เรื่องความคงทนของข้อมูลขึ้นกับการตัดสินทีละไฟล์?** — **root cause:** ไม่มีอะไรในระบบงานที่แยก "ของที่สร้างใหม่ได้ในไม่กี่วินาที" ออกจาก "ของที่ต้องลงแรงใหม่ทั้งหมด" ณ ตอนที่เขียนไฟล์ การตัดสินจึงตกอยู่กับความจำและความรู้สึกทุกครั้ง ซึ่งจะพลาดในวันที่งานเยอะที่สุด

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ไม่มีชั้นไหนครอบเรื่องนี้เลย ตรงไปตรงมา

| ชั้นที่น่าจะจับได้ | ทำไมไม่จับ |
|---|---|
| กฎใน `CLAUDE.md` | ผูกกับไฟล์บอร์ดอย่างเดียว ไม่ได้ผูกกับโฟลเดอร์ |
| คำแนะนำของสภาพแวดล้อม | แนะนำให้ใช้โฟลเดอร์นั้นเป็นค่าปกติ จึงผลักไปทางตรงข้ามกับกฎ |
| เครื่องมือใดๆ ในเครื่อง | ไม่มีตัวไหนดูว่าเซสชันเขียนไฟล์ลงที่ไหน |
| การสำรองข้อมูล | ไม่มีการสำรองไฟล์งานระหว่างรอบเลย |

## 7. การตรวจจับปัญหา (Detection)

- **ใครจับได้ / จับได้ยังไง:** ไม่มีชั้นไหนจับได้เลย รู้ตัวตอนเปิดหาไฟล์แล้วไม่เจอหลังเซสชันรีสตาร์ต
  คือรู้ตอนที่ความเสียหายเกิดไปแล้วเรียบร้อย
- **ใช้เวลาเท่าไหร่กว่าจะรู้:** รู้ทันทีที่เข้าถึงไฟล์ครั้งถัดไป แต่กว่าจะถึงตอนนั้นก็ไม่มีอะไรให้กู้แล้ว
- **รอบหน้าอะไรจะจับได้เร็วกว่านี้:** การจับให้เร็วขึ้นไม่ช่วย เพราะจังหวะที่ควรแทรกคือ **ตอนเขียนไฟล์**
  ไม่ใช่ตอนอ่านไม่เจอ มาตรการ P4 จึงเป็นการปฏิเสธตั้งแต่ตอนเขียน ไม่ใช่การแจ้งเตือนตอนหาย

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- ต้นทางของคลิปอยู่บนที่เก็บส่วนกลาง จึงดาวน์โหลดใหม่ได้ครบใน 51 วินาที ถ้าคลิปเป็นของที่สร้างในเครื่องอย่างเดียว
  ความเสียหายจะหนักกว่านี้มาก
- จดแถวหนี้ไว้ทันทีในเทิร์นที่รู้ตัว รายละเอียดของเหตุการณ์จึงรอดข้ามการรีสตาร์ตมาได้ แม้ตัวไฟล์จะไม่รอด

### สิ่งที่ต้องปรับปรุง
- **กฎที่เขียนโดยเอ่ยชื่อของที่ต้องคุ้มครอง จะคุ้มครองเฉพาะของชิ้นนั้น** ถ้าอันตรายอยู่ที่สถานที่
  กฎต้องเขียนถึงสถานที่ ไม่ใช่เขียนถึงของ
- **เหตุการณ์ที่เคยเกิดแล้วต้องจบด้วยรายงาน ไม่ใช่จบด้วยการเติมกฎหนึ่งบรรทัด** เหตุ 2026-09-03 จบด้วยการเติมกฎ
  จึงไม่มีใครไปไล่ถามว่ายังมีของอื่นวางอยู่ในที่เดียวกันอีกหรือเปล่า ซึ่งเป็นคำถามที่การเขียนรายงานบังคับให้ตอบ
- **คำแนะนำของสภาพแวดล้อมไม่ใช่นโยบายของงาน** เส้นทางที่เครื่องมือแนะนำว่าเหมาะกับไฟล์ชั่วคราว
  ตอบคำถามว่า "วางที่ไหนได้" ไม่ได้ตอบคำถามว่า "หายแล้วเสียหายแค่ไหน" ซึ่งเป็นคำถามที่งานต้องตอบเอง
