## สรุปสั้น (Executive Summary)

สคริปต์อัด NDLP_TC_003/004 ต่อกับเบราว์เซอร์ NDLP แบบมีจอของเจ้าของงาน (CDP) และอัดจากแท็บในหน้าต่างนั้น · ตัวเปิดหน้าต่างเรียก `bringToFront` · ผมยังสั่ง `osascript … set frontmost` ดึงหน้าต่างขึ้นหน้าสุดตอนเปิดหน้าต่างข้อตกลงเผยแพร่
เจ้าของงานกำลังใช้จอ ต้องกดยกเลิกและบอกว่า "ไม่ต้องเด้งมารบกวน เราใช้จออยู่" · take ของ NDLP_TC_004 ที่ถูกยกเลิกยังรันต่อ ผมหยุดด้วย pid (56019/56069) · ไม่มีการเขียนข้อมูล
memory เดิมระบุไว้ว่าหน้าต่างที่ถูกบังจะหยุดวาดภาพจนได้ภาพค้าง ซึ่งเป็นสมมติฐานของคลิป NDLP_TC_003 ที่ค้าง 85% (#0154 · กำลังยืนยันใน `laneT69/clip_stutter_0924.md`)

## 1. ปัญหา (Problem Statement)

- `ndlp_owner_window.js:53,64` เรียก `page.bringToFront()` · `n004_publish_popup.js` เรียก `bringToFront` + ผมรัน `osascript … set frontmost … to true`
- สคริปต์อัด NDLP_TC_003/004 บันทึกจากแท็บใน Chrome for Testing แบบมีจอ (`connectOverCDP 9333`)
- เจ้าของงานกดยกเลิก take NDLP_TC_004 · `pgrep` หลังยกเลิกยังพบ node 56069 + rec_lock 56019 → หยุดด้วย `kill <pid>` · WRITES_LEDGER ไม่มีบรรทัดใหม่

**สิ่งที่ควรจะเป็น:** ขับเบราว์เซอร์แบบเบื้องหลังเท่านั้น ไม่ยกหน้าต่าง ไม่แย่งโฟกัส · ถ้าต้องใช้จอจริงต้องขออนุญาตก่อน (memory `no-screen-hijack`)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมรบกวนจอ?** — เพราะอัดจากหน้าต่างมีจอ และสั่งยกหน้าต่างขึ้นหน้า
2. **ทำไมอัดจากหน้าต่างมีจอ?** — เพราะต้องใช้ session NDLP ที่เจ้าของงานล็อกอินไว้ในหน้าต่างนั้น (agent ห้ามพิมพ์รหัส)
3. **ทำไมยกหน้าต่าง?** — เพื่อให้เจ้าของงานเห็นหน้าต่างข้อตกลงเร็ว ๆ ตามที่ขอ "เด้งมาสิ" แต่ไม่ได้แยกว่าคำขอนั้นเฉพาะครั้งเดียว ไม่ใช่ทุกขั้น
4. **ทำไมกฎเดิมไม่หยุดผม?** — เพราะกฎอยู่ใน memory เป็นข้อความ ตัวเปิดหน้าต่างเองมี `bringToFront` ฝังอยู่ และไม่มีด่านในสคริปต์อัดที่ปฏิเสธการอัดจากหน้าต่างมีจอ
5. **root cause:** เครื่องมืออัด/เปิดหน้าต่างของเลนนี้ไม่มีโหมดเบื้องหลังที่ใช้ session ที่ล็อกอินไว้ได้ และไม่มีด่านบังคับ no-screen-hijack

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** memory เป็นข้อความ · agent-dispatch-guard ไม่ตรวจเรื่องหน้าต่าง · สคริปต์ไม่ตรวจว่าแท็บที่อัดถูกบังหรือไม่

## 5. แนวทางการแก้ไข (Fix)

- หยุด take ที่ยังรันด้วย pid · ยืนยัน `pgrep` ไม่เหลือ · REC.lock ถูกปล่อย · ledger ไม่เปลี่ยน
- หยุดใช้ `osascript frontmost` และ `bringToFront` ในงานนี้ทั้งหมด
- รอหลักฐานจาก agent เรื่องภาพค้าง แล้วเปลี่ยนการอัดเป็นแบบไม่มีจอ (หรือแบบที่ไม่ถูกหน่วงเมื่อถูกบัง) พร้อมอัดซ้อมผ่าน verify_video ก่อน
