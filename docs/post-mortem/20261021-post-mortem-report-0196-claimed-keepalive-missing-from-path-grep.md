## สรุปสั้น (Executive Summary)

ผมรายงานว่า "`session_keepalive_dev.sh` ไม่มีไฟล์ `state/dev_*` ของ E2E ตามมติ 16/Oct" และโยงว่าเป็นเหตุให้ session ตายข้ามคืน
หลักฐานที่ใช้คือ `grep -c "state/dev_"` ได้ 0 แต่ขั้น E2E มีอยู่แล้วในรูป `capture/e2e_state_touch.js` (`session_keepalive_dev.sh:45-52`, สเปก `docs/sdd/e2e-state-keepalive`) ซึ่งไม่มีสตริงนั้นในไฟล์
log ของ keepalive แสดง `e2e-touch summary ok=7` ตอน VPN ต่อ และ `DEV PREFLIGHT FAILED` ตลอดช่วงที่ VPN หลุด — session ตายเพราะ VPN ไม่ใช่เพราะขาดขั้น
เจ้าของงานเอาข้อความผิดไปใส่ในเป้าหมาย `/goal` · ตรวจพบเองตอนเปิดไฟล์จะลงมือแก้ · แก้ข้อความในแชทแล้ว

## 1. ปัญหา (Problem Statement)

- **ที่พูด:** keepalive ยังไม่ได้เพิ่ม `state/dev_*` ของ E2E ตามมติ 16/Oct เลยทำให้ session ตายข้ามคืน
- **ของจริง:** ขั้น E2E มีแล้วและทำงาน (`ok=7`) · เหตุที่ตายคือ VPN หลุด keepalive จึงแตะ session ไม่ได้

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมรายงานผิด?** — เพราะสรุป "ไม่มี" จาก grep ที่ได้ 0
2. **ทำไม grep ได้ 0?** — เพราะค้นด้วยชิ้นส่วน path ที่ผมเดาว่าจะอยู่ในไฟล์ ไม่ได้ค้นด้วยชื่อความสามารถ (E2E / e2e_state / ชื่อมติ)
3. **ทำไมไม่ค้นด้วยชื่อความสามารถ?** — มติ 16/Oct มีสเปกและ commit ชื่อ `feat/e2e-state-keepalive` อยู่แล้ว (เห็น commit นี้ใน `git log` ตั้งแต่ 2026-10-20) แต่ไม่ได้ค้น `git log --grep` / `docs/sdd/` ก่อนพูด
4. **ทำไมกฎเดิมไม่กัน?** — CLAUDE.md §0 บังคับ "ข้ออ้างเชิงลบต้องแนบคำสั่งค้น + ขอบเขต + จำนวน" ซึ่งผมแนบแล้ว แต่กฎไม่ได้บังคับว่าคำค้นต้องครอบชื่อของสิ่งที่อ้างว่าไม่มี — คำค้นผิดก็ผ่านกฎได้
5. **root cause:** ข้ออ้างว่า "ยังไม่ได้ทำตามมติ/ไม่มีความสามารถ X" ตรวจด้วยชิ้นส่วนโค้ดที่เดาไว้ได้ ไม่ต้องค้นที่ที่การตัดสินใจถูกบันทึก (สเปก · commit · ชื่อมติ)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** กฎ §0 จับ "ไม่แนบคำค้น" แต่ไม่จับ "คำค้นแคบเกิน" · ไม่มี guard ใดตรวจข้อความในแชท

## 4. ผลกระทบ (Impact)

- เป้าหมาย `/goal` ของเจ้าของงานมีข้อที่ตั้งจากข้อมูลผิด 1 ข้อ
- ไม่มีโค้ดหรือข้อมูลถูกแก้ตามข้อความผิด

## 5. แนวทางการแก้ไข (Fix)

- แก้ข้อความในแชททันทีที่พบ พร้อม `path:line` และบรรทัด log จริง (`e2e-touch summary ok=7` · `DEV PREFLIGHT FAILED`)

**ยืนยันแล้วด้วย:** `grep -n "e2e_state_touch" capture/session_keepalive_dev.sh` → บรรทัด 45-52 · log keepalive-dev ช่วง 2026-10-21 11:38–13:00

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

**กฎที่เพิ่มจากเหตุนี้:** ข้ออ้างว่า "ยังไม่ได้ทำ / ไม่มีความสามารถ X / มติ Y ยังไม่ทำ" ต้องค้นที่ที่การตัดสินใจถูกบันทึกก่อน: `git log --all --grep` ด้วยชื่อความสามารถ + `docs/sdd/` + ชื่อมติใน memory — grep ชิ้นส่วน path ที่เดาเองอย่างเดียวไม่นับเป็นหลักฐาน (เพิ่มใน CLAUDE.md §0)

## 7. การตรวจจับปัญหา (Detection)

- ตรวจพบเองตอนเปิดไฟล์เพื่อลงมือแก้ — ก่อนแก้โค้ด
