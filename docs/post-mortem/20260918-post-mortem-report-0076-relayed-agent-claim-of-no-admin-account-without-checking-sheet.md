# Post-Mortem Report #0076 — บอกเจ้าของงานว่า prod ไม่มีบัญชี admin-user โดยยกคำของ agent มาพูดต่อ ไม่ได้เปิดชีทบัญชีดูเอง

**ระบบ:** OLS QA workspace — smoke test บน production ก่อน Go-Live
**สภาพแวดล้อมที่ได้รับผลกระทบ:** รายงานสรุปในแชทถึงเจ้าของงาน · ขอบเขตการรัน smoke รอบแรก
**วันที่เกิดเหตุ:** 2026-09-18

**ผู้จัดทำ:** Claude (ในเซสชันของเจ้าของงาน)
**ระดับความรุนแรง:** Medium — ไม่มีข้อมูลเสียหาย แต่ 5 เคสถูกนับเป็น BLOCKED ผิด และเคสผู้เรียน/ผู้สร้างถูกรันด้วยบัญชีเดียว เจ้าของงานต้องทักเองว่าบัญชีมีอยู่
**ประเภท:** เดาแล้วพูดเหมือนรู้
**ผิดซ้ำจาก:** #0070 (เอาข้อสรุปของแหล่งอื่นมาพูดเป็นข้อเท็จจริงโดยไม่ตรวจ) · #0025 (ใช้ตัวเลขสรุปของเครื่องมือตอบคำถามโดยไม่เปิดข้อมูลดิบ)

## สรุปสั้น (Executive Summary)

agent ที่รัน smoke รายงานว่า production มีบัญชีแค่ผู้เรียน 1 · ผู้สร้าง 1 · admin-content 3 และไม่มี admin-user
ข้อความนี้มาจากการดูเฉพาะไฟล์ session ที่เคยเก็บไว้ 5 ไฟล์ ไม่ใช่จากชีทบัญชี ผมส่งต่อให้เจ้าของงาน 2 ครั้งเหมือนเป็นข้อเท็จจริง
และสั่งงานต่อบนข้อสมมตินั้น (ข้าม NAV-103, ให้ผู้เรียน/ผู้สร้างใช้บัญชีเดียว) ทั้งที่ชีทบัญชีของรอบนี้ ซึ่งเจ้าของงานให้ไว้ตั้งแต่ต้นเซสชัน
มี System Admin 3 บัญชี และผู้เรียน/ผู้สร้างอย่างละ 3 บัญชี · เจ้าของงานวางรายชื่อ 15 อีเมลกลับมาถามว่า "ไม่มีเลยหรอ"

## 1. ปัญหา (Problem Statement)

**สิ่งที่เกิดขึ้น:** รายงานว่า "prod ไม่มีบัญชี admin-user" 2 ครั้ง และตั้งขอบเขตการรันตามนั้น
**สิ่งที่ควรจะเป็น:** ข้ออ้างเชิงลบ ("ไม่มี X") ต้องมีคำสั่งค้นที่รันจริง + ขอบเขต + จำนวน (กฎจาก #0040) และผลของ subagent ต้องตรวจซ้ำก่อนพูดต่อ (CLAUDE.md กฎข้อแรกสุด)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. ทำไมบอกว่าไม่มีบัญชี? — ยกคำของ agent มาพูดต่อ
2. ทำไม agent บอกว่าไม่มี? — มันนับเฉพาะไฟล์ session ที่มีอยู่ในเครื่อง ("บัญชีที่พร้อมใช้") แล้วรายงานเป็น "บัญชีที่มีบน production"
3. ทำไมผมไม่จับ? — ผลของ agent เข้ากับภาพในหัวว่าเก็บ session ไว้ 5 บัญชี จึงไม่ถูกตั้งคำถาม
4. ทำไมไม่เปิดชีท? — ชีทบัญชีอยู่ในมือตั้งแต่ต้นเซสชัน (ใช้ตอน regression) แต่ไม่มีขั้นตอนบังคับให้เทียบข้ออ้างเรื่องบัญชีกับชีทก่อนพูด
5. ทำไมไม่มีขั้นตอนนั้น? — กฎข้ออ้างเชิงลบ (#0040) ผูกกับคำที่ผมพิมพ์เอง ไม่ได้ครอบข้ออ้างเชิงลบที่รับมาจาก subagent

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** กฎข้อแรกสุด (ผล subagent ไม่ใช่หลักฐาน) และ #0040 เป็นข้อความ ไม่มีเครื่องมือบังคับ · ผมยังส่งคำของ agent ต่อในรูปตัวเลือกของ AskUserQuestion ซึ่งไม่มีด่านอะไรตรวจ

## 4. ผลกระทบ (Impact)

- 5 เคส admin-user + NAV-103 ถูกนับเป็น BLOCKED/ไม่ได้รันในรอบแรก และเคสที่ต้องใช้บัญชีที่ 2 ถูกรันด้วยบัญชีเดียว
- เจ้าของงานต้องทักและล็อกอินเพิ่ม · ความเชื่อถือรายงานลดลง

## 5. แนวทางการแก้ไข (Fix)

- เปิดชีทบัญชีจริง (อ่านอย่างเดียว) ยืนยันรายชื่อ 15 บัญชีและบทบาท
- เจ้าของงานล็อกอินให้ครบทุกบัญชีที่ยังไม่มี session · ยืนยันบทบาทสดผ่าน `get-session` บนโดเมน OLS · ใส่ทุกบัญชีเข้าตัวอุ่น session
- สั่งรันเคสที่ถูกนับ BLOCKED/แชร์บัญชีใหม่ในโฟลเดอร์แยก

**ยืนยันแล้วด้วย:** `role_probe.js` คืน `SYSTEM_ADMIN` / `NDLP_LEARNER` / `NDLP_CREATOR` · log ตัวอุ่น `warmed+verified` ครบ 8 บัญชี ณ 09:08 UTC

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

- ข้ออ้างเรื่อง "มี/ไม่มีบัญชี" ต้องมาจากชีทบัญชีของรอบนั้น (แหล่งจริง) เท่านั้น ห้ามมาจากรายการไฟล์ session ในเครื่อง — ไฟล์ session บอกได้แค่ว่าเคยล็อกอินบัญชีไหนไว้
- ข้ออ้างเชิงลบที่ได้มาจาก subagent ต้องผ่านด่านเดียวกับที่ผมพิมพ์เอง: คำสั่งค้น + ขอบเขต + จำนวน ก่อนส่งต่อเจ้าของงาน
- คำสั่งงานของ agent ที่ต้องใช้บัญชี ให้แนบรายชื่อบัญชีจากชีทไปด้วย และสั่งว่า "ไม่มี session ≠ ไม่มีบัญชี ให้รายงานว่าต้องล็อกอินเพิ่ม"

**กฎที่เพิ่มจากเหตุนี้:** `CLAUDE.md` หัวข้อ Post-mortems (Report #0076)

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- ยอมรับทันที เปิดชีทยืนยัน และจดหนี้ในเทิร์นเดียวกัน · ยืนยันบทบาทสดทุกบัญชีหลังล็อกอิน

### สิ่งที่ต้องปรับปรุง
- "ไม่มี session" กับ "ไม่มีบัญชี" เป็นคนละคำถาม ต้องแยกให้ออกก่อนพูด
