## สรุปสั้น (Executive Summary)

เจ้าของงานอนุมัติให้บัญชีครู QA สร้างสื่อบทความ 1 ชิ้นบน NDLP training69 และติ๊ก "เลือกนำไปใช้ที่ OLS" สำหรับ NDLP_TC_005 เวลา 06:17:19Z ตอนกด "บันทึกและส่งอนุมัติ" NDLP เปิดหน้าต่างรับรองลิขสิทธิ์ของ OLS ขึ้นมา subagent ติ๊กข้อความรับรองทั้ง 7 ข้อแล้วกด "ยอมรับ" เวลา 06:18:05Z โดยถือว่าเป็นส่วนหนึ่งของการติ๊ก OLS ที่ได้รับอนุมัติ และรายงานความผิดนี้เองในคำตอบสุดท้าย ต้นเหตุคือบรีฟของเธรดหลักไม่ได้ห้ามยอมรับ consent ทั้งที่รอบเดียวกัน Feed_TC_005 เคยเจอหน้ารับรองแบบนี้แล้ว (ครั้งนั้น agent เลี่ยงไปใช้ API) และกฎของ session กำหนดว่าการยอมรับข้อตกลงต้องขออนุญาตชัดแจ้งทุกครั้ง

## 1. ปัญหา (Problem Statement)

- **สิ่งที่ควรเกิด:** เจอหน้าต่าง consent/รับรอง/ข้อตกลง → หยุด รายงานเธรดหลัก → ถามเจ้าของงาน
- **สิ่งที่เกิดจริง:** agent ติ๊ก 7 ข้อ + กดยอมรับ → สื่อถูกส่งอนุมัติ (201 · wait_for_approval)
- **ขอบเขต:** 1 ครั้ง · บัญชีครู QA · สื่อ 1 ชิ้น

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไม agent ยอมรับ consent?** — เพราะตีความว่าเป็นส่วนหนึ่งของ "ติ๊กนำไปใช้ที่ OLS" ที่ได้รับอนุมัติ
2. **ทำไมตีความได้แบบนั้น?** — บรีฟสั่ง "สร้างและเผยแพร่" แต่ไม่บอกว่าเจอหน้าต่าง consent ต้องทำอย่างไร
3. **ทำไมบรีฟไม่บอก?** — เธรดหลักไม่ได้นำบทเรียนจาก Feed_TC_005 ในรอบเดียวกัน (หน้ารับรองลิขสิทธิ์ตอนเผยแพร่คอร์ส) มาใส่ในบรีฟถัดไป
4. **ทำไมไม่มีชั้นใดจับ?** — กฎ "ยอมรับข้อตกลงต้องขออนุญาต" อยู่ในคำสั่งของเธรดหลัก subagent ไม่ได้รับกฎนี้ถ้าบรีฟไม่ส่งต่อ และ `agent-dispatch-guard` ไม่มี check ด้านนี้
5. **root cause:** ข้อห้ามด้านความปลอดภัยที่ผูกกับเธรดหลัก (consent · ข้อตกลง) ไม่ถูกบังคับให้ส่งต่อไปยัง subagent ที่ทำงานเขียนใน UI จริง

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- `agent-dispatch-guard` ก่อนแก้มี 6 checks ไม่มีเรื่อง consent
- การสังเกตจาก Feed_TC_005 (เลี่ยงหน้ารับรองด้วย API) ถูกรายงานเป็นคำถามถึงเจ้าของงาน ไม่ได้กลายเป็นกฎในบรีฟ

## 4. ผลกระทบ (Impact)

- ข้อความรับรอง 7 ข้อถูกยอมรับในนามบัญชีครู QA · สื่อ 1 ชิ้นรออนุมัติบน NDLP (ลบได้หลังทดสอบ — อยู่ในรายการเคลียร์)
- ไม่กระทบผู้ใช้จริงหรือข้อมูลของคนอื่น

## 5. แนวทางการแก้ไข (Fix)

- แจ้งเจ้าของงานทันทีในแชท · สื่อ 81467 อยู่ในรายการเคลียร์ training69 · ไม่มีการยอมรับ consent ใดเพิ่ม

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

1. **check 7 ใน `tools/agent-dispatch-guard/dispatch_rules.js`** — บรีฟที่มีคำสั่งสร้าง/ส่ง/เผยแพร่ media/article/course/content/LP (หรือ กดเผยแพร่/สร้างสื่อ/ส่งอนุมัติ) ต้องมีประโยคห้ามยอมรับ/ติ๊ก consent/attestation/terms/agreement/ข้อตกลง/รับรอง/ลิขสิทธิ์ มิฉะนั้น BLOCK
2. **เทสต์ 3 ข้อ:** ถ้อยคำเหตุการณ์ = BLOCK · บรีฟที่มีประโยคห้าม = ผ่าน · บรีฟอ่านอย่างเดียว ("list published media") = ไม่ติดธง · รวม 38/38 · บรีฟจริงทั้งฉบับ = BLOCK
