## สรุปสั้น (Executive Summary)

`pre-push` ไล่ไฟล์ชุดเทสต์ด้วย glob ใต้ `shopt -s nullglob` เมื่อ glob ไม่ตรงกับไฟล์ใดเลย ลูปไม่ทำงานแม้แต่รอบเดียว
ตัวแปร `rc` จึงคงค่า 0 แล้วสคริปต์เดินไปถึงบรรทัดสุดท้ายและพิมพ์ **`✅ ชุดเทสต์เขียวบนทุก commit ที่จะ push`**

วัดกับคอมมิตจริงในประวัติ repo นี้ (`f42885df` วันที่ 2026-08-13 ซึ่งเป็นคอมมิตสุดท้ายก่อนมีไฟล์เทสต์ตัวแรก
และมีไฟล์เทสต์ใต้ `tools/` เป็น 0 ไฟล์) — ด่านพิมพ์บรรทัดเขียวนั้นออกมาและจบด้วยรหัส 0

`repo` นี้รู้จักบั๊กรูปนี้อยู่แล้ว: ไฟล์ CI มีด่านกันไว้พร้อมประโยคอธิบายว่า *"A suite that matched nothing must fail:
'no tests ran' is not 'tests passed'"* และ `CLAUDE.md` เล่าเรื่อง `|| break` ที่ทำให้คำสั่งรวมจบด้วย 0 ทั้งที่ชุดเทสต์แดง
มีแต่ด่านที่บล็อก push เท่านั้นที่ไม่เคยได้ด่านนี้ไปด้วย

## 1. ปัญหา (Problem Statement)

- คอมมิตที่ไม่มีไฟล์ชุดเทสต์เลย ผ่านด่าน push ไปได้ พร้อมข้อความยืนยันว่าเทสต์เขียว
- ข้อความที่พิมพ์ออกมาไม่ได้แค่เงียบ แต่ **ยืนยันสิ่งที่ไม่ได้เกิดขึ้น** ซึ่งแย่กว่าการไม่พิมพ์อะไรเลย
- หัวไฟล์ของ hook เขียนไว้เองว่า *"fail closed: รันไม่ได้ = ไม่ให้ push · gate ที่รันไม่ได้ ไม่ใช่ gate ที่ผ่าน"*
  พฤติกรรมจริงขัดกับประโยคนั้นตรงๆ

**สิ่งที่ควรจะเป็น:** จำนวนชุดที่จับได้เป็น 0 = ปฏิเสธ พร้อมบอกเหตุผล — เหมือนที่ไฟล์ CI ทำอยู่แล้ว

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

`rc=0` ถูกตั้งไว้ล่วงหน้าให้แปลว่า "ยังไม่พบความล้มเหลว" แต่ตอนพิมพ์ผลมันถูกอ่านว่า "ผ่าน" ซึ่งเป็นคนละความหมาย
ค่าเริ่มต้นที่แปลว่า *ยังไม่มีข้อมูล* กับค่าที่แปลว่า *ผ่านแล้ว* ใช้ตัวแปรตัวเดียวกัน ระหว่างสองความหมายนั้น
สิ่งที่หายไปคือ **จำนวนสิ่งที่วัดไปจริง** ซึ่งไม่มีใครนับ

### 5 Whys

1. **ทำไมคอมมิตที่ไม่มีเทสต์ผ่านด่านไปได้?** — เพราะ `rc` เป็น 0 ตอนถึงบรรทัดตัดสิน
2. **ทำไม `rc` ถึงเป็น 0?** — เพราะไม่มีรอบไหนของลูปตั้งค่ามันเป็น 1
3. **ทำไมไม่มีรอบไหนทำงาน?** — เพราะ `nullglob` ทำให้ glob ที่ไม่ตรงกับไฟล์ใดเลยกลายเป็นรายการว่าง
4. **ทำไมรายการว่างถึงไม่ถูกมองว่าผิดปกติ?** — เพราะสคริปต์ไม่เคยนับว่าจับไฟล์ได้กี่ไฟล์ มีแต่ตัวแปรที่บอกว่า
   "มีอันไหนพังไหม" ซึ่งตอบว่า "ไม่มี" ได้ทั้งตอนที่ทุกอย่างผ่าน และตอนที่ไม่มีอะไรให้รัน
5. **ทำไมถึงเขียนแบบนั้นทั้งที่ CI มีด่านนี้อยู่แล้ว?** — **root cause:** ตอนเขียน hook นี้ ต้นแบบที่หยิบมาคือ
   *คำสั่งรันเทสต์* ใน `CLAUDE.md` ไม่ใช่ *ไฟล์ CI* ที่มีตัวนับอยู่ · ความรู้เรื่องนี้มีอยู่ใน repo แล้วเป็นลายลักษณ์อักษร
   แต่ไปอยู่คนละไฟล์กับที่คนกำลังเขียน และไม่มีอะไรบังคับให้สองที่นี้ตรงกัน

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** `pre-push` **ไม่มีเทสต์เลยสักข้อ** ทั้งที่ตัวมันเองคือด่านที่รันเทสต์ให้คนอื่น ·
CI มีตัวนับแต่ CI ไม่ได้ตรวจ hook · และในทางปฏิบัติ ทุกคอมมิตตั้งแต่ 2026-08-13 มีไฟล์เทสต์อยู่แล้ว
สภาพที่ทำให้บั๊กแสดงตัวจึงไม่เคยเกิดขึ้นเองในงานประจำวัน

## 5. แนวทางการแก้ไข (Fix)

- นับจำนวนไฟล์ที่ glob จับได้จริงด้วยตัวแปรแยก แล้ว **ปฏิเสธเมื่อเป็นศูนย์** พร้อมข้อความบอกว่าไม่มีอะไรให้วัด
  และชี้ว่าถ้าย้ายที่ชุดเทสต์จริงต้องแก้ทั้ง hook และไฟล์ CI พร้อมกัน
- บรรทัดสรุปตอนผ่าน **บอกจำนวนชุดที่รันจริง** ไม่ใช่เครื่องหมายถูกเปล่าๆ — ตัวเลขที่หดลงผิดปกติคือสัญญาณเดียว
  ที่คนเห็นได้ก่อนที่ด่านจะวัดไม่ได้เลย
- เพิ่มชุดเทสต์ `tools/push-gate/pre_push.test.js` 5 ข้อ ซึ่งรัน hook จริงกับคอมมิตจริงในประวัติ
  และข้ามอย่างชัดเจนถ้า clone นั้นตื้นเกินกว่าจะมีคอมมิตดังกล่าว

**ยืนยันแล้วด้วย:** ก่อนแก้ เทสข้อแรกแดงพร้อมข้อความว่า *"the push gate allowed a commit it never measured"* ·
หลังแก้ ด่านปฏิเสธคอมมิตเดียวกันด้วยรหัสไม่เป็นศูนย์และไม่พิมพ์เครื่องหมายถูก · การลบ ref ยังผ่านตามเดิม ·
เทสทั้ง repo 27 ไฟล์เขียว

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- ไล่ทั้งคลาสตามคำสั่ง ไม่ได้หยุดที่ไฟล์ที่เพิ่งแก้ไป และนั่นคือสิ่งเดียวที่ทำให้เจอ
- แยกได้ว่า fail-open แบบไหน **ตั้งใจและเขียนเหตุผลไว้** (สามจุด — ไม่แตะ) กับแบบไหนเป็นบั๊กเงียบ (จุดนี้)
- เขียนเทสให้แดงก่อนแก้ จึงพิสูจน์ได้ว่าเทสวัดของจริง ไม่ใช่เขียวเพราะไม่ได้วัดอะไร

### สิ่งที่ต้องปรับปรุง
- ความรู้ที่มีอยู่แล้วในไฟล์ CI ไม่ได้เดินทางไปถึง hook ที่ทำงานเดียวกัน — ของสองชิ้นที่ทำหน้าที่เดียวกัน
  ต้องมีอะไรผูกให้ตรงกัน ไม่ใช่หวังว่าคนเขียนจะจำได้
- ด่านที่ไม่มีเทสต์ของตัวเอง คือด่านที่ไม่มีใครรู้ว่ามันยังทำงานอยู่ไหม โดยเฉพาะด่านที่หน้าที่คือรันเทสต์ให้คนอื่น

```
[ols-qa pre-push] รันชุดเทสต์บน f42885df …
[ols-qa pre-push] ✅ ชุดเทสต์เขียวบนทุก commit ที่จะ push
exit=0
```

**หลักฐานหลังแก้:**

```
FAIL (ก่อนแก้) the hook refuses a commit whose tree contains no test file at all
              -> the push gate allowed a commit it never measured

PASS (หลังแก้) the hook refuses a commit whose tree contains no test file at all
PASS           a push that deletes a ref is still a no-op, not a refusal
PASS           the source counts what it matched — "none ran" cannot read as "all passed"
PASS           the hook still declares itself fail-closed, and still blocks with no node
PASS           every suite the gate would run is discoverable from the repo root
```
