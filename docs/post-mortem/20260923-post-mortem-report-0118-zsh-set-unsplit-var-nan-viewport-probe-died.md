## สรุปสั้น (Executive Summary)

เธรดหลักจะวัดว่าหน้าโปรไฟล์ของ TC_004 เลื่อนได้แค่ไหนที่ 2 ขนาดจอ จึงรัน `for V in "1920 1080" "1366 768"; do set -- $V; env … VW=$1 VH=$2 …` ใน zsh
zsh ไม่แยกคำของ `$V` ที่ไม่ครอบเครื่องหมายคำพูด `set -- $V` จึงได้อาร์กิวเมนต์เดียว — `VW="1920 1080"` และ `VH` ว่าง · สคริปต์แปลงด้วย `Number(process.env.VW || 1920)` ได้ NaN (ส่วน `VH=""` ตกไปที่ค่าเริ่มต้น 1080) แล้วล้มก่อนเปิดหน้าเว็บทั้ง 2 รอบ (rc=1, log มีแค่บรรทัด `start`)
เธรดหลักเห็นจากบรรทัด `== 1920 1080x rc=1` ของตัวเอง จดแถว ledger แล้วรันใหม่แยกคำสั่งพร้อมค่าชัดเจน ได้ค่าถูก (viewportH 1080 / 768)
มาตรการ #0117 อยู่ที่ตัวอัดและสคริปต์ทดลอง ไม่ครอบ shell ที่เธรดหลักพิมพ์เอง — รอบนี้เพิ่มชั้นใหม่ที่ตัวคำสั่ง (`tools/zsh-split-guard/`) และที่สคริปต์ (ปฏิเสธ VW/VH ที่ไม่ใช่ตัวเลข)

## 1. ปัญหา (Problem Statement)

- คำสั่งที่รัน (ใน zsh): `for V in "1920 1080" "1366 768"; do set -- $V; env … VW=$1 VH=$2 … node capture/profile_tc004_t69_full.js …; echo "== ${V}x rc=$?"; done`
- `review_0923/P004_probe_1790147932768.jsonl` และ `P004_probe_1790147933318.jsonl` มีบรรทัดเดียวแต่ละไฟล์ (วัดด้วย `/usr/bin/wc -l` = 1 และ 1): `{"ts":"2026-09-23T07:18:52.768Z","step":"start","probe":true}` · `{"ts":"2026-09-23T07:18:53.318Z","step":"start","probe":true}` — ล้มหลัง `start` ก่อนเปิดหน้าเว็บ
- บรรทัด echo ของเธรดหลัก: `== 1920 1080x rc=1` — `${V}x` แสดงว่าทั้งก้อนเป็นคำเดียว และ rc=1
- ต้นทางในสคริปต์ (สำเนาทำงานขณะเกิดเหตุ): `viewport: { width: Number(process.env.VW || 1920), height: Number(process.env.VH || 1080) }` — `Number("1920 1080")` = NaN ไม่มีจุดไหนปฏิเสธ
- รันใหม่แยกคำสั่ง: `P004_probe_1790147960622.jsonl` (07:19:20Z) `viewportH` 1080 · `P004_probe_1790147972171.jsonl` (07:19:32Z) `viewportH` 768 `docExtra` 34 — ค่าตรงกับที่ตั้งใจ

**สิ่งที่ควรจะเป็น:** คำสั่งที่ส่งค่าหลายค่าต่อรอบใน zsh ต้องแยกคำอย่างชัดแจ้ง (`${=V}` / array / เขียนทีละคำสั่ง) · สคริปต์ที่รับค่าจาก env ต้องปฏิเสธค่าที่แปลงไม่ได้ตั้งแต่ต้นพร้อมข้อความ — หลักจาก #0117 (ห้ามค่าเริ่มต้นเงียบในตัวแปรที่ถูกเปรียบเทียบ) และ #0097 (ปฏิเสธค่าที่ใช้ไม่ได้ตั้งแต่เริ่ม)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

กลไกเดียวกับ #0117: คำสั่งถูกเขียนตามพฤติกรรม bash (`$V` ไม่ครอบคำพูด = แยกคำ) แต่ Bash tool บนเครื่องนี้รัน zsh ที่ไม่แยกคำของ scalar
ต่างจาก #0117 ตรงที่คนพิมพ์คือเธรดหลักเอง (ไม่ใช่ subagent) และปลายทางคือ `Number()` ที่ให้ NaN แทนค่าเริ่มต้น — สคริปต์จึงล้ม (ดีกว่าเงียบ) แต่ล้มด้วยข้อความที่ไม่บอกว่าค่าไหนผิด

### 5 Whys

1. **ทำไม probe ทั้ง 2 รอบล้มก่อนเปิดเว็บ?** — เพราะ viewport width เป็น NaN (`Number("1920 1080")`) จึงสร้าง browser context ไม่ได้
2. **ทำไม VW ได้ "1920 1080"?** — เพราะ `set -- $V` ใน zsh ไม่แยกคำ `$1` ได้ทั้งก้อน `$2` ว่าง
3. **ทำไมเธรดหลักยังเขียน loop แบบนี้ทั้งที่เพิ่งปิด #0117?** — เพราะบทเรียน #0117 ถูกบันทึกเป็นข้อความในรายงานและ brief ของ agent ทดลอง (P3 ค้างใส่แม่แบบ) — ไม่มีอะไรทำงานตอนเธรดหลักพิมพ์คำสั่ง Bash
4. **ทำไมสคริปต์ไม่บอกว่าค่าไหนผิด?** — เพราะ `Number(env || default)` ไม่ตรวจผล — NaN ผ่านไปถึง Playwright · มาตรการ #0117 ที่เพิ่มในสคริปต์นี้ครอบแค่ `FPS` (ต้องระบุ ไม่มีค่าเริ่มต้น) ไม่ครอบ `VW`/`VH`
5. **root cause:** **ไม่มีชั้นที่ทำงาน ณ จุดที่คำสั่ง shell ถูกพิมพ์** — ทุกมาตรการของคลาสนี้ (#0097 → #0117) อยู่ปลายทาง (ตัวอัด · สคริปต์ทีละตัว · brief) จึงต้องมีคนจำเพิ่มทีละตัวแปรทีละสคริปต์ ส่วนรูปคำสั่งที่เป็นต้นเหตุ (`set -- $V`, loop รายการหลายคำ) ไม่มีใครตรวจ

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- #0117 P1 (`expect: { outFps }` ในตัวอัด) — ยังค้างรอเจ้าของงาน และต่อให้มีก็ครอบแค่ fps ของตัวอัด ไม่ใช่ viewport
- #0117 P2/P3 (ห้ามค่าเริ่มต้นในสคริปต์ทดลอง · brief ว่า shell คือ zsh) — เขียนสำหรับ subagent ทดลอง เธรดหลักไม่ได้ผ่าน brief
- FPS-required check ที่เพิ่มในสคริปต์หลัง #0117 — ครอบ `FPS` ตัวเดียว `VW`/`VH` ยังมีค่าเริ่มต้นและไม่ปฏิเสธ NaN
- hook PreToolUse บน Bash ที่มีอยู่ (customer-content · git-staging · issue-creation · discord-notify) — ไม่มีตัวไหนดูรูปการแยกคำของ shell
- ชั้นที่จับได้จริงคือบรรทัด echo `${V}x rc=$?` ที่เธรดหลักใส่เอง — เป็นพฤติกรรม ไม่ใช่ด่าน

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- บรรทัด echo ใส่ `${V}` และ `rc` ทำให้เห็นทั้งก้อนที่ไม่ถูกแยกทันที
- ตรวจ rc และ log ก่อนสรุปตัวเลข · จดแถว ledger ก่อนรันใหม่
- เก็บ log ที่ใช้ไม่ได้ไว้เป็นหลักฐาน

### สิ่งที่ต้องปรับปรุง
- บทเรียนที่เพิ่งเขียนไม่มีผลกับมือที่พิมพ์คำสั่ง ถ้าไม่มีด่านที่ทำงาน ณ ตอนพิมพ์
- มาตรการ "ห้ามค่าเริ่มต้น" ที่ใส่ทีละตัวแปร (FPS) ทิ้งตัวแปรข้างเคียง (VW/VH) ในไฟล์เดียวกันไว้ — ปิดคลาสต้องไล่ทุกค่าจาก env ในไฟล์เดียวกันรอบเดียว (บทเรียน #0003)
