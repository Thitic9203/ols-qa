## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

สคริปต์ fixture ถูกเขียนเฉพาะกิจในเลนเพื่อให้ได้สื่อไว้อัด ชื่อถูกต่อด้วยป้ายเลน/เคสเพื่อให้ตัวสคริปต์เองหาเจอภายหลัง ซึ่งเป็นนิสัยของสคริปต์ทดสอบ ไม่ใช่ของข้อมูลที่ดูเหมือนจริง

### 5 Whys

1. **ทำไมสื่อมีชื่อ/คำอธิบายที่ผิดกฎ?** — เพราะสคริปต์ fixture ต่อป้าย `(laneT2 Feed_TC_001)` และใช้คำอธิบาย placeholder
2. **ทำไมสคริปต์เขียนแบบนั้น?** — เพราะใช้ป้ายนั้นเป็นตัวระบุตัวตนของ fixture เพื่อค้นหา/ลบภายหลัง
3. **ทำไมไม่ผ่าน ols-data-prep?** — เพราะเลนเขียนสคริปต์สร้างเองในโฟลเดอร์เลน ไม่ได้เรียกเครื่องมือของ ols-data-prep ที่มี gate §7+§8
4. **ทำไมไม่มีอะไรหยุดก่อน POST?** — เพราะไม่มีด่านในเส้นทางเขียน (ledger / write guard) ที่ตรวจคำต้องห้ามในฟิลด์ชื่อ/คำอธิบาย/เนื้อหา
5. **ทำไมด่านนี้ไม่มี?** — เพราะกฎ §11 บังคับผ่านเครื่องมือของ ols-data-prep เท่านั้น เมื่อสคริปต์เลี่ยงเครื่องมือนั้นก็ไม่มีชั้นใดเหลือ (root cause: กฎเนื้อหาผูกกับเครื่องมือ ไม่ได้ผูกกับการเขียนทุกครั้ง)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** WRITES_LEDGER บันทึก intent แต่ไม่ตรวจเนื้อหา · `write_guard.js` ตรวจ env ไม่ตรวจคำ · name-guard เป็นตัวสแกนภายหลัง (และรันบน pre-prod) · ด่านเดียวที่จับได้คือเลน R2 อ่าน ledger
