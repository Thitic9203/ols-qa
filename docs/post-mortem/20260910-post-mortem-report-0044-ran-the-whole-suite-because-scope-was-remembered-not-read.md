- คำสั่งที่ยิงจริงคือ `npx playwright test --reporter=list,json,html` ไม่มี `--project` ไม่มี `--grep`
- ล็อกของรอบนั้นพิมพ์ `Running 1177 tests` (`out/training69-smoke-2026-09-09/run6.log`)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

จุดตัดสินใจที่ผิดคือตอนประกอบคำสั่งรัน ผมถือว่า "ชุดเคสของรอบนี้" เป็นสิ่งที่ผมรู้อยู่แล้วจากบทสนทนา
จึงข้ามขั้นเปิดรายงานรอบอ้างอิง · ตอนนั้นมันดูถูกเพราะรอบก่อนบน training69 ก็รันด้วยคำสั่งลักษณะนี้
และได้ 171 เทสต์ซึ่งใกล้เคียงกับที่คาด — แต่ 171 เองก็ไม่ใช่ 111 และผมไม่เคยตั้งคำถามกับส่วนต่างนั้น

### 5 Whys

1. **ทำไมถึงรัน 1,177 เทสต์?** — เพราะคำสั่งไม่มีตัวจำกัดสโคป และ config เปิดโปรเจกต์ responsive
   เพิ่มเมื่อ env เป็น training
2. **ทำไมคำสั่งถึงไม่มีตัวจำกัดสโคป?** — เพราะผมไม่รู้ว่ารอบอ้างอิงจำกัดสโคปไว้ยังไง
3. **ทำไมถึงไม่รู้?** — เพราะไม่เคยเปิดรายงานของรอบอ้างอิงอ่าน ทั้งที่ไฟล์อยู่ในเครื่องและอ่านได้ในคำสั่งเดียว
4. **ทำไมถึงไม่เปิดอ่าน?** — เพราะเชื่อว่าตัวเองรู้จำนวนเคสอยู่แล้ว จำนวนที่ "รู้" นั้นมาจากบทสนทนา
   ไม่ได้มาจากการวัด
5. **ทำไมความเชื่อนั้นถึงไม่ถูกตรวจ?** — **เพราะไม่มีอะไรวัดสโคปก่อนรัน** ตัวรันยอมรับคำสั่งที่ไม่ระบุ
   สโคปเสมอ และไม่มีใครเทียบสิ่งที่มันเลือกกับสิ่งที่รอบนี้ควรรัน — นี่คือ root cause

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ไม่มีชั้นไหนครอบเรื่องนี้เลย · `investigation-guard` คุมว่าต้องเรียก
สกิลตอนสืบปัญหา ไม่ได้คุมสโคปของการรัน · `postmortem-guard` คุมเอกสาร · ตัวรันเองไม่มีความคิดเรื่อง
"รอบนี้ควรมีกี่เคส" · สิ่งเดียวที่จับได้คือสายตาเจ้าของงาน ซึ่งไม่ใช่ชั้นป้องกัน

## 5. แนวทางการแก้ไข (Fix)

- ฆ่ารอบที่ผิดสโคปทิ้ง แล้วดึงรายชื่อเคสจากรายงานรอบ dev ออกมาเป็นตัวล็อก — ได้ 104 รหัสเคส
  จาก 111 แถว (อีก 7 แถวคือขั้นเข้าสู่ระบบ)
- รันใหม่ด้วย `--project` 6 ตัว + `--grep` ที่ประกอบจากรายชื่อนั้น ได้ 120 เทสต์
- ตรวจส่วนต่างก่อนรัน: ครอบ 104 เคสอ้างอิง **ครบ ไม่ขาดสักเคส** · เกินมา 9 แถวจาก lane เพิ่มบน training
  ซึ่งถูกประกาศไว้ ไม่ใช่ของหลุด

**ยืนยันแล้วด้วย:** `--list` ก่อนรันพิมพ์ `Total: 120 tests in 9 files` และการเทียบคู่ (โปรเจกต์, รหัสเคส)
กับรายงานรอบ dev รายงาน `EXTRA 3 · MISSING none`
