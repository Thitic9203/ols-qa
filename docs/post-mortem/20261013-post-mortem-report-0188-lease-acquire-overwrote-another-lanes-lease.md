## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไม L4 ใช้บัญชีที่ L1a ถืออยู่ได้?** — `acquire` เขียนทับได้เสมอ
2. **ทำไม acquire ไม่ตรวจ?** — ออกแบบให้ lease เป็นสัญญาณสำหรับ relink อย่างเดียว ไม่ได้ออกแบบให้กันเลนกับเลน
3. **ทำไมเธรดหลักไม่จับได้ตอนรีวิว?** — รีวิวเฉพาะเส้นทาง relink (`inUseProbe`) และเทสต์ครอบแค่ "lease fresh → relink เลื่อน" ไม่มีเทสต์ "2 ผู้ถือจองบัญชีเดียวกัน"
4. **ทำไมรอบแก้แรกยังพลาด?** — ใส่กฎ pid ตายโดยไม่ได้ตรวจว่า pid ที่บันทึกคือโปรเซสอะไร (`process.ppid` ของ CLI = shell ชั่วคราว)
5. **root cause** — กฎใหม่ที่บอกว่า "บังคับ" ถูก deploy โดยไม่มีเทสต์ของเงื่อนไขที่กฎตั้งใจกัน (สองเลนชนกัน) ทั้งที่กฎ #0002 กำหนดว่าชั้นที่พึ่งข้อสมมติเดียวนับเป็นชั้นเดียว

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** dispatch guard ตรวจแค่ว่า brief มีคำสั่ง acquire/release · lane-lease-check ตรวจแค่ว่าปล่อยครบตอนจบ · ไม่มีชั้นไหนตรวจว่า acquire ปฏิเสธผู้ถือคนที่ 2
