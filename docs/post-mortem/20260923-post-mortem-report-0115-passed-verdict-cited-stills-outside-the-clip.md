## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

เลนอัดมีหลักฐาน 2 ชุดในมือ: MP4 กับภาพ PNG/ผล `page.evaluate` ที่สคริปต์อัดเก็บไว้เอง ชุดหลังอ่านง่ายกว่า (ข้อความ toast อยู่ในผลโปรแกรมตรงๆ · ภาพ PNG คมกว่าเฟรม fps 3)
จึงถูกใช้ตัดสินแทนการเปิดคลิป ทั้งที่สิ่งที่ส่งมอบคือคลิป และกฎนับเฉพาะคลิป

### 5 Whys

1. **ทำไมคลิปที่ไม่มีหน้าจอตาม ER ถึงได้ "ผ่าน"?** — เพราะเลนตัดสินจากภาพ PNG และผล `page.evaluate` ที่สคริปต์อัดเก็บแยก ไม่ได้ดูเฟรมใน MP4
2. **ทำไมตัดสินจากของนอกคลิปได้?** — เพราะสคริปต์อัดผลิตหลักฐานคู่ขนาน (ภาพนิ่ง + assert ในโปรแกรม) ที่ "ยืนยัน ER" ได้โดยไม่ต้องให้ ER ไปอยู่ในคลิป — และเมื่อ flow ในแท็บที่ถูกอัดไปจบที่หน้า 404 หรือไม่ถึงฟอร์ม ภาพนิ่งกับ assert ก็ยังขึ้นว่าถูก *(ทำไมภาพนิ่งมีหน้าจอ ER แต่ MP4 ไม่มี — ยังไม่ตรวจ · สมมติฐาน: ถ่ายจากคนละเพจ/แท็บกับที่ screencast อัด จะตรวจด้วยการอ่านสคริปต์อัด 22/Sep ตอนอัดใหม่)*
3. **ทำไมไม่มีอะไรจับว่าหลักฐานที่อ้างไม่อยู่ในคลิป?** — เพราะด่านที่มีทั้งหมดดูแค่ "รูปแบบ" ของคลิป: `gate` ดู overlay · `verify_video.py` ดูการเคลื่อนไหว/ค้าง (และผ่านแค่คำเตือน — #0113) ไม่มีด่านไหนถามว่า "หน้าจอตาม ER อยู่ในเฟรมไหน"
4. **ทำไมตัวเขียนผลรับหมายเหตุแบบนี้?** — เพราะ `put_verdict.py` ตรวจแค่ค่า `ผ่าน|ไม่ผ่าน` กับคีย์มีอยู่ (`put_verdict.py` บรรทัด 9–13) หมายเหตุเป็นข้อความอิสระ ไม่บังคับให้ชี้เวลาในคลิป
5. **ทำไมเลนเขียนผลลงที่เก็บได้โดยตรง?** — root cause: **ผลตัดสิน "ผ่าน" เข้าที่เก็บได้โดยไม่ต้องมีการอ้างเฟรมในคลิปที่ตรวจซ้ำได้** — กฎ §6 อยู่ในรูปข้อความ ไม่มีชั้นเครื่องมือที่บังคับว่าผ่านต้องผูกกับ "เวลาในคลิป + สิ่งที่เห็น" ต่อ ER ทุกข้อ เลนจึงเลือกหลักฐานที่สะดวกได้เอง

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- `CLAUDE.md` §6 + บันทึกในแผนเรื่องภาพนิ่ง `Profile_TC_004` — เป็นข้อความ ไม่มีตัวบังคับ
- `gate` ใน `capture.json` — ตรวจ overlay/caption ไม่ใช่เนื้อหา ER (`gate.passed=true` ทั้ง 3 ไฟล์)
- `verify_video.py` — ตรวจการเคลื่อนไหว และรอบนี้ผ่านแบบคำเตือนเพราะไม่มี `--strict-motion` (#0113)
- `put_verdict.py` — ไม่อ่านหมายเหตุ
- รีวิวเธรดหลัก — 22/Sep ไม่ได้ตรวจเฟรมก่อนผลเข้าที่เก็บ จับได้ 23/Sep เพราะเจ้าของงานเคาะให้ตรวจ 4 คลิปนี้โดยเฉพาะ
