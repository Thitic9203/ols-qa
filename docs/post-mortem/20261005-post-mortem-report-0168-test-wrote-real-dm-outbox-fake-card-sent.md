## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมการ์ดปลอมถึงเข้า DM?** — เพราะ heartbeat ส่งทุกอย่างที่อยู่ในไฟล์คิวจริง และมีการ์ดของเทสต์อยู่ในนั้น
2. **ทำไมการ์ดของเทสต์อยู่ในคิวจริง?** — เพราะ `test_fail_notify_dedup.py` เรียก `main()` ในกรณีที่ทุกชั้นส่งไม่ได้ ซึ่งโค้ดใหม่จะเขียนลงคิว และเทสต์นั้นย้ายแค่ `LEDGER` กับ `DEDUP_STATE` ไม่รู้จัก `OUTBOX`
3. **ทำไมเทสต์ไม่รู้จัก `OUTBOX`?** — เพราะ `OUTBOX` เป็นไฟล์ผลข้างเคียงใหม่ที่เพิ่งเพิ่ม เทสต์เดิมเขียนก่อนมันจะมี
4. **ทำไมการเพิ่มไฟล์ผลข้างเคียงใหม่ถึงไม่ทำให้เทสต์เดิมปลอดภัยไปด้วย?** — เพราะกำหนดที่อยู่เป็นค่าคงที่แยกอิสระ แทนที่จะผูกกับ `LEDGER` ที่ทุกเทสต์ย้ายอยู่แล้ว
5. **ทำไมไม่เช็คก่อนรันชุดเทสต์?** — ไม่ได้ไล่ว่ามีเทสต์ไหน import โมดูลนี้แล้วเรียก `main()` บ้าง ก่อนรันชุดเต็มบนเครื่องที่มี heartbeat ทำงานจริงทุก 5 นาที — root cause: ไฟล์ผลข้างเคียงใหม่ของโมดูลที่มีเทสต์อยู่แล้ว ไม่ได้ผูกกับกลไกย้ายไฟล์ที่เทสต์เดิมใช้

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ไม่มีชั้นไหนแยก "ไฟล์ของเทสต์" กับ "ไฟล์จริง" ในโมดูลนี้ เทสต์ dedup ใช้วิธีเขียนทับค่าคงที่ทีละตัว ซึ่งปลอดภัยเฉพาะกับค่าคงที่ที่มันรู้จัก

## 5. แนวทางการแก้ไข (Fix)

- `sfd/fail_notify.py`: `OUTBOX = None` + `_outbox_path()` คืน `os.path.join(os.path.dirname(LEDGER), "dm_outbox.jsonl")` เมื่อไม่ได้กำหนด — ใครย้าย `LEDGER` คิวย้ายตาม
- `sfd/fail_notify.py`: ย้ายการตัดสินบันทึก dedup ไปก่อนเติม `+queued` ให้กฎ "stamp ได้จากการส่งถึงจริง" เหมือนเดิม (`test_fail_notify_dedup` กลับมา 34/34)
- `tests/test_fail_notify_outbox.py`: `OutboxFollowsLedgerTest` ตรึงว่าย้ายแค่ `LEDGER` แล้วคิวต้องอยู่ในที่ชั่วคราว

**ยืนยันแล้วด้วย:**
