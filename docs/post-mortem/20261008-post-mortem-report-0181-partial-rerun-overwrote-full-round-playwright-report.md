## สรุปสั้น (Executive Summary)

ระหว่าง triage รอบ smoke dev v2026.10.08.1 ผมรันเคส creator 15 เคสซ้ำโดยไม่ใส่ `--reporter=list` ตัวรันจึงใช้ reporter ของ config ซึ่งเขียน HTML ลง `playwright-report/` ที่เดียวกับรอบเต็ม รายงานของรอบเต็ม 12:19–12:25 ถูกทับ เมื่อเจ้าของงานสั่งส่งโนติแบบผ่านอย่างเดียว ไฟล์แนบจึงไม่มีให้ใช้ ต้องรันทั้งชุดใหม่ 13:23–13:32 ก่อนส่ง · แก้ที่ skill แล้ว: รันบางส่วนต้องใส่ `--reporter=list` ทุกครั้ง และรอบเต็มต้องคัดลอก report เข้าโฟลเดอร์รอบทันทีที่จบ

## 1. ปัญหา (Problem Statement)

- `playwright.config.ts:22` ตั้ง `['html', { open: 'never', outputFolder: 'playwright-report' }]` ทุกการรันที่ไม่ override reporter จะเขียนทับโฟลเดอร์นี้
- รอบเต็มจบ 12:25:59 (`run2/time.txt`) แต่ `playwright-report/index.html` ใน worktree มี mtime 12:29:15 ขนาด 548486 B และมีแค่ 15 เคส (`report.json` stats total 15) — มาจากการรันซ้ำกลุ่ม creator ตอน 12:28
- skill ข้อ Stage 3 เขียนว่า "Do not pass `--reporter=`" (สำหรับรอบเต็ม) และ "rerun ... into a separate `--output` dir so the first run's artefacts survive" — `--output` แยกแค่ artifacts ไม่ได้แยก HTML report

**สิ่งที่ควรจะเป็น:** ไฟล์แนบต้องเป็น Playwright report ตัวจริงของรอบที่อ้างถึงตัวเลข (กฎเจ้าของงาน 23/Sep · skill Stage 7.5 ข้อ mtime)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมไฟล์แนบของรอบเต็มหาย?** — เพราะการรันซ้ำ 15 เคสเขียน `playwright-report/index.html` ทับ
2. **ทำไมการรันซ้ำเขียนทับ?** — เพราะไม่ได้ใส่ `--reporter=list` จึงใช้ HTML reporter จาก config ที่ปักโฟลเดอร์ไว้ตายตัว
3. **ทำไมไม่ใส่?** — เพราะ skill บอกแค่ "ห้ามใส่ `--reporter=`" สำหรับรอบเต็ม และบอกว่าใช้ `--output` แยกก็พอ ผมจึงเข้าใจว่า artefacts รอบแรกปลอดภัยแล้ว
4. **ทำไม skill ถึงพาเข้าใจผิดได้?** — เพราะ `--output` คุมแค่โฟลเดอร์ test-results/trace ไม่ได้คุม HTML reporter ที่ config ตั้ง `outputFolder` ไว้ แต่ skill เขียนเหมือนว่าคุ้มครองทุกอย่าง
5. **ทำไมไม่มีอะไรกันไว้?** — เพราะไม่มีขั้นตอนเก็บ report ของรอบเต็มออกจากโฟลเดอร์ที่ใช้ร่วมกันทันทีที่จบ สิ่งส่งมอบจึงอยู่ในที่ที่การรันครั้งต่อไปขนาดเท่าไหร่ก็ทับได้

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** `passed_report.py` มีด่าน mtime ที่ปฏิเสธ report ที่เก่ากว่า run.json แต่ด่านนี้จับได้แค่ "เก่ากว่า" ไม่ใช่ "ใหม่กว่าแต่เป็นของรอบอื่น" · ผมจับได้เองจากการตรวจ mtime ตามกฎ 23/Sep ก่อนลงมือตัดเคส
