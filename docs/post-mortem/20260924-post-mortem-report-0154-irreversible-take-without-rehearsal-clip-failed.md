## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมคลิปใช้ไม่ได้?** — เพราะภาพค้าง 85% · fps 9.04 · holds 36% (สาเหตุเชิงเทคนิคกำลังสืบใน `laneT69/clip_stutter_0924.md`)
2. **ทำไมไม่รู้ก่อนกดลบ?** — เพราะไม่ได้อัดซ้อม flow นี้เลย มีแค่ dry ที่ไม่บันทึกวิดีโอ
3. **ทำไมไม่ซ้อม?** — เพราะเชื่อว่าการแก้ที่ผ่านใน NDLP_TC_005 (rafGlide + held) จะใช้ได้กับ flow นี้ด้วย ทั้งที่ flow นี้บันทึกจากเบราว์เซอร์คนละแบบ (headed ผ่าน CDP) และมีหน้า NDLP หลายหน้า
4. **ทำไมสคริปต์ไม่หยุดเอง?** — เพราะไม่มีด่านตรวจคุณภาพคลิปก่อนคลิกที่ย้อนไม่ได้ (held share ถูกวัดแต่ไม่เคยใช้เป็นเงื่อนไขหยุด)
5. **root cause:** ไม่มีขั้นบังคับ "ซ้อมแล้วผ่าน verify_video ก่อนกดคลิกที่ย้อนไม่ได้" ในสคริปต์อัดของเคสที่เขียนข้อมูล

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ด่านเขียนตรวจแค่ "เขียนอะไร" ไม่ได้ตรวจ "คลิปจะใช้ได้ไหม" · มติเจ้าของงาน "อัดจริงเลย" ยกเว้นเฉพาะ LOADMAX ไม่ได้ยกเว้นการซ้อม
