## สรุปสั้น (Executive Summary)

เพื่อยืนยันบรรทัดโค้ดที่ agent อ้าง (`useMediaPreviewHandler.ts`) ผมรัน `find / -name …` ค้นทั้งดิสก์ ทั้งที่รู้อยู่แล้วว่าโค้ดอยู่ใน monorepo ที่ commit ระบุไว้
คำสั่งไม่จบใน 120 วินาทีจึงถูกย้ายไปรันเบื้องหลัง และรันต่อราว 4 นาทีระหว่างที่ load average ของเครื่องอยู่ที่ 88–127 ผมหยุดด้วย pid (exit 144) · ไม่มีการเขียนข้อมูล
ต่อมาหาไฟล์ได้ภายในไม่กี่วินาทีด้วย `git ls-tree` บน commit ที่ agent ระบุ

## 1. ปัญหา (Problem Statement)

- คำสั่ง: `find / -name useMediaPreviewHandler.ts -not -path '*/node_modules/*'` (ต่อท้ายคำสั่ง investigation-guard)
- ผล: timeout 120 วินาที → background task → หยุดด้วย `kill` pid 64018/64026 · task แจ้ง exit 144
- ช่วงเดียวกัน `sysctl vm.loadavg` = `126.50 88.24 67.98` · `ps` เห็น `bfs` 38% CPU · เลน P009 ต้องรอ rec_lock เพราะโหลดสูง (โหลดหลักมาจาก CI runner และ Bitdefender ที่ไม่ใช่ของเรา)

**สิ่งที่ควรจะเป็น:** ค้นเฉพาะใน repo ที่รู้ตำแหน่ง (`git -C <monorepo> ls-tree -r --name-only <commit> | grep <name>`) ซึ่งเร็วและไม่แตะดิสก์ทั้งเครื่อง

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมเครื่องโหลดเพิ่ม?** — เพราะ `find /` ไล่ทั้งดิสก์
2. **ทำไมใช้ `find /`?** — เพราะไม่รู้ว่า repo school-web อยู่ path ไหน จึงเลือกค้นกว้างที่สุด
3. **ทำไมไม่ใช้ข้อมูลที่มี?** — agent ระบุ commit hash มาแล้ว ซึ่งหาได้ด้วย `git cat-file` ใน repo ที่มีอยู่ แต่ผมไม่ได้เริ่มจากข้อมูลนั้น
4. **ทำไมไม่คำนึงถึงโหลด?** — ไม่ได้เช็คโหลดก่อนรันคำสั่งหนัก ทั้งที่รู้ว่าเลนอื่นกำลังรอคิวอัดที่ตัดสินด้วยโหลด
5. **root cause:** ไม่มีนิสัย/ด่านที่ห้ามค้นทั้งดิสก์ และให้เริ่มค้นจาก repo/commit ที่รู้ก่อน

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ไม่มี hook ใดตรวจคำสั่ง `find /` · กฎข้อ 15 (ประหยัด) เป็นข้อความ
