## สรุปสั้น (Executive Summary)

เคส R130 ต้องให้เจ้าของงานพิมพ์รหัสผ่านในหน้าต่างเบราว์เซอร์ที่สคริปต์เปิด ผมบอกเจ้าของงาน 3 ครั้งว่า "ฟอร์มล็อกอินขึ้นจริง รอใส่รหัส"
ทั้งที่ครั้งแรกฟอร์มไม่เคยขึ้น (สคริปต์พิมพ์ข้อความรอโดยไม่ตรวจ) และอีก 2 ครั้งฟอร์มอยู่ในหน้าเว็บจริงแต่อยู่นอกส่วนที่มองเห็นของหน้าต่าง
(ตั้งหน้าเว็บกว้าง 1920 px บนหน้าต่างที่จอให้แค่ 1404 px) ส่วนอีกรอบหน้าต่างอยู่หลัง Chrome ของเจ้าของงาน
หลักฐานทุกชิ้นที่ผมใช้ยืนยันมาจากตัว DOM ไม่มีชิ้นไหนวัดจอที่เจ้าของงานเห็น

## 1. ปัญหา (Problem Statement)

**สิ่งที่เกิดขึ้น:** เจ้าของงานตอบ "มันเด้งไวและหายไปเลย" · "ไม่มีหน้า login นะ" · "ขึ้นจริงบ้าไร ไม่มีเลย" ต่อข้อความของผมที่ยืนยันว่าหน้าต่างพร้อม
**สิ่งที่ควรจะเป็น:** ก่อนบอกคนให้ลงมือในหน้าต่าง ต้องยืนยันจากฝั่งที่คนเห็น — หน้าต่างอยู่หน้าสุด ขนาดหน้าต่างรองรับ viewport และฟอร์มอยู่ในกรอบที่มองเห็น (กฎที่ #0018 เขียนไว้แล้ว)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. ทำไมเจ้าของงานไม่เห็นฟอร์ม? — รอบ 2 ฟอร์มไม่เคยเปิด · รอบ 4 ฟอร์มอยู่นอกกรอบที่มองเห็นและหน้าต่างอยู่ด้านหลัง
2. ทำไมผมบอกว่าพร้อม? — เชื่อข้อความ `WAITING…` และ `FORM READY` ที่สคริปต์พิมพ์
3. ทำไมข้อความนั้นผิด? — รอบ 2 สคริปต์ (`laneL/r130.js:20-21`) พิมพ์ข้อความรอต่อจาก `EMAIL_FIELD_NOT_FOUND` · รอบ 4 `FORM READY` วัดแค่ว่า element มองเห็นได้ใน DOM ของ viewport ที่ตั้งเอง
4. ทำไมไม่วัดจอจริง? — ไม่มีขั้นตอนไหนอ่านขนาดหน้าต่าง/ลำดับหน้าต่างของ OS ก่อนบอกคน ทั้งที่ `osascript` อ่านได้ในคำสั่งเดียว
5. ทำไมไม่มีขั้นตอนนั้น? — ผมถือว่า "headed + DOM บอกว่ามองเห็น" = "คนเห็น" ซึ่งเป็นคลาสเดียวกับ #0018 (ผลของฝั่งเขียนไม่ใช่สิ่งที่คนอ่านเห็น)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** กฎของ #0018 เป็นข้อความใน `CLAUDE.md` ไม่มีเครื่องมือบังคับ และเขียนถึง "บอร์ด/หน้าเว็บที่เผยแพร่" จึงไม่ถูกหยิบมาใช้กับหน้าต่างเบราว์เซอร์บนเครื่อง · `session_capture.js` ที่ใช้ได้ผลก่อนหน้าไม่ได้ตั้ง viewport ตายตัว ความต่างนี้ไม่ถูกเทียบ

## 4. ผลกระทบ (Impact)

- เจ้าของงานเสียเวลาประมาณ 12 นาที และต้องทักซ้ำ 4 ข้อความ
- ไม่มีการเขียนข้อมูล ไม่มีรหัสผ่านหลุด (สคริปต์ไม่เคยพิมพ์รหัส)

## 5. แนวทางการแก้ไข (Fix)

- สคริปต์ใหม่ `r130v2.js` (นอก repo): หยุดทันทีถ้าไม่เจอฟอร์ม · ไม่คลิกซ้ำถ้าแถบเปิดอยู่แล้ว · ตรวจ bounding box ของ iframe ล็อกอินว่าอยู่ใน viewport · viewport 1440×810 ให้พอดีจอ 1470×956 · ทดสอบแบบ headless ก่อนเปิดจริงทุกครั้ง
- หลังเปิดจริง ดึงหน้าต่างขึ้นหน้าสุดด้วย `osascript` และอ่านตำแหน่ง/ขนาดหน้าต่างกลับมา

**ยืนยันแล้วด้วย:** `r130v2.run.log` 07:50:54 `SIGNED IN return URL … sameAsOrig true` · เฟรมคลิปที่ 20 วินาทีเห็นแถบล็อกอินพร้อมอีเมล

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

- ก่อนบอกคนให้ลงมือในหน้าต่างที่สคริปต์เปิด ต้องมีหลักฐานจากฝั่ง OS ครบ 3 ข้อ: หน้าต่าง frontmost · ขนาดหน้าต่าง ≥ viewport · element เป้าหมายอยู่ในกรอบ
- ข้อความ "รอคุณ…" ของสคริปต์พิมพ์ได้ต่อเมื่อเงื่อนไขผ่านแล้วเท่านั้น ไม่ผ่าน = จบด้วยรหัสไม่เป็นศูนย์
- ห้ามเปิดหน้าต่างให้คนซ้อนกันหลายรอบ และห้ามบอกให้ปิดหน้าต่าง "เดิม" ในขณะที่มีหน้าต่างใหม่กำลังจะขึ้น

**กฎที่เพิ่มจากเหตุนี้:** ข้อความใน `CLAUDE.md` หัวข้อ Post-mortems (Report #0074) · เครื่องมือบังคับระดับ OS ยังไม่ได้สร้าง — อยู่ใน Action Items

## 7. การตรวจจับปัญหา (Detection)

เจ้าของงานเป็นผู้จับได้ทุกครั้ง ภาพหน้าจอที่เจ้าของงานส่งมา (เมนูบนถูกตัดที่ "การเรียนรู้แ…") คือหลักฐานที่ชี้สาเหตุเรื่อง viewport

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- สคริปต์ไม่เคยพิมพ์รหัสผ่าน · หยุดเลนแล้วสืบด้วย headless ก่อนเปิดหน้าต่างรอบถัดไป

### สิ่งที่ต้องปรับปรุง
- "DOM บอกว่ามองเห็น" ไม่ใช่ "คนเห็น" — วัดจากฝั่งคนเสมอ
