## สรุปสั้น (Executive Summary)

ด่าน pre-commit นับหนี้ด้วย `awk` ที่เขียนแทรกไว้ในตัว hook แล้วส่งผลเข้าเงื่อนไข `[ "$OPEN_COUNT" -gt 0 ]` ตรงๆ
เมื่อไฟล์บัญชีหนี้อ่านไม่ได้ `awk` พิมพ์ค่าว่างและจบด้วยรหัส 2 ทำให้เงื่อนไขกลายเป็น `[ "" -gt 0 ]` ซึ่งคืนเท็จ
**โดยไม่พ่นข้อความใดๆ** ด่านจึงถูกข้ามทั้งบล็อกและคอมมิตผ่าน ทั้งที่มีหนี้ค้างอยู่

อีกครึ่งหนึ่งคือเกณฑ์ `NF < 7` ที่ผิดตัวเลข วัดจริงแล้วแถว 6 คอลัมน์ที่ถูกต้องได้ `NF=8` ส่วนแถวที่ถูกตัดเหลือ 5 คอลัมน์
ได้ `NF=7` ซึ่งผ่านด่าน แล้ว `$6` ไปชี้คอลัมน์อื่น แถวที่เขียนว่า `OPEN` จึงไม่ถูกนับ

ชั้น Node (`check.js`) ปฏิเสธทั้งสองกรณีถูกต้องมาตลอด — สอง runtime ถือกฎชุดเดียวกันแล้วให้คำตอบต่างกัน
และตัวที่มีอำนาจบล็อกคือตัวที่ตอบผิด แก้โดยย้ายการตัดสินไปอยู่ที่ `check.js --gate` ที่เดียว
ให้ hook เป็นผู้เรียกและรายงานผล ส่วนทางสำรองเมื่อ Node ใช้ไม่ได้คือสคริปต์ที่ **ปฏิเสธแทนการเดา**

## 1. ปัญหา (Problem Statement)

- บัญชีหนี้อ่านไม่ได้ (สิทธิ์ปิด) + มีแถว `OPEN` + stage ไฟล์อื่น → pre-commit **จบด้วยรหัส 0 ปล่อยผ่าน**
- ตารางบัญชีหนี้ถูกตัดคอลัมน์ + มีแถว `OPEN` → **จบด้วยรหัส 0 ปล่อยผ่าน** เช่นกัน
- ตัวเตือน (`postmortem-debt.sh`) ในสถานการณ์แรก **พิมพ์ออกมา 0 ไบต์** เงียบสนิท
- ชั้น Node บนอินพุตชุดเดียวกันตอบว่า `CANNOT RUN … EACCES` (รหัส 2) และ `expected 6 columns, found 5` (รหัส 1)

**สิ่งที่ควรจะเป็น:** "อ่านบัญชีหนี้ไม่ได้" กับ "ไม่มีหนี้" เป็นคำตอบคนละอัน อันแรกต้องบล็อกและบอกเหตุผล
ตามหลัก fail-closed ที่ตัว hook เดียวกันนี้ใช้กับ secret guard อยู่แล้ว (`ตาข่ายกันพลาด ... a blocked commit is the cheap outcome`)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

ตัวแปรที่ถือ "จำนวนหนี้" ไม่เคยมีสถานะที่แปลว่า **ยังไม่รู้** มีแค่ตัวเลขกับค่าว่าง และค่าว่างเดินเข้าไปใน
การเปรียบเทียบเชิงตัวเลขซึ่งตอบเท็จโดยไม่ร้อง ผลคือ "อ่านไม่ได้" ถูกยุบรวมกับ "ไม่มี" ตั้งแต่ระดับชนิดข้อมูล
ไม่ใช่ระดับตรรกะ — ไม่ว่าจะเขียนเงื่อนไขรอบๆ ดีแค่ไหนก็ปิดไม่ได้

### 5 Whys

1. **ทำไมคอมมิตผ่านทั้งที่มีหนี้?** — เพราะเงื่อนไขบล็อกไม่เข้า
2. **ทำไมไม่เข้า?** — เพราะ `[ "" -gt 0 ]` คืนเท็จ และไม่พิมพ์ error ออกมาเลย
3. **ทำไมค่าถึงว่าง?** — เพราะ `awk` บนไฟล์ที่อ่านไม่ได้จบด้วยรหัส 2 และไม่ทันเข้าบล็อก `END` ที่จะพิมพ์ตัวเลข
4. **ทำไมรหัส 2 ของ `awk` ถึงไม่มีใครดู?** — เพราะผลถูกเก็บด้วย command substitution แล้วส่งเข้าเงื่อนไขทันที
   ไม่มีขั้นตอนไหนถามว่า "อ่านสำเร็จไหม" มีแต่ "ค่ามากกว่าศูนย์ไหม"
5. **ทำไมถึงออกแบบมาแบบนั้น?** — **root cause:** ตั้งใจให้ shell ถือกฎชุดเดียวกับ Node ด้วยเหตุผลว่า
   "สองชั้นที่ใช้ runtime เดียวกันล้มพร้อมกัน" ทั้งที่ `CLAUDE.md` ของ repo เขียนกฎตรงข้ามไว้แล้วว่า
   **การตัดสินต้องอยู่ที่ไฟล์เดียว ชั้น bash พิมพ์ตัวกฎอย่างเดียว เพราะสอง runtime ที่ถือกฎชุดเดียวกัน
   คือสองคำตอบที่รอวันไม่ตรงกัน** — เหตุผลของผมถูกในแง่ความเป็นอิสระ แต่แลกมาด้วยการทำสำเนากฎ
   ซึ่งเป็นความเสี่ยงที่ repo นี้เคยชั่งแล้วและตัดสินไปแล้ว

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** เทส 32 ข้อป้อนข้อมูลสมมติเข้าโมดูลกฎ ไม่มีข้อไหนรันไฟล์ shell จริง ·
CI รันเทสชุดเดียวกัน จึงมีจุดบอดเดียวกัน · และรายงาน #0002 เพิ่งปิดคลาสนี้ไปเมื่อวันก่อน **แต่ปิดเฉพาะไฟล์ที่เกิดเหตุ
ไม่ได้ไล่หาว่าไฟล์อื่นมีอาการเดียวกันไหม** — นี่คือเหตุผลที่มันกลับมา

## 5. แนวทางการแก้ไข (Fix)

- **การตัดสินย้ายไปอยู่ที่เดียว** — เพิ่มโหมด `--gate` ใน `tools/postmortem-guard/check.js` คืน
  `0` ไม่มีหนี้ · `1` มีหนี้ · `2` ตัดสินไม่ได้ (บัญชีหนี้ไม่ผ่านการตรวจ)
- **`scripts/hooks/pre-commit` เลิก parse เอง** เรียก `--gate` แล้วรายงานผล · รหัส 2 = พิมพ์เหตุผลแล้วตกไปทางสำรอง
- **ทางสำรองเป็น fail-closed ในตัวเอง** — `tools/postmortem-guard/ledger_open_count.sh` รับ path เป็น **อาร์กิวเมนต์**
  (ไม่ใช่ตัวแปรสภาพแวดล้อม ซึ่งจะกลายเป็นช่องบายพาส) ตรวจว่าอ่านได้จริง หาคอลัมน์สถานะ **จากชื่อในหัวตาราง**
  ปฏิเสธเมื่อจำนวนคอลัมน์ไม่ตรงหัว และพิมพ์ได้แค่ 2 แบบคือเลขจำนวนเต็มล้วน หรือ `REFUSE:<เหตุผล>` พร้อมรหัส 2
- **`.claude/hooks/postmortem-debt.sh`** ตรวจ `-r` ไม่ใช่แค่ `-f` และดึงรายละเอียดจาก `check.js --debt`
- **เทสใหม่ 16 ข้อ** `tools/postmortem-guard/hook_gate.test.js` รันสคริปต์จริงกับไฟล์จริงบนดิสก์

**ยืนยันแล้วด้วย:** ทั้ง 3 เคสที่เคยหลุด (หนี้เปิดปกติ · บัญชีหนี้อ่านไม่ได้ · ตารางถูกตัดคอลัมน์) ตอนนี้ **บล็อกทั้งหมด รหัส 1**
พร้อมข้อความบอกเหตุผล · `--gate` คืน 1 / 2 ตรงตามที่ออกแบบ · ตัวเตือนพิมพ์คำเตือนดังแทนที่จะเงียบ · เทสทั้ง 16 ข้อผ่าน

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- วัดที่ขอบเขตของแต่ละชั้นก่อนสรุป ทำให้จับได้ว่าสมมติฐานแรก (`awk` พิมพ์ `0`) **ผิด** ของจริงคือค่าว่าง
- รายงานเจ้าของงานแล้วถามก่อนลงมือ ตามลำดับที่กฎกำหนด ไม่รีบแก้
- ไม่แตะแถวบัญชีหนี้ของเซสชันอื่นที่บังเอิญใช้เลขซ้ำกัน เลี่ยงเลขของตัวเองแทน

### สิ่งที่ต้องปรับปรุง
- เหตุผลออกแบบที่ฟังดูดี ("แยก runtime กันล้มพร้อมกัน") ต้องเทียบกับกฎที่ repo ตัดสินไปแล้วก่อนเสมอ
  ไม่ใช่ตั้งขึ้นใหม่ในหัวแล้วเขียนลงคอมเมนต์ให้ดูเป็นเจตนา
- ปิดบั๊กแล้วต้องถามว่า "คลาสนี้มีที่อื่นอีกไหม" — #0002 ปิดไฟล์เดียว อีกวันเดียวคลาสเดิมกลับมาในไฟล์ข้างๆ
- ในเชลล์ ค่าว่างกับศูนย์แยกกันไม่ออกด้วยการเปรียบเทียบเชิงตัวเลข ต้องแยกด้วยรหัสจบหรือรูปแบบข้อความเสมอ
