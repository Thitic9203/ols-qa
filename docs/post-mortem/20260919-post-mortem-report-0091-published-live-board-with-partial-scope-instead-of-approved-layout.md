## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

จุดตัดสินใจที่ผิดมี 2 จุด: (1) ตอนเขียน brief เธรดหลักเลือกแหล่งตัวเลขเองจากไฟล์ที่อยู่ใกล้งานของรอบ (`short.json` ของ track Integration) แทนตัวนับที่อนุมัติแล้ว (`make_board.py`) — ตอนนั้นดูถูกเพราะรอบนี้ทำงานกับ Integration อยู่ และ `short.json` เป็นไฟล์คำตัดสินล่าสุด (2) ตอนเจอยอด 146 เธรดหลักแก้ "ตัวเลข" ให้ครบในขอบเขตเดิม แทนที่จะตั้งคำถามกับ "ขอบเขต" — การแก้ที่ทำให้ตัวเลขดูถูกต้องขึ้น (148 ตรงกับจำนวนเคส Integration) ทำให้มั่นใจผิดว่าช่องสรุปถูกแล้ว

### 5 Whys

1. **ทำไมบอร์ดฉบับที่ 21 แสดงแค่ Integration 148 เคส?** — เพราะข้อมูลบอร์ดถูกสร้างจาก `short.json` + `all.json` ซึ่งเป็นคำตัดสินของ track Integration อย่างเดียว ไม่มี System / Unit
2. **ทำไมข้อมูลบอร์ดสร้างจากไฟล์ของ Integration อย่างเดียว?** — เพราะ brief ที่เธรดหลักเขียนให้ subagent ระบุแหล่งตัวเลขเป็น `short.json` และ subagent ทำตาม brief
3. **ทำไม brief ถึงระบุแหล่งนั้น แทนตัวนับที่อนุมัติ?** — เพราะไม่มีกฎหรือเอกสารใดบอกว่าตัวเลขบนบอร์ดต้องมาจาก `make_board.py` · memory ฟอร์แมตบอร์ดแช่แข็ง "โครงหน้า" (หัวข้อ · เลน · Blockers/Corrections) แต่ไม่ได้ระบุว่าช่องสรุปต้องเป็นยอดรวม + แยก track และไม่ได้ชี้ตัวนับ (`grep -c -iE '875|track|make_board'` ในไฟล์ memory = 0)
4. **ทำไมหลุดถึง publish แม้เธรดหลักจะแก้ยอดและอ่านเวอร์ชันที่ live ไปแล้ว?** — เพราะการแก้ยอด 146→148 ตรวจแค่ "ครบในขอบเขตที่เลือก" และการอ่านเวอร์ชันที่ live ทำเพื่อผ่านเงื่อนไขของเครื่องมือ publish ไม่ได้ใช้เทียบช่องสรุปกับของตัวเอง · และไม่มีด่านอัตโนมัติใดเทียบยอดช่องสรุปกับจำนวนเคสที่คาดต่อ track
5. **ทำไมไม่มีด่านนั้น?** — root cause: ตัวเลขบนบอร์ดสดไม่มี "แหล่งเดียวที่บังคับใช้" — ด่าน `EXPECTED_TOTALS` อยู่ใน `make_board.py` ซึ่งเป็นตัวเลือก ไม่ใช่ทางบังคับ ส่วน `build_board.js`/`check_theme.js` ที่ทุกบอร์ดต้องผ่านรับตัวเลขอะไรก็ได้ · มาตรการ P3 ของ #0066 (ด่านตรวจเนื้อหาบอร์ดก่อน publish) ยังค้าง `Open` จึงไม่มีชั้นใดปฏิเสธบอร์ดที่ขอบเขตผิด — ต้องปิดทั้งคลาสด้วยด่านที่ทุกบอร์ดต้องผ่าน และตรวจ "ยอดตรงกับจำนวนคาด" ไม่ใช่แค่ "ไม่ว่าง"

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- `make_board.py` `EXPECTED_TOTALS` (ปฏิเสธเมื่อนับไม่ตรง) — ไม่ได้ถูกเรียกเลยในรอบนี้ ด่านที่อยู่ในเครื่องมือที่ไม่ได้ใช้ = ไม่มีด่าน
- `build_board.js` — หลัง #0066 เตือนเมื่อ `tileTotal` ไม่มี tiles แต่ฉบับที่ 21 มี tiles ครบรูป แค่ขอบเขตผิด จึงไม่มีคำเตือน
- `check_theme.js` — ด่านธีม ไม่อ่านเนื้อหาช่องสรุป (0 การอ้าง `tileRows`/`tileTotal`)
- เงื่อนไข "ต้องอ่านเวอร์ชันที่ live ก่อน publish" ของเครื่องมือ publish — บังคับให้อ่าน แต่ไม่บังคับให้เทียบ เธรดหลักเห็นโครงเดิมแล้วก็ยัง publish
- memory `feedback_live-board-format-frozen` — ไม่ได้ระบุเนื้อหาช่องสรุปและแหล่งตัวเลข

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- การแก้ไม่ได้พิมพ์ตัวเลขเอง — `add_track_tiles.py` เรียกฟังก์ชันนับและด่าน `EXPECTED_TOTALS` ของ `make_board.py` โดยตรง จึงได้ตัวเลขชุดเดียวกับฟอร์แมตที่อนุมัติ
- ไม่ได้ออกแบบฟอร์แมตใหม่ในฉบับที่ 22 — กลับไปใช้โครงช่องสรุปเดิม

### สิ่งที่ต้องปรับปรุง
- ตอนเจอยอดไม่ครบ (146) แก้ "ตัวเลข" แทนที่จะถาม "ขอบเขต" — ยอดที่ผิดคือสัญญาณให้ตรวจแหล่ง ไม่ใช่แค่เติมให้ครบ
- อ่านเวอร์ชันที่ live เพื่อผ่านเงื่อนไขเครื่องมือ ไม่ใช่เพื่อเทียบ — เห็นโครง 875 + 3 แถวแล้วยังไม่เทียบ
- brief ที่ระบุแหล่งข้อมูลให้ subagent ต้องมาจากตัวนับที่อนุมัติ ไม่ใช่ไฟล์ที่อยู่ใกล้งานของรอบ
