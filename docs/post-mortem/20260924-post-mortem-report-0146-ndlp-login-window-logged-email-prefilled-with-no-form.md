## สรุปสั้น (Executive Summary)

เจ้าของงานอนุมัติให้เตรียมข้อมูล NDLP ของ st9020 สำหรับ Authen_TC_006 เธรดหลักจ่ายงานให้ subagent เปิดหน้าต่าง NDLP แบบ headed และ "prefill ONLY the email" subagent บันทึกบรรทัด `OWNER: log in as st9020 on NDLP` พร้อมโน้ต "email prefilled" ก่อนจะกรอกจริง บรรทัดถัดมาแสดงว่าหน้าเด้งไปหน้าแรก NDLP (`/`) ซึ่งไม่มีฟอร์ม ช่องอีเมลจึงไม่เคยถูกกรอก แต่ไม่มีขั้นใดอ่านค่ากลับ เจ้าของงานเห็นหน้าต่างว่างและต้องทักซ้ำ เธรดหลักจึงเขียน `ndlp_owner_window.js` ขึ้นใหม่ ตัวนี้เปิดหน้า sign-in หาช่องอีเมลในทุกเฟรม กรอก แล้วอ่านค่ากลับ ผลคือ `EMAIL_READY st9***` เวลา 04:58:39Z จากนั้นเจ้าของงานล็อกอินได้

## 1. ปัญหา (Problem Statement)

- **สิ่งที่ควรเกิด:** หน้าต่างอยู่ที่ฟอร์มเข้าสู่ระบบและช่องอีเมลมีค่าแล้ว ก่อนบอกเจ้าของงานว่าพร้อม
- **สิ่งที่เกิดจริง:** หน้าจบที่หน้าแรก NDLP ไม่มีฟอร์ม และช่องอีเมลว่าง แต่ log เขียนว่า "email prefilled"
- **ขอบเขต:** 1 หน้าต่าง ไม่มีการเขียนข้อมูล และไม่มีการพิมพ์รหัสผ่าน

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมช่องอีเมลว่าง?** — เพราะหน้าที่เปิดคือ `/profile` ซึ่ง redirect ไปหน้าแรกที่ไม่มีฟอร์ม โค้ดกรอกจึงไม่เจอช่อง
2. **ทำไม log บอกว่ากรอกแล้ว?** — เพราะโน้ต "email prefilled" ถูกเขียนลงบรรทัดประกาศก่อนการกรอก ไม่ได้ผูกกับผลการกรอก
3. **ทำไมไม่มีใครจับได้ก่อนเจ้าของงาน?** — เพราะไม่มีขั้นอ่านค่าช่องกลับ ทั้งใน `waitOwnerLogin` (ออกแบบให้ไม่พิมพ์อะไรเลย) และในบรีฟ
4. **ทำไมบรีฟไม่สั่งให้อ่านกลับ?** — เธรดหลักเขียนแค่ "prefill ONLY the email" โดยไม่กำหนดหลักฐาน ทั้งที่ #0074 สอนแล้วว่า "พร้อม" ต้องพิสูจน์จากสิ่งที่อยู่บนจอ
5. **ทำไมผิดซ้ำ?** — (root cause) มาตรการของ #0074 เป็นข้อความใน CLAUDE.md และเครื่องมือระดับ OS ที่ยังไม่ได้สร้าง ไม่มีชั้นเครื่องที่ขอบการจ่ายงาน หรือในตัวสคริปต์ ที่บังคับว่า "ใส่อีเมลแล้ว" ต้องมาจากค่าที่อ่านกลับ

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- #0074 — กฎเป็นตัวหนังสือ Action Item ด้านเครื่องมือยัง Open
- `agent-dispatch-guard` — ก่อนแก้มี 5 checks ไม่มีเรื่องการกรอกอีเมล · ตรวจบรีฟจริงของเหตุนี้หลังแก้ = BLOCK `EMAIL_PREFILL_WITHOUT_READBACK`
- `relogin_t69.js` เดิม — พิมพ์ "email filled in frame" หลัง `fill()` โดยไม่อ่านค่ากลับ

## 4. ผลกระทบ (Impact)

- เจ้าของงานเสียเวลาและต้องทักซ้ำเรื่องที่สั่งไว้แล้ว
- ไม่มีการเขียนข้อมูลหรือพิมพ์รหัสผ่านจากเหตุนี้

## 5. แนวทางการแก้ไข (Fix)

- `ndlp_owner_window.js` (ใหม่): เปิด `/sign-in` → หาช่องอีเมลทุกเฟรม → กรอก → `inputValue()` ต้องตรง → จึงพิมพ์ `EMAIL_READY` · เปิด CDP 9333 ให้เลนใช้เบราว์เซอร์เดียวกันแทนการโหลด session
- `relogin_t69.js`: อ่านค่ากลับหลัง `fill()` · ไม่ตรง = `EMAIL_READBACK_MISMATCH` และลองใหม่ · ตรง = `EMAIL_READY (readback ok)`

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

1. **check 6 ใน `tools/agent-dispatch-guard/dispatch_rules.js`** — บรีฟที่มีคำสั่งกรอกอีเมล แต่ไม่สั่งอ่านค่ากลับ (read back … input/value · `inputValue(` · `EMAIL_READY`) = BLOCK การอ้างชื่อสคริปต์ช่วยที่อื่นในบรีฟไม่นับเป็นหลักฐาน
2. **เทสต์ 3 ข้อ:** ถ้อยคำเหตุการณ์ = BLOCK · รูปบรีฟจริง (มี relogin_t69.js ในอีกขั้น) = ยัง BLOCK · บรีฟที่สั่ง inputValue + EMAIL_READY = ผ่าน · รวม 35/35 · และตรวจบรีฟจริงทั้งฉบับ (3825 ตัวอักษร) ได้ BLOCK
3. **กฎการรายงาน:** บอกเจ้าของงานว่า "ใส่อีเมลแล้ว" ได้เมื่อมีบรรทัด `EMAIL_READY` ใน log เท่านั้น
