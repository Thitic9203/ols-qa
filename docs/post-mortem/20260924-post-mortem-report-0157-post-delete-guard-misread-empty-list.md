## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมคลิปขาดช่วง OLS หลังลบ?** — เพราะสคริปต์หยุดที่ด่านตรวจรายการหลังลบ
2. **ทำไมด่านหยุด?** — เพราะไม่พบ GET รายการที่ "มีสมาชิก" จึงตัดสินว่ารายการยังไม่โหลด
3. **ทำไมไม่พบ?** — `scanNdlpJson` ข้าม array ว่าง และ tc9020 มีสื่อชิ้นเดียว หลังลบรายการจึงว่าง
4. **ทำไมการซ้อมไม่จับ?** — การซ้อมกดยกเลิกแทนยืนยันลบ สภาพหลังซ้อมจึงมีสื่อ 1 ชิ้นเสมอ ทางเดิน "รายการว่าง" ไม่เคยถูกเรียก
5. **root cause:** การซ้อม take ที่ย้อนไม่ได้พิสูจน์ได้แค่ส่วนก่อนกระทำการ ไม่มีขั้นทดสอบด่านหลังกระทำการด้วยข้อมูลที่จำลองสภาพหลังการกระทำ (known-answer test ทั้งกรณีมีและไม่มี)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ด่าน take ตรวจแค่ว่ามีคลิปซ้อมที่ผ่าน · กฎ CLAUDE.md §0 "เครื่องมือวัดที่เขียนเองต้องผ่านตัวอย่างที่รู้คำตอบ (ต้องพบ 1 · ต้องไม่พบ 1)" ไม่ได้ถูกใช้กับ `listPresence` ฝั่ง "ไม่พบ"

## 5. แนวทางการแก้ไข (Fix)

- แก้ `scanNdlpJson`/`listPresence`: รายการว่างจาก GET รายการที่รู้จัก หรือหน้าจอ "ไม่พบข้อมูล" = ไม่มีสื่อ · คง stop "not loaded" ไว้เฉพาะเมื่อไม่มี GET จริง · ทดสอบกับตัวอย่างที่รู้คำตอบทั้ง 2 ฝั่ง
- เพิ่ม `--phase after` (อ่านอย่างเดียว) อัดรายการ NDLP ว่าง + สื่อบน OLS เหมือนเดิม แล้วต่อท้ายคลิปลบจริง ตามมติเจ้าของงาน

**ยืนยันแล้วด้วย:** log/summary ข้างบน · เฟรมสุดท้ายของคลิป · ledger L330-331
