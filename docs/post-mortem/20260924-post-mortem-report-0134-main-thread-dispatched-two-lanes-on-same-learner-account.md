## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

จุดตัดสินใจที่ผิดอยู่ที่เธรดหลักตอน dispatch: มองความขัดกันระหว่าง 2 เลนแค่ว่า "เลน Feed ต้องไม่เขียนความคืบหน้าบนบัญชีนี้" ซึ่งกันไม่ให้เลน Feed ไปรบกวนเลน Badge แต่ไม่กันทิศกลับ — การเขียนของเลน Badge เปลี่ยนสิ่งที่ขึ้นบนจอของบัญชีนั้น และจอนั้นคือหลักฐานที่เลน Feed กำลังอัด

### 5 Whys

1. **ทำไมหน้าต่างเหรียญ Gold ไปค้างในคลิป Feed_TC_001?** — เพราะเหรียญ Gold ของบัญชีผู้เรียนเกิดที่ 23:51:44Z และยังไม่ถูกกดรับตอนเลน Feed เปิด `/trending` ด้วยบัญชีเดียวกันที่ 23:51:56Z
2. **ทำไมเลน Badge ถึงเขียนบนบัญชีนั้นในเวลาเดียวกัน?** — เพราะทั้ง 2 เลนได้รับบัญชีผู้เรียนเดียวกันและรันขนานกัน: เลน Badge ต้องเขียนความคืบหน้าและเหรียญ เลน Feed ต้องอัดหน้าจอของบัญชีเดียวกัน
3. **ทำไมเธรดหลักจ่ายบัญชีเดียวกันให้ 2 เลนพร้อมกัน?** — เพราะบรีฟของเลน Feed กันแค่การเขียนของเลน Feed เอง ("ห้ามเขียนความคืบหน้าบนบัญชีนี้") เธรดหลักไม่ได้คิดถึงผลของการเขียนจากอีกเลนที่ขึ้นบนจอ (หน้าต่างเหรียญ · ลำดับฟีด)
4. **ทำไมไม่มีอะไรหยุดการจ่ายงานแบบนี้?** — เพราะด่านร่วมระหว่างเลนมีแค่ `REC.lock` ที่ล็อกการอัด (บรีฟบรรทัด 20) ขั้นเตรียมข้อมูลของเลน Badge (`prep2` นอกกล้อง) ไม่ต้องจอง lock นี้ · preflight ของเลนตรวจแค่ว่า session ยังมีชีวิต · `agent-dispatch-guard` ไม่มีการตรวจบัญชีเลย
5. **ทำไมการจัดสรรบัญชีถึงไม่มีด่าน?** — เพราะการจัดสรรบัญชีเป็นข้อความในบรีฟแต่ละฉบับ ที่เธรดหลักตัดสินใจเองทุกครั้งที่ dispatch (แบบเดียวกับที่ #0122 และ #0126 พบว่าบรีฟเป็นข้อความ ไม่มีด่านในโค้ด) — root cause: ไม่มีล็อกบัญชีในโค้ดที่บังคับ "1 บัญชี = 1 เลน ณ เวลาหนึ่ง" ทั้งตอน dispatch และตอนเปิด context ของบัญชี

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- `REC.lock` / `capture/rec_lock.sh` (มาตรการจาก #0122): ล็อกเฉพาะคำสั่ง take ไม่ล็อกบัญชี และการเขียนนอกกล้องไม่ต้องจอง
- preflight ของเลน Feed (`<creator account>_lane_progress.jsonl` บรรทัด 54): ตรวจ session และ `REC.lock` เท่านั้น
- `agent-dispatch-guard`: ตรวจการเขียนผลลงดิสก์และตัวแปรการรัน (#0121) ไม่มีกติกาเรื่องบัญชี (grep = 0)
- CLAUDE.md §12 เขียนเรื่อง "ไม่ชน (บัญชี)" ไว้เป็นข้อความสำหรับการมอบงานถัดไป ไม่มีด่านในโค้ด
