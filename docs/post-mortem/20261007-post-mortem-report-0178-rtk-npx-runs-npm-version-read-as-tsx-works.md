# Post-Mortem Report #0178 — รายงานว่า `rtk npx tsx` ใช้ได้จากเลขเวอร์ชันของ npm

**ระบบ:** เธรดหลัก (Claude) เปิดหน้าต่างล็อกอินผ่าน Bash ที่ถูก rtk hook เขียนคำสั่งใหม่
**สภาพแวดล้อมที่ได้รับผลกระทบ:** เครื่อง QA · ทุกเซสชันที่ใช้ rtk hook กับ `npx tsx`
**วันที่เกิดเหตุ:** 2026-10-07
**วันที่ค้นพบ:** 2026-10-07
**วันที่จัดทำรายงาน:** 2026-10-07
**ผู้จัดทำ:** Claude (ในเซสชันของเจ้าของงาน)
**ระดับความรุนแรง:** Low — หน้าต่างล็อกอินรอบแรกไม่ขึ้น เสียเวลาราว 30 วินาที แต่ข้อสรุปผิดเสี่ยงให้เชื่อ rtk ต่อไป
**ประเภท:** เดาแล้วพูดเหมือนรู้

## สรุปสั้น (Executive Summary)

คำสั่ง `npx tsx state/popup_login.mts` ใน Bash ถูก rtk hook เขียนเป็น `rtk npx tsx …` แล้ว rtk 0.36.0 รันเป็น `npm tsx …` จึงได้ `Missing script: "tsx"`
ระหว่างสืบ เธรดหลักรัน `rtk npx tsx --version` ได้ `11.13.0` แล้วบอกว่า "ใช้ได้" ทั้งที่เลขนี้คือเวอร์ชันของ npm (tsx จริงคือ v4.19.2)
แก้โดยเรียก `./node_modules/.bin/tsx` ตรง (rtk ไม่เขียนใหม่) และพิสูจน์ด้วย `rtk -v` ที่พิมพ์ `Running: npm tsx …`

---

## 1. ปัญหา (Problem Statement)

- **อาการที่เห็น:** `npm error Missing script: "tsx"` · npm debug log `argv "run" "tsx" "state/popup_login.mts"`
- **สิ่งที่ควรเป็น:** `npx tsx <file>` รันไฟล์ด้วย tsx
- **ขอบเขต:** `rtk npx <tool>` ทุกตัวที่ hook ไม่มีคำสั่งเฉพาะ (ตรวจ `tsx` `playwright` `tsc` `eslint` ด้วย `rtk -v npx` ได้ `Running: npm <tool>` ทุกตัว) · hook เขียน `npx tsx` เป็น `rtk npx tsx` ส่วน playwright/tsc/eslint ถูกแปลงเป็นคำสั่ง rtk เฉพาะ

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมหน้าต่างไม่เปิด?** — เพราะ rtk รัน `npm tsx …` แทน `npx tsx …`
2. **ทำไมรายงานว่าใช้ได้?** — เพราะเห็นตัวเลขเวอร์ชันแล้วถือว่าเป็นของ tsx
3. **ทำไมไม่รู้ว่าเป็นของ npm?** — เพราะไม่ได้เทียบกับตัวอย่างที่รู้คำตอบ (`tsx --version` ตรงๆ)
4. **ทำไมทดสอบด้วย `--version`?** — เพราะเร็ว แต่ `--version` เป็นแฟล็กที่ npm เองก็ตอบ จึงแยกไม่ออกว่าใครตอบ
5. **ทำไมไม่มีชั้นบังคับ?** — กฎ "เครื่องมือวัดต้องผ่านตัวอย่างที่รู้คำตอบก่อนเชื่อ" มีอยู่ (CLAUDE.md §0) แต่ไม่ได้ทำ — root cause

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** กฎข้อนี้เป็นกฎความจำ ไม่มี guard ตรวจ

## 5. แนวทางการแก้ไข (Fix)

- เรียก `./node_modules/.bin/<tool>` หรือ `rtk proxy npx <tool>` (ตรวจแล้ว `rtk proxy npx tsx --version` = v4.19.2)
- ยืนยันพฤติกรรมด้วย `rtk -v npx <tool>` ที่พิมพ์บรรทัด `Running:`

---

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

1. ทดสอบเครื่องมือด้วยงานจริง (ไฟล์ที่พิมพ์ข้อความที่รู้) ไม่ใช่ `--version`
**กฎที่เพิ่มจากเหตุนี้:** `docs/ENVIRONMENT.md` — ทดสอบเครื่องมือด้วยงานจริงที่รู้ผล ไม่ใช่ `--version` · `rtk npx <tool>` รันเป็น `npm <tool>` ให้ใช้ `./node_modules/.bin/<tool>` หรือ `rtk proxy npx`

2. เสนอเจ้าของงาน: รายงานปัญหาต่อผู้ดูแล rtk หรือเพิ่มข้อยกเว้น `npx tsx` ใน hook — เป็น global config ต้องถามก่อน
