## สรุปสั้น (Executive Summary)

smoke dev รอบ 24/Sep ล้มที่ขั้นล็อกอินของบัญชี `fixtureOwnerF1` (`TEST_ACCOUNT_11`, HTTP 400) ผมจึงเปิดหน้าต่างล็อกอินให้เจ้าของงานกรอกบัญชีนั้นทันที
ทั้งที่เมื่อ 22/Sep เจ้าของงานแจ้งไว้ในแชทแล้วว่าบัญชีนี้ใช้ไม่ได้ ต้นเหตุคือรายชื่อบัญชีที่เลิกใช้มีอยู่แค่ในแชท ไม่มีไฟล์กลางให้เครื่องมือและผมอ่าน
ผมปิดหน้าต่างก่อนมีการกรอก จดลง memory เปลี่ยน `fixtureOwnerF1` ไปใช้บัญชีที่เจ้าของงานเลือก และเปิดมาตรการรายชื่อกลางไว้เป็นงานค้าง

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

จุดตัดสินใจที่ผิดคือ ผมตีความ "ล็อกอินไม่ผ่าน" ว่า session หมดอายุ จึงเลือกทางล็อกอินใหม่ทันที ในตอนนั้นดูสมเหตุสมผล เพราะ session ของรอบก่อนๆ หมดอายุบ่อย

### 5 Whys

1. **ทำไมถึงเปิดหน้าต่างให้บัญชีที่เลิกใช้แล้ว?** — เพราะไม่ได้ค้นว่าบัญชีนี้เคยถูกแจ้งว่าเลิกใช้หรือไม่
2. **ทำไมถึงไม่ค้น?** — เพราะ ask-guard ครอบแค่การ *ถาม* แต่การ *เปิดหน้าต่างให้คนกรอก* ไม่ผ่านการ์ดใด
3. **ทำไมค้น memory แล้วไม่เจอ?** — เพราะข้อความ 22/Sep ไม่ได้ถูกยกเป็น memory หรือบันทึกรอบ
4. **ทำไมไม่มีที่จดสถานะ "เลิกใช้"?** — เพราะ roster (`accounts_dev.json`) และ `accounts.ts` ของ e2e ไม่มีช่องสถานะบัญชี
5. **ทำไมไม่มีช่องนี้?** — เพราะไม่มีรายชื่อกลางของบัญชีที่เลิกใช้ ที่ทั้ง roster, e2e และ `session_capture.js` อ่านแล้วปฏิเสธได้เอง (root cause)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ask-guard ครอบแค่ AskUserQuestion · `session_capture.js` ตรวจแค่เป้า env ไม่ได้ตรวจสถานะบัญชี · ไม่มีชั้นใดครอบเรื่องนี้
