## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

`session_verify.js` วัดว่า "คุกกี้ชุดนี้ขอ session OLS ใหม่ผ่าน NDLP link ระหว่างโหลดหน้าได้ไหม" ไม่ได้วัดว่า "session OLS ที่บันทึกไว้ยังมีชีวิตไหม"
ตราบใดที่ `access_token` ของ NDLP ยังไม่หมดอายุ (1 ชม. หลังล็อกอิน) proxy จะสร้าง session ใหม่ให้ทุกครั้ง ตัวตรวจจึงพิมพ์ `ok` แม้ไฟล์ที่ตัวอัดจะเปิดใช้ตายแล้ว
และเพราะบริบทถูกปิดโดยไม่บันทึก session ใหม่ก็ถูกทิ้ง ไม่ได้ช่วยให้ไฟล์กลับมาใช้ได้

### 5 Whys

1. **ทำไมรายงานว่า session pre-prod ใช้ได้ 4/4 ทั้งที่ 2 บัญชีตาย?** — เพราะเธรดหลักยกบรรทัด ok ของ `session_verify.js` มารายงานและใส่บอร์ด
2. **ทำไม `session_verify.js` พิมพ์ ok ให้ session ที่ตาย?** — เพราะมันโหลดหน้าแรกก่อนถาม get-session และ proxy NDLP link สร้าง session ใหม่ในบริบทชั่วคราวนั้น คำตอบจึงเป็นของ session ใหม่ ไม่ใช่ของไฟล์
3. **ทำไมเธรดหลักเชื่อบรรทัด ok โดยไม่สงสัย?** — เพราะไม่ได้พิสูจน์เครื่องมือกับตัวอย่างที่รู้คำตอบว่าตาย (CLAUDE.md §0) · ตัวตรวจไม่เคยถูกทดสอบว่าจะพิมพ์ dead ได้จริงเมื่อไฟล์ตายแต่ access_token ยังดี
4. **ทำไมใช้ `session_verify.js` แทน `recording_preflight.js` ที่ CLAUDE.md §9 กำหนด?** — เพราะ keepalive ของรอบนี้ถูกประกอบขึ้นใหม่ในโฟลเดอร์งาน (`keepalive_preprod.sh` เรียก `session_verify.js`) และ "keepalive พิมพ์ verified" ถูกถือเป็นหลักฐานความพร้อมเอง ไม่ได้ผ่านด่านของ repo · เมื่อรันด่านจริงครั้งแรกยังติด pidfile ผิดรูป เพราะตัวเขียน pidfile ไม่มีรูปแบบบังคับ
5. **ทำไมช่องโหว่แบบเดียวกับ #0078 ยังเปิดอยู่?** — เพราะ #0078 ปิดด้วยมาตรการที่ยัง "ค้าง" ทั้งหมด (P1 พิสูจน์โดยไม่นำทาง · P2 เทสต์ไฟล์ตาย) และไม่มีชั้นใดบังคับว่า **ตัวตรวจ session ทุกตัวต้องถามจากไฟล์โดยไม่มีการนำทาง** หรือบังคับให้คำว่า "พร้อม/done" ต้องมาจาก `recording_preflight.js` — root cause ของคลาสนี้คือ ความพร้อมของ session มีแหล่งตัดสินได้หลายแหล่ง และแหล่งที่ผิดยังพิมพ์คำว่า ok ได้

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- CLAUDE.md §9 (ให้เธรดหลักรัน `recording_preflight.js`) — เป็นกฎที่คนต้องจำ ไม่มีเครื่องมือบังคับ และเธรดหลักไม่ได้รัน
- CLAUDE.md §0 (พิสูจน์เครื่องมือกับตัวอย่างที่รู้คำตอบ) — ไม่มีเครื่องมือบังคับเช่นกัน
- มาตรการ P1–P4 ของ #0078 — สถานะค้าง ไม่มีส่วนไหนถูกนำไปใช้กับตัวตรวจของ pre-prod
- `recording_preflight.js` — ตรวจถูก แต่ถูกเรียกหลังจากรายงานไปแล้ว และเรียกครั้งแรกด้วย pidfile ผิดรูป (ด่านทำงานถูกคือปฏิเสธ)
- บอร์ด — เลน keepalive เดิมอ่านจาก log ของ keepalive (ok 4/4) จึงขึ้น done
