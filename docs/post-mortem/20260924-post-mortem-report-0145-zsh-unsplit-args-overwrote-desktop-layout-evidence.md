# Post-Mortem Report #0145 — zsh ไม่แยกคำ ทำให้สคริปต์วัด layout เขียนทับไฟล์ผลของความกว้าง desktop

**ระบบ:** OLS QA workspace — สคริปต์วัด layout ชั่วคราวของรอบรีเทส (นอก repo)
**สภาพแวดล้อมที่ได้รับผลกระทบ:** ไฟล์หลักฐานในโฟลเดอร์งานของรอบ (ไม่แตะระบบ OLS)
**วันที่เกิดเหตุ:** 2026-09-24
**วันที่ค้นพบ:** 2026-09-24
**วันที่จัดทำรายงาน:** 2026-09-24
**ผู้จัดทำ:** Claude (ในเซสชันของเจ้าของงาน)
**ระดับความรุนแรง:** Medium — แชทรายงาน "ผ่านครบ 3 ความกว้าง" ขณะที่ไฟล์หลักฐานของความกว้างหนึ่งไม่มีแล้ว ถ้าผู้ตรวจอิสระไม่จับ คอมเมนต์รีเทสจะอ้างผลที่ไม่มีหลักฐานรองรับ
**ประเภท:** เดาแล้วพูดเหมือนรู้ (อ้างผลโดยไม่ได้ตรวจไฟล์หลักฐานที่อ้าง)
**ผิดซ้ำจาก:** #0140

## สรุปสั้น (Executive Summary)

ระหว่างรีเทส OLS-759 เธรดหลักวัด layout ที่ 1440 ผ่านแล้วบันทึกเป็น `check_759_desktop.json` จากนั้นรัน
`for v in "820 1180 tablet" "390 844 mobile"; do node check_759.js $v; done` ใน zsh ซึ่งไม่แยกคำตัวแปรที่ไม่มีเครื่องหมายคำพูด
สคริปต์จึงได้อาร์กิวเมนต์เดียว ค่า width เป็น `NaN` และใช้ label เริ่มต้น `desktop` ทำให้เขียนทับผลที่ 1440 ด้วยข้อความ error
รอบที่สองส่งค่าแยกตัวแล้วรันผ่าน แต่ไฟล์ของ 1440 ไม่ได้ถูกตรวจซ้ำ แชทจึงสรุปว่า "ผ่านครบ 3 ความกว้าง"
ผู้ตรวจอิสระ (ขั้น 6c) จับได้ก่อนโพสต์ วัดที่ 1440 ใหม่แล้ว และสคริปต์ถูกแก้ให้ปฏิเสธอาร์กิวเมนต์ที่ไม่ถูกต้องแทนการใช้ค่าเริ่มต้น

## 1. ปัญหา (Problem Statement)

- `check_759_desktop.json` มี `"error": "browser.newContext: viewport.width: expected integer, got float NaN"` ไม่มีผลการวัด (ตรวจด้วย python อ่านไฟล์ 2026-09-24)
- ไฟล์ของ desktop, tablet และ mobile มีเวลาแก้ไขตรงกัน (09:56) ยืนยันว่าไฟล์ desktop ถูกเขียนในรอบที่รันผิด
- แชทรายงานว่า OLS-759 "ผ่านครบทั้ง 3 ความกว้าง" และร่างคอมเมนต์ใส่แถว TC_03 ว่า 1440 / 820 / 390 ไม่ล้น

**สิ่งที่ควรจะเป็น:** ทุกความกว้างที่อ้างต้องมีไฟล์ผลที่วัดจริงอยู่ ณ ตอนที่อ้าง (CLAUDE.md §0 "ตรวจแล้วต้องแนบหลักฐาน" · post-mortem #0140 zsh ไม่แยกคำ)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมไฟล์ desktop มีแต่ error?** — เพราะสคริปต์รอบที่สองเขียนไฟล์ชื่อ `desktop` ทับ
2. **ทำไมรอบที่สองเขียนชื่อ desktop?** — เพราะอาร์กิวเมนต์ทั้งก้อนเข้าไปเป็นตัวแรก ตัวที่สามว่าง สคริปต์จึงใช้ label เริ่มต้น `desktop`
3. **ทำไมอาร์กิวเมนต์ไม่แยก?** — zsh ไม่แยกคำตัวแปรที่ไม่มีเครื่องหมายคำพูด (คลาสเดียวกับ #0140)
4. **ทำไมสคริปต์ยอมรันต่อ?** — สคริปต์ใช้ค่าเริ่มต้นเมื่ออาร์กิวเมนต์ผิด แทนการปฏิเสธ จึงเขียนไฟล์ผลที่มีอยู่แล้วทับด้วยผลที่ใช้ไม่ได้
5. **ทำไมสรุปผ่านทั้งที่ไฟล์หายไป?** — ข้อสรุปมาจากผลที่พิมพ์ในแชทก่อนหน้า ไม่ได้อ่านไฟล์หลักฐานทุกไฟล์ใหม่ก่อนสรุป — **root cause: เครื่องมือวัดที่เขียนเองมีค่าเริ่มต้นที่ทำให้ข้อมูลผิดดูเหมือนรันได้ และข้อสรุปไม่ได้อ่านหลักฐานจากดิสก์ ณ เวลาสรุป**

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** zsh-split-guard ข้อ 4 (จาก #0140) ตรวจรูปแบบ pid list ใน `kill`/`ps` ไม่ครอบ loop ที่ส่งอาร์กิวเมนต์ให้สคริปต์ของรอบ · retest_guard ตรวจรูปแบบคอมเมนต์ ไม่ได้เปิดไฟล์ผลที่แถวอ้าง · ขั้น 6c (ผู้ตรวจอิสระ) เป็นชั้นที่จับได้

## 5. แนวทางการแก้ไข (Fix)

- วัดที่ 1440 ใหม่: `check_759_desktop.json` width 1440 · role SYSTEM_ADMIN · ทั้งสองกล่อง `scrollW 1440 = innerW 1440` · ผู้สร้างที่มีช่องตรงชื่อและรูปทุกราย
- แก้ `check_759.js` ให้หยุด (exit 2) เมื่อ width/height ไม่ใช่จำนวนเต็มหรือไม่มี label แทนการใช้ค่าเริ่มต้น

**ยืนยันแล้วด้วย:** `node check_759.js "820 1180 tablet"` → exit 2 ไม่เขียนไฟล์ · `node check_759.js 1440 900 desktop` → บันทึกผลปกติ
