## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไม SETUP ถึงเขียนจริงโดยไม่มีบรรทัด ledger ก่อนคลิก?** — เพราะ `f003_tc9021_t69.js` ไม่มีฟังก์ชัน `ledger()` อยู่ในไฟล์เลยตอนที่เขียนสคริปต์ครั้งแรก (ยืนยันเองใน `LANE_T2.status.jsonl:38`: "it did not exist in the script")
2. **ทำไมเขียนสคริปต์โดยไม่มีฟังก์ชันนั้น?** — เพราะกฎ "ledger ก่อนทุกคลิกเขียน" ถูกสั่งเป็นข้อความในบรีฟ (`LANE_BRIEF_T69_NOVPN.md` หัวข้อ Writes) เท่านั้น ไม่มี helper กลางที่เลนต้อง import แล้วบังคับให้เรียกก่อน write call
3. **ทำไมไม่มี helper กลางที่บังคับ?** — เพราะสคริปต์อัดคลิปของแต่ละเลน/เคส (เช่น `f003_tc9021_t69.js`) เป็นสคริปต์เฉพาะกิจที่เขียนใหม่ทีละไฟล์ต่อ flow ใหม่ (goal wizard ไม่เคยมี flow เดิมให้อ้างอิง) ไม่ได้สืบทอดจาก wrapper เขียนกลางที่มี ledger ฝังอยู่แล้ว (ต่างจากบางเลนที่ recycle wrapper เดิม)
4. **ทำไมไม่มี wrapper เขียนกลางที่ทุกสคริปต์ต้อง import?** — เพราะ `ols-qa-testing-bot/capture/` (โฟลเดอร์เครื่องมือ off-repo) ยังไม่มี module กลางชื่อเช่น `ledgeredWrite()` ที่ throw ทันทีถ้าจะยิง click เขียนโดยไม่มี ledger entry มาก่อน — มีแค่ `rec_lock.sh` (คุม concurrency) และ `session_verify.js` (คุม session) แต่ไม่มีตัวคุม ledger
5. **Root cause:** กฎ "ledger ก่อนทุกคลิกเขียน" มีสถานะเป็นกฎบังคับ (`CLAUDE.md` ols-qa และบรีฟ) แต่การบังคับใช้ทั้งหมดอยู่ที่การที่ผู้เขียนสคริปต์แต่ละคน/แต่ละเลนต้อง "จำ" ใส่เอง ไม่มีชั้นโค้ดใดปฏิเสธการรันถ้าไม่มี ledger call มาก่อน จุดเดียวที่จับได้คือการตรวจทานของเธรดหลักหลังเขียนเสร็จ (reactive ไม่ใช่ preventive)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ไม่มีชั้นโค้ดใดครอบเรื่องนี้เลยในสคริปต์เฉพาะกิจของ lanes_0923 — `agent-dispatch-guard` คุมเรื่องอื่น (persist-before-print, ขนาด context) ไม่ได้ตรวจเนื้อหาการเขียนของสคริปต์ปลายทาง; `rec_lock.sh` คุม concurrency เท่านั้น การจับได้ครั้งนี้เกิดจากคนตรวจ (เธรดหลัก) grep ledger เทียบชื่อเคสหลังเลนรายงานผล ไม่ใช่กลไกอัตโนมัติ

- เขียนสคริปต์เก็บ `before`/`after` ด้วยการอ้างอิงไฟล์แหล่งที่มาแบบละเอียด (path:line) แม้จะเป็นการแก้ย้อนหลัง ไม่ปั้นตัวเลข ระบุตรงๆ ว่า badge ผลข้างเคียงยังไม่ยืนยันว่าคืนค่าได้ แทนที่จะกลบเงียบ
- แก้ทั้งสองสคริปต์ (`f003`, `f001`) พร้อมกันในการแก้ครั้งเดียว ป้องกันไม่ให้ `f001` (เคสถัดไปที่ยังไม่รัน) มีช่องโหว่เดียวกันซ้ำ

### สิ่งที่ต้องปรับปรุง
- ควรเขียน/เรียกใช้ ledger helper ตั้งแต่ตอนร่างสคริปต์ครั้งแรก ไม่ใช่เพิ่มทีหลัง — ถ้ามี template สคริปต์กลางที่มี `ledger()`ฝังไว้แต่ต้น จะไม่มีช่องให้ลืมได้ตั้งแต่แรก
