บอร์ดสดของรอบรีวิวเทสเคสถูกเผยแพร่ 4 ฉบับ โดยช่อง "อัปเดตล่าสุด" และเวลาในลำดับเหตุการณ์เป็นเวลาที่ผมพิมพ์ประมาณเองตอนเขียน JSON ไม่ได้อ่านจากนาฬิกาหรือบันทึกใดเลย

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

ผมเขียน `board_data.json` ด้วยมือ ช่อง `updated` และ `ts` ถูกกรอกเป็นข้อความ ในบริบทของผมไม่มีนาฬิกา มีแค่วันที่
ผมจึงกะเวลาจากความรู้สึกว่างานน่าจะใช้เวลาเท่าไร ตอนพิมพ์ตัวเลขนั้นมันดูสมเหตุสมผล เพราะเวลาเรียงกันและห่างกันไม่กี่นาที
แต่ไม่มีอะไรในขั้นตอนบังคับให้ค่ามาจากแหล่งที่วัดได้ และ `build_board.js` ยอมรับข้อความอะไรก็ได้ในช่องนี้

### 5 Whys

1. **ทำไมบอร์ดแสดงเวลาที่ยังมาไม่ถึง?** — เพราะช่องเวลาถูกกรอกด้วยค่าที่ผมประมาณเอง
2. **ทำไมจึงประมาณ?** — เพราะในบริบทของผมไม่มีเวลาปัจจุบัน และผมไม่ได้เรียก `date` ก่อนเขียน
3. **ทำไมไม่เรียก `date`?** — เพราะมองว่าเวลาเป็นแค่ป้ายกำกับของบอร์ด ไม่ได้มองว่าเป็นตัวเลขที่ต้องวัด
4. **ทำไมจึงมองแบบนั้น?** — เพราะขั้นตอนทำบอร์ดสั่งให้ใส่เวลา แต่ไม่ได้บอกว่าเวลาต้องมาจากที่ไหน และตัวสร้างบอร์ดก็ไม่ได้ตรวจค่า
5. **ทำไมตัวสร้างบอร์ดไม่ตรวจ?** — เพราะบอร์ดถูกออกแบบให้รับข้อมูลที่เขียนมาแล้ว และเชื่อว่าข้อมูลนั้นถูกต้อง ช่องเวลาเป็นตัวเลขชุดเดียวบนบอร์ดที่ไม่มีแหล่งอ้างอิงบังคับ — ช่องว่างนี้ทำให้ค่าประมาณผ่านไปถึงหน้าจอได้ทุกครั้ง

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** `check_theme.js` ตรวจแค่ธีม ไม่ได้ตรวจเนื้อหา · มาตรการของ #0019 (แนบคำสั่งค้นหาและตัวหารกับตัวเลข) ออกแบบไว้สำหรับตัวเลขที่ได้จากการค้นหา ไม่ครอบคลุมเวลา · #0020 ตรวจชนิดข้อมูลของบอร์ด แต่ไม่ได้ตรวจว่าค่าถูกต้อง

## 5. แนวทางการแก้ไข (Fix)

- ช่อง `updated` ของฉบับที่ 5 มาจากผลลัพธ์ของ `date` ที่รันในคำสั่งเดียวกับการสร้างบอร์ด
- เวลาในลำดับเหตุการณ์ทุกบรรทัดมาจาก timestamp ของบันทึกเซสชัน แปลงเป็นเวลาไทย
- เพิ่มรายการใน Corrections ว่าบอร์ดฉบับที่ 1 ถึง 4 ใช้เวลาประมาณ และตอนนี้แก้เป็นเวลาจริงแล้ว

**ยืนยันแล้วด้วย:** `now=16/Sep/2026 3.29 PM` · `THEME OK (exit 0)` · ผลเผยแพร่ `Version 5`
