## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมรายงานว่า "ยังไม่ได้รัน"?** — เพราะเชื่อข้อความ "rejected" ของ tool ว่าคำสั่งไม่ได้ทำงาน
2. **ทำไมเชื่อ?** — เพราะไม่ได้แยก "tool call ถูกยกเลิก" ออกจาก "โปรเซสลูกถูกหยุด" — การยกเลิกไม่ได้ฆ่าโปรเซส node ที่เริ่มไปแล้ว
3. **ทำไมไม่ตรวจ?** — เพราะไม่มีขั้นบังคับหลังการยกเลิกคำสั่งที่เขียนข้อมูล ให้เช็คโปรเซส ledger และสถานะเป้าก่อนรายงาน
4. **ทำไมพอเจอสถานะเปลี่ยนแล้วยังสรุปผิดอีก?** — เพราะยึดข้อสรุปแรก ("run 2 ไม่ได้รัน") เป็นจริง จึงไปโทษด่านของ run 1 โดยไม่อ่าน ledger ครบทุกบรรทัดของเป้าเดียวกัน
5. **root cause:** ผมรายงานสถานะของงานที่เขียนข้อมูลจากความเข้าใจเรื่องผลของ tool แทนการอ่านหลักฐาน ณ ขณะนั้น (โปรเซส · ledger ทุกบรรทัดของเป้า · สถานะจริง)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ด่านเขียนในสคริปต์ทำงานถูกต้องทั้ง 2 run · ledger บันทึกครบ · ช่องว่างคือไม่มีขั้นที่บังคับให้ผมอ่าน ledger ก่อนพูดถึงสถานะการเขียน
