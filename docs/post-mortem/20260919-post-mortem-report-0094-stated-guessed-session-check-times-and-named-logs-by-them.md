## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

เวลาถูกพิมพ์จากความรู้สึกว่า "น่าจะประมาณนี้" แทนที่จะอ่านจากนาฬิกา แล้วค่าที่เดาถูกใช้ต่อใน 3 ที่: ข้อความถึงคน · ชื่อไฟล์ · ข้อสรุปเชิงเวลา
ชื่อไฟล์เป็นจุดที่ความผิดขยายตัว เพราะตัวสร้างบอร์ดใช้ชื่อไฟล์เป็นลำดับเวลา และข้อสรุปเรื่อง keepalive ขึ้นกับว่าผลตรวจเกิดก่อนหรือหลังเส้นตาย ซึ่งต่างกันเพียงไม่กี่นาที

### 5 Whys

1. **ทำไมเจ้าของงานได้เวลา 18:52 ทั้งที่ผลจริงคือ 18:46:48 / 18:48:05?** — เพราะเธรดหลักพิมพ์เวลาเอง ไม่ได้รัน `date` หรืออ่าน mtime ของไฟล์ผล
2. **ทำไมเวลาเดาไปอยู่ในชื่อไฟล์?** — เพราะเธรดหลักตั้งชื่อไฟล์ log ด้วยมือ (`preflight_<HHMM>.log`) แทนให้คำสั่งใส่เวลาจากนาฬิกา · `recording_preflight.js` พิมพ์ผลออก stdout อย่างเดียว ไม่มีเวลาในบรรทัดผล ทำให้ต้องมีคนตั้งชื่อเอง
3. **ทำไมบอร์ดเลือกไฟล์เก่า?** — เพราะ `gen_board_data.py:233` เรียงตามชื่อไฟล์และเชื่อว่าชื่อสะท้อนเวลา ไม่ได้อ่านเวลาจากในไฟล์หรือจากนาฬิกา
4. **ทำไมสรุปว่า keepalive ต่ออายุ session ได้?** — เพราะเวลาที่เดา (18:52/18:53) อยู่หลังเส้นตายที่อนุมานไว้ (18:47:11 / 18:49:57) จึงดูเหมือน session ที่ควรตายแล้วยังมีชีวิต · ถ้าใช้เวลาจริงจะเห็นว่ายังไม่ผ่านเส้นหนึ่ง และผ่านอีกเส้นเพียง 54 วินาทีบนเส้นที่เป็นการอนุมาน
5. **ทำไมกฎ "เวลาต้องวัด" (CLAUDE.md §0) และมาตรการของ #0060/#0083/#0086 ไม่กัน?** — เพราะมาตรการเดิมบังคับเฉพาะจุด: ช่อง updated ของบอร์ด (#0060 P3 ใน `build_board.js`) และข้อความคอมมิต (#0086 ใน git-staging-guard) · ไม่มีชั้นใดครอบ **ชื่อไฟล์ผลตรวจ** หรือ **เวลาในข้อความแชท** และเครื่องมือตรวจเองไม่ได้ประทับเวลาลงผล — root cause ของคลาสนี้คือ ผลการวัดที่ไม่มีเวลาติดมากับตัว บังคับให้คนต้องเติมเวลาเอง และคนเติมด้วยการเดา

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- CLAUDE.md §0 "เวลาต้องวัด" — กฎที่คนต้องจำ ไม่มีเครื่องมือบังคับในแชท
- #0060 P3 (`build_board.js` ใส่เวลาเองหรือปฏิเสธเวลาในอนาคต) — ครอบเฉพาะช่อง updated ไม่ครอบข้อมูลที่ `gen_board_data.py` เลือกจากชื่อไฟล์
- #0086 (git-staging-guard บล็อกตัวเลขประมาณในข้อความคอมมิต) — ครอบเฉพาะข้อความคอมมิต
- `recording_preflight.js` — ไม่เขียนไฟล์ผลเองและไม่พิมพ์เวลา จึงไม่มีแหล่งเวลาที่ติดมากับผล

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- เก็บผลตรวจทุกรอบไว้เป็นไฟล์ จึงวัดเวลาจริงย้อนหลังได้จาก mtime
- เปลี่ยนชื่อไฟล์ ไม่แก้เนื้อไฟล์ผล
- จดแถวหนี้ในเทิร์นที่รู้ตัว
