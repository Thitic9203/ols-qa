## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

bash แยกคำของ `$var` ที่ไม่ครอบเครื่องหมายคำพูด แต่ zsh (shell ของเครื่องนี้) ไม่แยกโดยค่าเริ่มต้น (ต้องใช้ `${=var}` หรือ array)
loop ที่เขียนแบบ bash จึงส่งค่าทั้งก้อนเป็นอาร์กิวเมนต์เดียว สคริปต์ทดลองรับค่าที่ขาดด้วยค่าเริ่มต้นโดยไม่บ่น และตัวอัดไม่รู้ว่าผู้เรียก "ตั้งใจ" fps เท่าไร จึงไม่มีจุดไหนล้ม

### 5 Whys

1. **ทำไมรัน A กับ B ได้ผลเหมือนกัน?** — เพราะทั้ง 2 รันเป็น fps 12 ไม่เลื่อน (`outFps` 12 ทั้งคู่)
2. **ทำไมไม่ได้ค่าที่ตั้งใจ?** — เพราะ zsh ไม่แยกคำของตัวแปรใน loop ค่า `A 25 18 0` ทั้งก้อนไปอยู่ที่ `TAG` ส่วน `FPS`/`SCROLL` ไม่ได้ตั้ง
3. **ทำไมค่าที่ไม่ได้ตั้งไม่ทำให้ล้ม?** — เพราะ `cand_test.js:8` มีค่าเริ่มต้น `FPS || 12` และ `SCROLL === '1'` (ไม่ได้ตั้ง = ปิด) — ค่าเริ่มต้นทำงานแทนเงียบๆ
4. **ทำไมบทเรียนของ #0097 ไม่กัน?** — เพราะมาตรการ #0097 อยู่ที่ `qa_recorder.js` (`resolveOpts()` ทิ้งค่าไม่ได้กำหนด + ปฏิเสธ fps ที่ใช้ไม่ได้) — fps 12 เป็นค่าที่ใช้ได้ ตัวอัดจึงรับ ส่วนสคริปต์ทดลองที่เขียนใหม่ในรอบนี้ไม่มีด่านเดียวกัน
5. **root cause:** **ไม่มีชั้นที่ผูก "ค่าที่ตั้งใจของแต่ละรัน" เข้ากับ "ค่าที่ตัวอัดใช้จริง" ในการทดลองเปรียบเทียบ** — การตรวจทำได้เฉพาะคนที่นึกเปิด manifest (รอบนี้ agent นึกได้ รอบหน้าไม่มีอะไรรับประกัน)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- `qa_recorder.js` `resolveOpts()` (#0097) — ตรวจว่าค่าใช้ได้ ไม่ได้ตรวจว่าตรงกับที่ผู้เรียกตั้งใจ
- `verify_video.py` — ให้ผลตามคลิป ไม่รู้ว่าคลิปควรเป็น fps เท่าไร
- `CLAUDE.md` §9 (ห้ามค่าเริ่มต้นในเครื่องมือเลือก env) — ครอบแค่ env ไม่ครอบค่าทดลอง
- ชั้นที่จับได้จริงคือ agent อ่าน `outFps` ใน manifest เอง — เป็นพฤติกรรม ไม่ใช่ด่าน

| # | มาตรการ | ชนิด | สถานะ |

| P1 | `startRecording(page, { …, expect: { outFps } })` ใน `qa_recorder.js`: ผู้เรียกระบุค่าที่ตั้งใจ ตัวอัดเทียบกับค่าที่ใช้จริงก่อนเริ่มอัด ไม่ตรง = ล้มทันทีพร้อมข้อความ · และเขียน `requested` ลง `capture.json` · เทสต์คู่ (ตรง ⇒ อัด · ไม่ตรง ⇒ ล้มก่อนอัด) | เครื่องมือ + เทส | ค้าง — ต้องถามเจ้าของงาน (เปลี่ยนเครื่องมือกลางที่เลนอัดใช้อยู่) |
