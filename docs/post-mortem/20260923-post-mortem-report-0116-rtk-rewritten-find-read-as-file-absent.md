## สรุปสั้น (Executive Summary)

เธรดหลักบอกเจ้าของงานและเขียนใน prompt ของ agent ว่า `gen_board_data.py` / `add_track_tiles.py` "ไม่พบบนดิสก์ (ค้นทั้ง bot repo ได้ 0 ไฟล์)" ทั้งที่ทั้ง 2 ไฟล์อยู่ที่ `out/lanes-2026-09-19/board/`
คำสั่ง `find` ที่รันถูก hook เขียนใหม่ผ่าน `rtk` แล้วไม่มีเอาต์พุตของ `find` ออกมา (ออกแต่ของ `ls` ที่ต่อท้าย) ผลว่างจึงถูกอ่านเป็น "ไม่มี"
ทำซ้ำได้ในรอบเขียนรายงาน: `find` ที่มี `-not` ถูกเขียนเป็น `rtk find` ซึ่งปฏิเสธ predicate แบบผสม ถ้าตัด stderr ทิ้ง stdout ว่างและรหัสจบ 1
นี่คือครั้งที่ 3 ของคลาสนี้ (#0051 #0093) มาตรการเดิมเป็นกฎ "ห้ามเชื่อเอาต์พุตที่ rtk ย่อ" ซึ่งไม่ได้กันข้ออ้างเชิงลบ จึงต้องเพิ่มชั้นเครื่องมือ (หัวข้อ 6)

## 1. ปัญหา (Problem Statement)

- แถว `PM-2026-09-23-04` ใน `PENDING.md`: เธรดหลักพูดว่า "ไม่พบบนดิสก์ (ค้นทั้ง bot repo ได้ 0 ไฟล์)" กับทั้งเจ้าของงานและใน prompt ของ agent
- ของจริง (`stat` 2026-09-23): `out/lanes-2026-09-19/board/gen_board_data.py` 24354 ไบต์ แก้ล่าสุด 2026-09-20 08.35.49 · `out/lanes-2026-09-19/board/add_track_tiles.py` 1814 ไบต์ แก้ล่าสุด 2026-09-19 18.34.03
- รันซ้ำด้วย `rtk proxy find` เจอ 2 ไฟล์ (ตามแถว ledger)
- ทำซ้ำกลไกในรอบเขียนรายงาน (`rtk 0.36.0`):
  - `find <bot> -name 'gen_board_data.py' -not -path '*/node_modules/*'; ls <board> | head -2` → บรรทัดแรกเป็น `rtk: rtk find does not support compound predicates or actions (e.g. -not, -exec). Use \`find\` directly.` ตามด้วยผลของ `ls` — ไม่มีชื่อไฟล์จาก `find`
  - คำสั่งเดียวกันต่อท้าย `2>/dev/null` → stdout ว่าง · `rc=1`
  - `find` เดียวกันไม่มีคำสั่งอื่นต่อ → พบ 1 ไฟล์ · ต่อท่อ `| wc -l` → `1`
- เกิดคลาสเดียวกันอีก 2 ครั้งในเซสชันเขียนรายงานนี้เอง (จับได้ก่อนพูด): `grep -rln 'a\|b'` ที่ถูกเขียนเป็น `rtk grep` ตอบ "0 matches" ขณะที่ `command grep -nE 'a|b'` บนไฟล์ชุดเดียวกันเจอ 5 ไฟล์ · `ls -la <2 ไฟล์> | awk …` ไม่มีเอาต์พุตเลย ขณะที่ `stat` แสดงทั้ง 2 ไฟล์

**สิ่งที่ควรจะเป็น:** `CLAUDE.md` §0 — ข้ออ้างเชิงลบต้องแนบคำสั่งค้น + ขอบเขต + จำนวน · สถานะจากผลว่างของ grep/เครื่องมือห้ามใช้ · เครื่องมือวัดต้องผ่านตัวอย่างที่รู้คำตอบ (ต้องพบ 1 · ต้องไม่พบ 1) ก่อนเชื่อ

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

hook `rtk` เขียนคำสั่ง shell ใหม่ให้วิ่งผ่านตัวกรองของ `rtk` ตัวกรองบางตัวรับ syntax ไม่ครบ (`rtk find` ไม่รับ `-not`/`-exec` · `rtk grep` ตีความ `\|` ต่างจาก grep ของระบบ) เมื่อไม่รับ มันพิมพ์ข้อความไป stderr หรือพิมพ์ "0 matches" แทนการล้มดังๆ
ผู้เรียกเห็นเพียง "ไม่มีผลลัพธ์" ซึ่งหน้าตาเหมือนกับ "ค้นแล้วไม่เจอ" ทุกประการ

### 5 Whys

1. **ทำไมบอกว่าไฟล์ไม่มี?** — เพราะอ่านผลว่างของ `find` เป็น "ค้นแล้ว 0 ไฟล์"
2. **ทำไมผลว่าง?** — เพราะ hook เขียน `find` เป็น `rtk find` ซึ่งไม่รับ predicate แบบผสม stdout จึงว่าง (ทำซ้ำได้: `-not` + `2>/dev/null` → ว่าง rc=1) — คำสั่งต้นฉบับของเธรดหลักไม่ได้เปิดอ่านซ้ำ จึงยืนยันได้แค่ว่ากลไกนี้ให้อาการเดียวกับที่ ledger บันทึก
3. **ทำไมไม่รู้ว่าเครื่องมือไม่ได้ทำงาน?** — เพราะไม่ได้ใส่ตัวควบคุมที่รู้คำตอบ (ไฟล์ที่รู้ว่ามีอยู่) ในการค้นครั้งเดียวกัน และไม่ได้อ่านรหัสจบของ `find` แยก — ต่อ `ls` ท้ายทำให้รหัสจบรวมเป็นของ `ls`
4. **ทำไมมาตรการของ #0051/#0093 ไม่กัน?** — เพราะเป็นกฎ "ห้ามใช้ผลบนจอเป็นตัวนับ/ห้าม redirect ลงไฟล์" ซึ่งครอบการ "นับ" และการ "เขียนไฟล์" แต่ไม่ครอบ "ข้ออ้างว่าไม่มี" และไม่มีตัวบังคับ — ข้อเสนอแก้ config ของ `rtk` (#0093 P2) ค้างเพราะเป็น global config ที่ต้องถามก่อน
5. **root cause:** **การค้นทุกครั้งวิ่งผ่านตัวกลางที่อาจกลืนผลโดยไม่ล้ม และไม่มีชั้นเครื่องมือที่แยก "เครื่องมือค้นไม่ได้ทำงาน" ออกจาก "ค้นแล้วไม่เจอ"** — ข้ออ้างเชิงลบจึงพึ่งความจำของคนพูดชั้นเดียว

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- `CLAUDE.md` §0 (ข้ออ้างเชิงลบต้องแนบคำสั่ง+ขอบเขต+จำนวน · ตัวอย่างที่รู้คำตอบ) — ข้อความ ไม่มีตัวบังคับ
- มาตรการ #0051 P2 / #0093 P3 — ครอบการนับและการเขียนไฟล์ ไม่ครอบข้ออ้างว่าไม่มี
- #0093 P2 (ตั้งค่า `rtk` ไม่ให้เขียนคำสั่งบางแบบ) — ค้าง ไม่เคยถูกเคาะ
- ask-guard / investigation-guard — ไม่ได้ตรวจเนื้อหาข้ออ้างใน prompt ของ agent

## 6. แนวทางการป้องกันไม่ให้เกิดปัญหาซ้ำ (Prevention)

ครั้งที่ 3 ของคลาส — มาตรการต้องเป็นชั้นเครื่องมือ ไม่ใช่กฎซ้ำ

| # | มาตรการ | ชนิด | สถานะ |
|---|---------|------|-------|
| P1 | สคริปต์ค้นแบบมีตัวควบคุม (เช่น `scripts/find-with-control.sh <root> <pattern> <known-existing-file>`): เรียก `find`/`grep` ของระบบด้วย path สัมบูรณ์ (`/usr/bin/find`) ไม่ผ่าน `rtk` · ค้นไฟล์ควบคุมที่รู้ว่ามีอยู่ในคำสั่งเดียวกัน · ไม่พบไฟล์ควบคุมหรือรหัสจบ ≠ 0/1 → พิมพ์ `UNVERIFIABLE` และจบด้วยรหัส 3 · พบ → พิมพ์ `FOUND n` / `NOT-FOUND 0 (control ok)` · เทสต์คู่ 3 ทาง (พบ · ไม่พบแต่ตัวควบคุมผ่าน · ตัวควบคุมหาย ⇒ UNVERIFIABLE) และแตะไฟล์จริงบนดิสก์ ≥ 1 ข้อ | เครื่องมือ + เทส | ค้าง — ต้องถามเจ้าของงาน (เพิ่มเครื่องมือกลาง + ต้องผูกเข้า brief/hook ถึงจะมีผล) |
| P2 | ตั้งค่า `rtk` ไม่ให้เขียน `find`/`ls`/`grep` ใหม่ (หรือให้ล้มด้วยรหัสจบ ≠ 0 และข้อความบน stdout เมื่อไม่รับ syntax) — ต่อยอด #0093 P2 | config (global บนเครื่องเจ้าของงาน) | ค้าง — ต้องถามเจ้าของงาน (กฎ global ข้อ 23) |
| P3 | ข้อความถึงเจ้าของงาน/prompt ของ agent ที่เป็นข้ออ้างว่า "ไม่มี/ไม่พบ/0 ไฟล์" ต้องมาจากคำสั่งที่ไม่ผ่านตัวกรอง (`command find` · `/usr/bin/find` · `rtk proxy` · `stat`) และแนบผลของตัวควบคุมที่รู้คำตอบ | กฎ (ใช้กับรายงานนี้แล้ว — ทุกข้ออ้างเชิงลบในรายงาน #0115–#0117 ยืนยันด้วย `command grep -E` / `stat` / `wc -l`) | ทำแล้วรอบนี้ · ตัวบังคับรอ P1 |

**กฎที่เพิ่มจากเหตุนี้:** ผลว่างของคำสั่งที่วิ่งผ่าน hook `rtk` = "ตรวจไม่ได้" จนกว่าจะรันซ้ำด้วยคำสั่งที่ไม่ผ่านตัวกรองพร้อมตัวควบคุมที่รู้คำตอบ — สรุปไว้ใน `docs/CLAUDE-ARCHIVE.md` § Post-mortems (Report #0116)
