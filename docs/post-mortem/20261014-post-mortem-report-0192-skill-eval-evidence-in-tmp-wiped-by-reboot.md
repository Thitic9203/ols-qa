## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

จุดตัดสินใจที่ผิดคือการเลือกที่เก็บหลักฐานตอนวางแผน eval scratchpad ถูกเลือกเพราะ system prompt ของเซสชันบอกให้ใช้ scratchpad สำหรับไฟล์ชั่วคราว
และเขียนได้โดยไม่ต้องขออนุญาต ตอนนั้นไฟล์ eval ดูเหมือน "ไฟล์ทำงานระหว่างทาง" แต่จริงๆ คือหลักฐานที่ขั้นต่อไป (final eval เทียบ baseline) และการตัดสินใจ merge ต้องพึ่ง

### 5 Whys

1. **ทำไมเลน final eval รันเทียบ baseline ไม่ได้?** — เพราะ scenario · fixture · ผลรัน baseline และไฟล์ GRADE หายไปทั้งหมด
2. **ทำไมไฟล์เหล่านั้นหาย?** — เพราะอยู่ใน scratchpad ใต้ `/private/tmp` ที่เดียว และเครื่องรีบูตเวลา 21:21 ซึ่งล้าง `/private/tmp`
3. **ทำไมหลักฐานจึงอยู่ใน `/private/tmp` ที่เดียว?** — เพราะเธรดหลักสั่งเลนให้เขียนลง scratchpad โดยไม่แยกว่าไฟล์ไหนเป็นของสร้างใหม่ได้ ไฟล์ไหนเป็นหลักฐานที่การตัดสินใจภายหลังต้องพึ่ง
4. **ทำไมไม่มีอะไรทักตอนสั่ง?** — เพราะกฎจาก #0008 เป็นข้อความอย่างเดียว ไม่มีเครื่องมือหรือ hook ใดตรวจว่าที่เก็บหลักฐานถาวรหรือไม่ และ agent-dispatch-guard ที่ตรวจ brief ทุกฉบับ ตรวจแค่ว่ามีการเขียนผลลงดิสก์หรือไม่ ไม่ได้ตรวจว่าดิสก์ตรงนั้นอยู่รอดข้ามการรีบูต
5. **ทำไมหลัง #0008 ยังไม่มีชั้นบังคับ?** — เพราะ #0008 ปิดด้วยการแก้ข้อความกฎ (P1/P2) และ memory (P3) ส่วน P4 ที่เป็นตัวดักจริงถูกบันทึกเป็น "ข้อเสนอที่ยังไม่ได้ทำ" แล้วไม่มีใครหยิบไปทำ — **root cause:** ไม่มีชั้นอัตโนมัติที่แยก "หลักฐานที่ต้องถาวร" ออกจาก "ไฟล์ทิ้งได้" ณ จุดที่สั่งเขียน คำเตือนพึ่งให้คนสั่งจำได้เองทุกครั้ง

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- กฎ `CLAUDE.md` จาก #0008 — เป็นข้อความ ต้องจำเอง เธรดหลักไม่ได้เชื่อมกฎนี้กับไฟล์ eval เพราะมองว่าเป็นไฟล์ทำงานระหว่างทาง
- agent-dispatch-guard (`NO_PERSIST_CONTRACT`) — ผ่าน เพราะ brief สั่งเขียนลงดิสก์จริง ด่านนี้ไม่ได้ดูว่าเป็นดิสก์ส่วนไหน
- `PERSIST-BEFORE-PRINT` — เขียนลงดิสก์ก่อนพิมพ์ตามสั่ง แต่ดิสก์ที่เขียนคือ temp จึงไม่ช่วยกรณีรีบูต
- ไม่มีชั้นไหนที่ตรวจว่าโฟลเดอร์หลักฐานอยู่ใน git
