## สรุปสั้น (Executive Summary)

ตอนตรวจชีท 3 ไฟล์ตามที่เจ้าของงานสั่ง เจอ Unit TC003!M4 (Authen_TC_002) ไฟล์บน Drive ยาว 19.24 วิ แต่ไฟล์ที่ตรวจผ่านคือฉบับตัด 13.52 วิ ที่อยู่ในเครื่องเท่านั้น
ไล่ตรวจทั้งหมดแล้ว (`review_0924/trimmed_vs_drive_0924.md`) พบคลิปที่ตัดแก้ 264 คลิป ตรงกับ Drive 38 · ไม่ตรง 218 · ไม่มีลิงก์ในชีท 8 · ในกลุ่มที่ verdict ผ่าน ไม่ตรง 205 และไม่มีคลิปไหนที่ Drive ใหม่กว่าไฟล์ในเครื่อง
กระบวนการตัดคลิปจบที่ "ตัดในเครื่อง + พลิก verdict" ไม่มีขั้นอัปขึ้นปลายทางและไม่มี gate เทียบไฟล์ที่ส่งมอบกับไฟล์ที่ตรวจ

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมลิงก์ในชีทชี้ต้นฉบับ?** — เพราะฉบับตัดไม่เคยถูกอัปขึ้น Drive
2. **ทำไมไม่เคยอัป?** — เพราะ workflow ตัดคลิปจบที่ไฟล์ในเครื่อง + review json
3. **ทำไม verdict ผ่านได้ทั้งที่ยังไม่ส่งมอบ?** — เพราะนิยาม "ผ่าน" ผูกกับไฟล์ที่ตรวจในเครื่อง ไม่ผูกกับไฟล์ที่ชีทชี้
4. **ทำไมตัวนับ/บอร์ดไม่จับ?** — ตัวนับ §4 ขั้น 0 นับจาก verdict json อย่างเดียว ไม่มีชั้นเทียบ md5 ของ Drive
5. **root cause:** ไม่มี gate "ไฟล์ส่งมอบ = ไฟล์ที่ตรวจ" (md5) ในขั้นพลิก verdict และในตัวนับ

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** `put_verdict.py` ตรวจ er-frames กับคลิปในเครื่อง · ไม่มีเครื่องมือใดอ่านลิงก์ในชีทกลับไปเทียบไฟล์
