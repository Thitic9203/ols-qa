## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมตอบเป็นภาษาอังกฤษ?** — เพราะ Output Style แบบ Concise และร่างรายงานเทคนิคถูกเขียนตามภาษาที่ใช้คิด ไม่ได้เช็คภาษาก่อนส่ง
2. **ทำไมไม่เช็ค?** — เพราะกฎภาษาอยู่ใน CLAUDE.md กับ memory ซึ่งเป็นข้อความ ไม่มีด่านไหนตรวจข้อความขาออก
3. **ทำไมส่ง popup ถามทั้งที่มีมติแล้ว?** — เพราะผมถือว่ากฎ "สเปกไม่ชัด = ถาม PO" (§7) ชนะมติของรอบ แทนที่จะอ่านมติของรอบก่อน แล้วค่อยเลือกทางที่ตัดสินเองได้
4. **ทำไมไม่อ่านมติของรอบก่อน?** — เพราะลำดับที่ผมใช้คือ สืบ → ถาม แล้วค่อยค้นตอนที่ guard บล็อก ไม่ได้ค้นมติตั้งแต่ก่อนร่างคำถาม
5. **ทำไมลำดับเป็นแบบนั้น?** — root cause: ไม่มีขั้นบังคับว่า "ก่อนร่างคำถามถึงเจ้าของงาน ต้องค้น `ROUND_DECISIONS.md` ของรอบหาคำสั่งเรื่องการรอ/การถาม" และไม่มีด่านตรวจภาษาของข้อความขาออก

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ask-guard จับได้แค่ว่า "ยังไม่ค้นประวัติ" (บล็อกถูก) แต่ข้อความบล็อกไม่ได้ชี้ไปที่มติของรอบ · ไม่มี hook ตรวจภาษาของข้อความตอบ

## 8. บทเรียนที่ได้ (Lessons Learned)

### สิ่งที่ทำได้ดี
- ask-guard บล็อกคำถามที่ยังไม่ได้ค้นประวัติ ทำให้คำถามไม่หลุดออกไปถึงเจ้าของงาน
- หลังถูกทัก บันทึกมติกับ memory แล้วเดินงานต่อทันที

### สิ่งที่ต้องปรับปรุง
- ค้น `ROUND_DECISIONS.md` เรื่องการถาม/การรอ ก่อนร่างคำถามทุกครั้ง ไม่ใช่หลังถูกบล็อก
- เช็คภาษาของทุกข้อความก่อนส่ง รวมถึงข้อความสั้นระหว่าง tool call
