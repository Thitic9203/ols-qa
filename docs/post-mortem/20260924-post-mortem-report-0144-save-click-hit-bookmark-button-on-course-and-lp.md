## สรุปสั้น (Executive Summary)

ระหว่างรีเทส OLS-721 (แก้ไข/ลบความคิดเห็น) บน Dev สคริปต์ของเธรดหลักกดปุ่มบันทึกการแก้ไขด้วยตัวเลือก
`getByRole('button', { name: 'บันทึก' }).last()` ซึ่งไม่ได้จำกัดขอบเขตไว้ที่กล่องแก้ไขความคิดเห็น บนหน้าคอร์สและหน้าเส้นทางการเรียนรู้
ปุ่มสุดท้ายที่ชื่อ "บันทึก" คือปุ่มบุ๊กมาร์กของเนื้อหา บัญชีทดสอบจึงถูกเพิ่มบุ๊กมาร์ก 2 รายการ และคอมเมนต์ทดสอบค้างอยู่ 2 รายการ
(เพราะขั้นบันทึกล้ม สคริปต์เลยหยุดก่อนถึงขั้นลบ) คืนสภาพผ่านหน้าจอครบแล้ว และสคริปต์ถูกแก้ให้กดเฉพาะปุ่มในกล่องแก้ไข
พร้อมตัวกันที่หยุดการรันทันทีถ้ามีการเรียก endpoint บุ๊กมาร์ก

## 1. ปัญหา (Problem Statement)

- บันทึก network ของรอบแรก (`run_721_course.json` / `run_721_learning-path.json` ในโฟลเดอร์งานของรอบ) มีคำสั่ง
  `POST /api/activities/bookmarks/course/<id>` → 204 และ `POST /api/activities/bookmarks/learning-path/<id>` → 204
  ทั้งที่ขั้นตอนที่ตั้งใจคือ `PATCH /api/activities/comments/<id>`
- ขั้นบันทึกล้ม (`AC_04_save_button {"closed":false,"patches":[]}`) สคริปต์จึงเข้า catch ก่อนถึงขั้นลบ
  คอมเมนต์ทดสอบ 2 รายการ (หนึ่งรายการต่อหน้า) จึงค้างอยู่บนหน้า
- บนหน้าสื่อ (ที่รันก่อน) ตัวเลือกเดียวกันบังเอิญโดนปุ่มที่ถูกต้อง จึงยังไม่มีอาการจนกระทั่งรันหน้าที่สอง

**สิ่งที่ควรจะเป็น:** การกดต้องโดนเฉพาะปุ่ม "บันทึก" ที่อยู่ในกล่องแก้ไขความคิดเห็น ไม่แตะสถานะอื่นของบัญชี
(CLAUDE.md §1 "แตะของห้ามแตะ / ทำเกินโดยไม่บอก" · กฎ global 23 ทำเกินที่สั่ง)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมบัญชีทดสอบถูกบุ๊กมาร์ก?** — เพราะสคริปต์กดปุ่มบุ๊กมาร์กแทนปุ่มบันทึกการแก้ไข
2. **ทำไมกดผิดปุ่ม?** — เพราะตัวเลือกหาปุ่มจากชื่อ "บันทึก" ทั้งหน้าแล้วเอาปุ่มสุดท้าย (`.last()`) ซึ่งบนหน้าคอร์ส/เส้นทางการเรียนรู้เป็นปุ่มบุ๊กมาร์ก
3. **ทำไมใช้ตัวเลือกทั้งหน้า?** — เพราะตอนเขียนสคริปต์ทดสอบบนหน้าสื่อเป็นหน้าแรก และบนหน้านั้นลำดับปุ่มบังเอิญทำให้ `.last()` ถูก จึงไม่มีสัญญาณเตือน
4. **ทำไมไม่รู้ว่ามีปุ่ม "บันทึก" อีกปุ่ม?** — ความรู้ว่าปุ่มบุ๊กมาร์กของ OLS ชื่อ "บันทึก" มีอยู่แล้วใน memory ของเครื่อง
   (reference เรื่องป้ายปุ่มบุ๊กมาร์ก) แต่เป็นบันทึกเรื่องถ้อยคำสเปก ไม่ได้บอกว่าเป็นกับดักของสคริปต์กดปุ่ม และไม่ได้ถูกดึงมาใช้ตอนเขียนสคริปต์
5. **ทำไมไม่มีอะไรหยุดสคริปต์ก่อนเขียนข้อมูลผิด?** — สคริปต์ชั่วคราวของรอบไม่มีตัวกันว่า "ต้องเรียก endpoint ที่ตั้งใจเท่านั้น"
   กฎ §10 ("สคริปต์คลิกที่เขียนข้อมูลต้องยืนยันเป้าด้วยชื่อ/รหัสบนจอก่อนคลิก") ถูกทำแค่กับแถวคอมเมนต์ แต่ไม่ได้ทำกับปุ่มบันทึก — **root cause:
   ปุ่มที่เขียนข้อมูลถูกเลือกด้วยชื่อทั่วทั้งหน้า ไม่ได้ผูกกับ container ของสิ่งที่กำลังแก้ และไม่มีการยืนยันว่า request ที่เกิดขึ้นตรงกับที่ตั้งใจ**

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** `write_guard.js` คุมการเขียนผ่านเครื่องมือของ repo ไม่ครอบสคริปต์ Playwright ชั่วคราวในโฟลเดอร์งาน ·
agent-dispatch-guard คุม prompt ของ subagent ไม่ใช่สคริปต์ของเธรดหลัก · ไม่มีชั้นไหนตรวจว่า request ที่เกิดจากการคลิกตรงกับที่ตั้งใจ

## 5. แนวทางการแก้ไข (Fix)

- ลบคอมเมนต์ที่ค้าง 2 รายการผ่านหน้าจอ — `DELETE /api/activities/comments/<id>` 204 ×2 (`revert_pm12.json`)
- ยกเลิกบุ๊กมาร์ก 2 รายการผ่านปุ่มเดิม — `DELETE /api/activities/bookmarks/<type>/<id>` 204 ×2 · `aria-pressed` ก่อน `true` หลัง `false` (`unbookmark_pm12.json`)
- สคริปต์: `clickSave()` หา "บันทึก" เฉพาะใน container ที่มีกล่องแก้ไขอยู่ และ throw ทันทีถ้าการคลิกทำให้เกิด request ไป `/bookmarks`
  · listener ระดับหน้าพิมพ์ `GUARD-HIT` ทุกครั้งที่มี write ไป `/bookmarks`

**ยืนยันแล้วด้วย:** รันใหม่บนคอร์สและเส้นทางการเรียนรู้ → write call ไป `/bookmarks` = `[]` ทั้งคู่ · `AC_04_save_button {"closed":true,"patches":[204]}` · จำนวนคอมเมนต์ต้น/ท้าย `[1,1]→[1,1]` และ `[0,0]→[0,0]`
