## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมมีโฟลเดอร์ซ้ำ?** — เพราะ `folder(ROOT_NAME, PARENT)` หาชื่อ `Mica Phase 2` ไม่เจอ จึงสร้างใหม่
2. **ทำไมหาไม่เจอ?** — เพราะเจ้าของงานเปลี่ยนชื่อโฟลเดอร์เดิมเป็น `Mica`
3. **ทำไมเครื่องมือถึงพึ่งชื่อ?** — เพราะตอนเขียนผมคิดไว้แค่การรันซ้ำแบบ idempotent ด้วยชื่อ ไม่ได้คิดว่าของบน Drive จะถูกคนแก้ระหว่างงาน ทั้งที่ `drive_state.json` มี id ของโฟลเดอร์หลักเก็บอยู่แล้ว
4. **ทำไมไฟล์อื่นไม่เป็น?** — เพราะโฟลเดอร์ย่อยอ่านจาก id ที่เก็บไว้ ความไม่สม่ำเสมอนี้ทำให้พังแค่บางส่วน
5. **ต้นเหตุ:** เครื่องมือเขียนลงระบบที่คนอื่นแก้ได้ แต่ใช้ข้อมูลที่เปลี่ยนได้ (ชื่อ) เป็นกุญแจ แทนข้อมูลที่ไม่เปลี่ยน (id)

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ไม่มีชั้นใดตรวจก่อนสร้างของใหม่ว่า state มี id อยู่แล้ว มีแค่ `verify` หลังอัปโหลดซึ่งจับได้ถูกต้อง แต่จับได้หลังเขียนไปแล้ว

## 5. แนวทางการแก้ไข (Fix)

- อัปโหลดทับไฟล์ `Mica Phase 2.pdf` เดิม (อยู่ใน `Mica`) ด้วย id เดิม → `37 replaced-by-id`
- ก่อนย้ายโฟลเดอร์ซ้ำไปถังขยะ ตรวจตอนนั้นเลยว่า ชื่อ = `Mica Phase 2`, createdTime = 01:29 และมีลูกแค่ไฟล์เดียวที่เราสร้าง → `{'trashed': True}`
- `drive_up.py`: โฟลเดอร์หลักและไฟล์ใช้ id ใน state ก่อน (ตรวจว่ายังไม่อยู่ในถังขยะ) ส่วนชื่อใช้แค่ตอนยังไม่มี id
- `verify`: ตรวจด้วย id ว่าชื่อ + md5 + PDF + โฟลเดอร์แม่ถูกต้อง และแจ้งถ้าโฟลเดอร์ถูกย้าย

**ยืนยันแล้วด้วย:** `drive_up.py verify` → `root: Mica | trashed: False | under target parent: True` · `37/37`
