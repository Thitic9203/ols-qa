## 1. ปัญหา (Problem Statement)

- ผลการรันจริงใน `out/lanes-2026-09-19/P005_record.out` บรรทัดท้าย:

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

`Object.assign` คัดลอก **ทุกคีย์ที่มีอยู่จริงในออบเจ็กต์ต้นทาง** ไม่ว่าค่าจะเป็นอะไร รวมถึง `undefined`
ดังนั้น `Object.assign({}, { fps: 25 }, { fps: undefined })` ให้ผลเป็น `{ fps: undefined }` ไม่ใช่ `{ fps: 25 }`
ตรงนี้คือความต่างระหว่าง "ผู้เรียกไม่ได้ตั้งค่า" กับ "ผู้เรียกตั้งค่าเป็นความว่าง" ซึ่งโค้ดเดิมมองเป็นเรื่องเดียวกัน
สำนวน `arg('--fps') ? Number(...) : undefined` ในฝั่งผู้เรียกอ่านแล้วดูถูกต้อง เพราะผู้เขียนคาดว่า
"ส่ง `undefined` ไปก็เท่ากับไม่ส่ง" — ซึ่งจริงกับพารามิเตอร์ของฟังก์ชัน แต่ไม่จริงกับการผสานออบเจ็กต์

### 5 Whys

1. **ทำไม ffmpeg ถึงได้ `-r undefined`?** — เพราะ `qa_recorder.js:64` แปลง `o.fps` เป็นข้อความโดยไม่ตรวจชนิดก่อน
2. **ทำไม `o.fps` ถึงเป็นไม่ได้กำหนด ทั้งที่ `DEFAULTS.fps` เท่ากับ 25?** — เพราะ `Object.assign` เอาคีย์ `fps` ที่มีค่า `undefined` จากผู้เรียกมาทับค่าตั้งต้น
3. **ทำไมผู้เรียกถึงส่ง `fps: undefined`?** — เพราะตัวเดินไฟล์บทแปลงธงที่ไม่ได้ใส่เป็น `undefined` แล้วส่งต่อทั้งก้อน แทนที่จะละคีย์นั้นทิ้ง
4. **ทำไมถึงไม่มีใครทักตั้งแต่ตอนเริ่มอัด?** — เพราะไม่มีชั้นไหนตรวจความถูกต้องของค่าตั้งค่าเลย ค่าถูกใช้ครั้งแรกตอนแปลงไฟล์ซึ่งเป็นขั้นตอนสุดท้าย
5. **ทำไมถึงไม่มีชั้นตรวจ?** — **root cause:** ตัวอัดรับค่าตั้งค่าจากผู้เรียกโดยไม่แยกระหว่าง "ไม่ได้ตั้ง" กับ "ตั้งเป็นความว่าง" และไม่ตรวจค่าที่ผสานเสร็จแล้วก่อนเริ่มงานที่กินเวลา — ปิดสองอย่างนี้แล้วปิดทั้งคลาส ไม่ใช่เฉพาะ `fps`

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:**
- ไม่มีชั้นตรวจค่าตั้งค่าของตัวอัดเลยก่อนหน้านี้ — เขียนตรงๆ ว่าไม่มีชั้นไหนครอบ
- `verify_video.py` ครอบเฉพาะไฟล์ที่ออกมาแล้ว รอบนี้ไม่มีไฟล์ออกมาเลย จึงไม่มีอะไรให้ตรวจ
- รหัสจบของ shell เป็น 0 เพราะเขียน `; echo "EXIT=$?"` ต่อท้าย การอ่านรหัสจบอย่างเดียวจึงหลอกได้ — สอดคล้องกับกฎเดิมที่ว่าห้ามอ่านสถานะงานจากรหัสจบผ่านท่อ

## 5. แนวทางการแก้ไข (Fix)

- `qa_recorder.js` — เพิ่มฟังก์ชัน `resolveOpts()` ที่ (ก) ทิ้งคีย์ที่มีค่าเป็นไม่ได้กำหนดก่อนผสาน จึงปล่อยให้ค่าตั้งต้นทำงาน และ (ข) ปฏิเสธอัตราเฟรมที่ไม่ใช่จำนวนบวกที่มีค่าจำกัด ตั้งแต่เริ่มอัด
- `qa_recorder.js` — จุดผสานเดิมเปลี่ยนจาก `Object.assign({}, DEFAULTS, opts)` มาเรียก `resolveOpts(opts)` และส่งออก `resolveOpts` ให้ทดสอบได้โดยไม่ต้องเปิดเบราว์เซอร์
- `capture/_qa_recorder_opts_test.js` — ชุดทดสอบแบบรู้คำตอบล่วงหน้า 9 ข้อ ครอบทั้งข้อที่ต้องผ่าน (ไม่ได้ตั้งค่า → ได้ 25 · ตั้ง 30 → ได้ 30) ข้อที่ต้องถูกปฏิเสธ (0 · ติดลบ · ไม่ใช่ตัวเลข · ความว่าง · ค่าที่ไม่ใช่จำนวน) และข้อที่แตะไฟล์จริงบนดิสก์ (แปลงวิดีโอจริงจากค่าที่ผสานแล้ว ต้องได้ไฟล์ที่มีไบต์จริง)

**ยืนยันแล้วด้วย:** รัน `node capture/_qa_recorder_opts_test.js` ได้ `all checks passed` รหัสจบ 0
รันชุดทดสอบเดิมสองชุดซ้ำเพื่อยืนยันว่าไม่พัง — `node capture/_qa_recorder_tailhold_test.js` และ `python3 capture/_verify_video_tailhold_test.py` เขียวทั้งคู่ รหัสจบ 0
และรอบอัดจริงหลังแก้แปลงไฟล์ออกมาได้ 1,588,161 ไบต์ (รอบก่อนแก้ไม่มีไฟล์เลย)
