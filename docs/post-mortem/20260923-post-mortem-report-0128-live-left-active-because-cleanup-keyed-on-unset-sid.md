## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

สคริปต์เปิดไลฟ์ก่อน แล้วค่อยพยายามหา sid ของไลฟ์ที่เพิ่งเปิด ถ้าหาไม่เจอก็ throw ทั้งที่ไลฟ์เปิดแล้ว ขั้น finally ถูกเขียนว่า "ถ้ามี sid ให้ปิด" จึงข้ามไป สถานะจริงบนระบบกับตัวแปรในสคริปต์ไม่ตรงกัน

### 5 Whys

1. **ทำไมไลฟ์ค้าง ACTIVE?** — เพราะไม่มีขั้นใดเรียกปิดไลฟ์หลังสคริปต์ error
2. **ทำไม finally ไม่ปิด?** — เพราะ finally ปิดด้วยตัวแปร sid ซึ่งยังเป็น null
3. **ทำไม sid เป็น null ทั้งที่ไลฟ์เปิดแล้ว?** — เพราะด่าน `goLive` หา sid จากผลที่อ่านได้ไม่เจอ (ผลมีรายการไลฟ์แต่ไม่ได้แปลงเป็น sid) แล้ว throw ก่อนตั้งค่า
4. **ทำไมไม่มีอะไรจับไลฟ์ที่ค้าง?** — เพราะไม่มี watchdog ที่อ่านรายการไลฟ์ ACTIVE ของบัญชีหลังสคริปต์จบ ไม่ว่าจบแบบไหน
5. **ทำไมการคืนสภาพออกแบบแบบนี้?** — เพราะสคริปต์ผูกการคืนสภาพกับสถานะภายในของตัวเอง แทนที่จะผูกกับสถานะจริงของระบบ (root cause: cleanup ขึ้นกับตัวแปรที่อาจไม่ถูกตั้ง ไม่ใช่ "อ่านของจริงแล้วปิดทุกอันที่ค้าง")

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** ledger บันทึก intent/result ถูกต้อง แต่ไม่มีตัวอ่าน ledger ที่เตือนว่ามี N1 ไม่มี N3 คู่ · ไม่มี watchdog สถานะไลฟ์ · หน้าเว็บของระบบไม่มีทางกลับเข้าควบคุมไลฟ์จาก session ใหม่
