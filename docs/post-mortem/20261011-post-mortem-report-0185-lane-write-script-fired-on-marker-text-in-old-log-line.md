## สรุปสั้น (Executive Summary)

เลน F1 ต้องรอ marker `DEV_THRESHOLD_DONE` ใน `LB1/progress.log` ก่อนเขียนข้อมูล dev สคริปต์รอใช้การค้นข้อความ ซึ่งไปเจอบรรทัดเก่าที่เธรดหลักเขียนไว้เองว่า "F1 holds dev writes until DEV_THRESHOLD_DONE" จึงเริ่มรันเวลา 23:00:48 ทั้งที่ marker จริงยังไม่มี
F1 ตรวจเจอเองและหยุดสคริปต์ด้วย pid ของตัวเองเวลา 23:01:01 · ตรวจแล้วจำนวนคอมเมนต์ของสื่อเป้าหมายยังเท่าเดิม (74) → ไม่มีการเขียน
เธรดหลักเห็นบรรทัดหลอกนี้ใน grep ตั้งแต่ 22:55 (ผลค้น marker ออกมาเป็นบรรทัดนี้) แต่ไม่ได้แจ้งเลนว่าการค้นข้อความชนิดนี้ผิด

## 1. ปัญหา (Problem Statement)

- **สิ่งที่ควรเกิด:** สคริปต์เขียนเริ่มเมื่อ B1 เขียน marker เป็นบรรทัดของตัวเองหลังคืนค่าเกณฑ์แล้วเท่านั้น
- **สิ่งที่เกิดจริง:** `grep DEV_THRESHOLD_DONE` คืนผลจากบรรทัด 65 ของ `LB1/progress.log` ("21:57:30 MAIN GO received … F1 holds dev writes until DEV_THRESHOLD_DONE") → สคริปต์เริ่ม 23:00:48 · หยุด 23:01:01
- **ขอบเขต:** 1 สคริปต์ของ F1 · ไม่มีการเขียน (ตรวจด้วยจำนวนคอมเมนต์ 74 เท่าเดิม)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมสคริปต์เริ่มก่อน?** — ด่านรอค้นข้อความ marker ในไฟล์แล้วพบ
2. **ทำไมพบทั้งที่ยังไม่มี marker?** — ไฟล์มีประโยคบันทึกที่อ้างชื่อ marker อยู่แล้ว
3. **ทำไมการค้นแยกไม่ออก?** — marker ไม่มีรูปแบบตายตัว (เช่น ทั้งบรรทัดเท่ากับ marker หรือขึ้นต้นด้วย timestamp + marker) ใครก็เขียนชื่อ marker ในประโยคได้
4. **ทำไมไม่มีรูปแบบตายตัว?** — บรีฟรอบ 2/3 กำหนดชื่อ marker แต่ไม่กำหนดรูปแบบบรรทัดและวิธีตรวจ
5. **ทำไมเธรดหลักไม่จับได้?** — เห็นบรรทัดหลอกในผล grep ของตัวเองตอน 22:55 แต่อ่านว่าเป็นข้อความธรรมดา ไม่ได้คิดต่อว่าเลนจะใช้วิธีค้นเดียวกัน

**สาเหตุราก:** marker ระหว่างเลนไม่มีรูปแบบที่ตรวจได้แบบตรงตัว และชื่อ marker ถูกใช้ในประโยคบันทึกด้วย

## 4. ผลกระทบ (Impact)

- สคริปต์เขียนทำงาน 13 วินาทีในช่วงห้ามเขียน · ไม่มีข้อมูลถูกเขียน (จำนวนคอมเมนต์ 74 เท่าเดิม)
- เสียเวลาเลน F1 และต้องตรวจซ้ำ

## 5. แนวทางการแก้ไข (Fix)

- F1 หยุดสคริปต์ทันทีและตรวจว่าไม่มีการเขียน (`LF1/progress.log` บรรทัด 114)
- F1 เปลี่ยนการรอเป็นการตรวจ marker แบบเข้มงวด (`LF1/progress.log` บรรทัด 115 "polling strictly") แล้วเริ่มงานหลัง `DEV_REPORT_RESTORED` จริง (23:07)

**ยืนยันแล้วด้วย:** `LF1/progress.log` บรรทัด 114–116 · จำนวนคอมเมนต์สื่อเป้าหมาย 74 ก่อน/หลัง
