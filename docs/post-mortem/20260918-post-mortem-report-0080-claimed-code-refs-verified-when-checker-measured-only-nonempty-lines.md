## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมรายงานว่าครบ?** — อ่านผลของตัวตรวจเป็น "อ้างอิงถูกต้อง" ทั้งที่มันตอบได้แค่ "บรรทัดนั้นมีอยู่"
2. **ทำไมตัวตรวจวัดแค่นั้น?** — เขียนให้เปิดไฟล์ตามเลขบรรทัดแล้วเช็คว่าไม่ว่าง ซึ่งทำได้เร็ว ส่วนการเทียบว่าบรรทัดพูดสิ่งที่ใบอ้างต้องอ่านทีละข้อ
3. **ทำไมช่องว่าง 3 ช่องไม่ถูกพูดถึง?** — ช่องว่างไม่มี path ให้เปิด จึงไม่ถูกนับเป็น "ผิด" ในความหมายของตัวตรวจ และคำสรุปถูกเขียนจากส่วนที่วัดได้
4. **ทำไมผลเลน D8 ถูกพูดเหมือนตรวจแล้ว?** — ส่งต่อข้อความของเลนทั้งก้อนเป็นรายงาน ไม่ได้แยกว่าบรรทัดไหนเธรดหลักเปิดดูเอง ซึ่งเป็นขั้นที่ #0077 เพิ่งกำหนดไว้ในวันเดียวกัน
5. **ทำไมคลาสนี้ยังเกิด?** — ไม่มีรูปแบบบังคับของรายงานที่ต้องแยก "วัดอะไร · กี่ชิ้น · ไม่ผ่านกี่ชิ้น · ยังไม่ได้วัดกี่ชิ้น" ก่อนคำว่า "ครบ" หรือ "ตรวจแล้ว" · และมาตรการของ #0077 ที่อ่านข้อความขาออกยังเป็นข้อเสนอ ไม่ได้ติดตั้ง

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** กฎ #0025/#0076/#0077 เป็นข้อความทั้งหมด · ทุก hook ที่มีตัดสินจากข้อความผู้ใช้หรือการเรียกเครื่องมือ ไม่มีชั้นใดอ่านข้อความที่ส่งถึงเจ้าของงาน
