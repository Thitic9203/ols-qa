## สรุปสั้น (Executive Summary)

รีเทส OLS-883 (กดแก้ไขคอร์สพร้อมกัน 2 หน้าจอ) ต้องทำให้คอร์สที่เผยแพร่อยู่เปลี่ยนเป็น PENDING_EDIT ก่อน สคริปต์ตั้งใจคืนสภาพด้วย `POST /courses/{id}/publish` หลังเทส
แต่ไม่ได้ตรวจก่อนว่า publish จะผ่าน · API ตอบ 400 `lesson.media_not_published` เพราะสื่อในบทเรียนไม่ได้เผยแพร่ (และไม่ใช่สื่อของบัญชีนี้)
คอร์สจึงค้าง PENDING_EDIT · แก้ด้วยการเพิ่ม precheck ในสคริปต์ที่อ่านสถานะลูกทุกตัวก่อนเขียน และปฏิเสธถ้าพิสูจน์ทางกลับไม่ได้ · คอร์สที่ค้างรอเจ้าของงานตัดสินใจ

**สิ่งที่ควรจะเป็น:** ก่อนเขียนข้อมูลที่มีผลถาวร ต้องพิสูจน์ว่าทางคืนสภาพทำได้จริง ณ วินาทีนั้น (CLAUDE.md §0 ข้อสุดท้าย · §9 "destructive fixture มีคู่คืนสภาพใน ledger" · §10 "endpoint ที่มีผลถาวร ต้องเตรียมที่เก็บผลก่อนยิง")

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

ตัดสินว่า "ย้อนได้" จาก transition map ของ value object (`course-status.vo.ts` บรรทัด 33–35) ซึ่งบอกแค่ว่าสถานะเปลี่ยนได้ ไม่ได้บอกเงื่อนไขอื่นใน use-case

### 5 Whys

1. **ทำไมคอร์สค้าง?** — publish ถูกปฏิเสธเพราะสื่อในบทเรียนไม่ได้เผยแพร่
2. **ทำไมไม่รู้ก่อนยิง?** — ไม่ได้อ่านสถานะสื่อในบทเรียนก่อน request-edit
3. **ทำไมไม่อ่าน?** — เชื่อว่า transition map = ทางกลับใช้ได้ ไม่ได้อ่านเงื่อนไขใน use-case
4. **ทำไมเชื่อแค่นั้น?** — ไม่มีขั้นบังคับในสคริปต์ที่ต้องพิสูจน์ทางกลับด้วยข้อมูลสดก่อนเขียน การพิสูจน์อยู่ในหัวคน
5. **ทำไมไม่มีขั้นบังคับ?** — กฎ "คู่คืนสภาพใน ledger" กำหนดให้จดทางกลับ แต่ไม่บังคับให้ **ทดลองเงื่อนไขของทางกลับกับข้อมูลจริง** ก่อนการเขียนครั้งแรก

**ทำไมชั้นป้องกันที่มีอยู่ถึงไม่จับ:** write_guard ครอบเฉพาะ toolkit name-guard ไม่ครอบสคริปต์รีเทส · agent-dispatch-guard ครอบเฉพาะคำสั่งที่ส่งให้ subagent ครั้งนี้รันในเธรดหลัก · ไม่มีชั้นไหนอ่านเงื่อนไข publish

## 5. แนวทางการแก้ไข (Fix)

- สคริปต์รีเทสเพิ่ม `RESTORE PRECHECK`: อ่านสถานะลูกทุกตัว (สื่อในบทเรียน / คอร์สใน LP) ก่อน request-edit · ลูกตัวใดไม่ใช่ PUBLISHED หรืออ่านไม่ได้ = ปฏิเสธ · ไม่พบลูก = ปฏิเสธ (พิสูจน์ไม่ได้)
- ส่ง header CSRF ในคำขอ restore

**ยืนยันแล้วด้วย:** `PRECHECK_ONLY=1` รัน 3 รอบ — คอร์สค้าง → `precheck: restore impossible` (เจอ 1) · LP 2 รายการ → `restore path proven, no write made` (ผ่าน 2) · ทั้ง 3 รอบไม่มี request-edit
