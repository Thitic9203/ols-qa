## 1. ปัญหา (Problem Statement)

- **สิ่งที่ควรเกิด:** เมื่อเจ้าของงานสั่งไม่ใส่รหัส งาน background ทุกตัวที่จะเปิดหน้าต่างใส่รหัสต้องถูกหยุดทันที
- **สิ่งที่เกิดจริง:** ลูป `relogin_row2_attempts` ยังทำงาน และเปิดหน้าต่าง 2 ครั้ง (`logs/relogin_row2_attempts.log`: `00:03:56 dev try1 rc=1` · `00:05:45 preprod try1 rc=1`)
- **ขอบเขต:** 2 หน้าต่าง · ไม่มีการบันทึก state (`SUMMARY saved=0/1`)

## 3. สาเหตุโดยละเอียด (Root Cause Analysis)

### 5 Whys

1. **ทำไมหน้าต่างเด้ง?** — ลูป background ที่ตั้งไว้ก่อนคำสั่งยังรันอยู่
2. **ทำไมยังรัน?** — เธรดหลักไม่ได้หยุดมันตอนรับคำสั่งใหม่
3. **ทำไมไม่หยุด?** — ตอนรับคำสั่ง เธรดหลักไม่ได้ไล่รายการงาน background ที่ตัวเองเปิดไว้ว่าตัวไหนขัดกับคำสั่งใหม่
4. **ทำไมไม่ไล่?** — ไม่มีขั้นตอนบังคับ "คำสั่งเจ้าของงานเปลี่ยน → ตรวจงาน background ทั้งหมด" และลูปไม่ได้ตรวจคำสั่งล่าสุดก่อนเปิดหน้าต่างแต่ละครั้ง
5. **ทำไมลูปไม่ตรวจ?** — ลูปเขียนแบบ shell for-loop ธรรมดา ไม่มีจุดตรวจ "ยังได้รับอนุญาตอยู่ไหม" ก่อนการกระทำที่รบกวนเจ้าของงาน

**สาเหตุราก:** งาน background ที่รบกวนเจ้าของงานถูกตั้งไว้โดยไม่มีจุดหยุด และเธรดหลักไม่ได้ทบทวนงาน background เมื่อคำสั่งเปลี่ยน

## 4. ผลกระทบ (Impact)

- เจ้าของงานถูกรบกวนด้วยหน้าต่างใส่รหัส 2 ครั้ง หลังสั่งห้าม
- ไม่มีข้อมูลเสียหาย · session ไม่ถูกเขียนทับ

## 5. แนวทางการแก้ไข (Fix)

- ลูปจบแล้ว (exit 0) · ตรวจ `pgrep -fl 'session_capture|login_from_sheet'` = ไม่มีโปรเซสค้าง
- บันทึก memory กฎถาวร: ห้ามเด้งหน้าต่างใส่รหัส · session ตายใช้ relink `--force` (ไม่ใช้รหัส)

**ยืนยันแล้วด้วย:** `logs/relogin_*_row2_try1.log` (saved=0/1) · keepalive 00:02 (dev 12 ok · pre-prod 12/12)
