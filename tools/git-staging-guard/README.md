# git-staging-guard

`~/GitHub/ols-qa` มีหลาย session ทำงานพร้อมกันเป็นเรื่องปกติ **`git add <โฟลเดอร์>/` จึงมองไม่เห็น
ความต่างระหว่างไฟล์ของงานรอบนี้ กับไฟล์ที่อีก session เพิ่งเขียนไป 4 วินาทีก่อน** guard ตัวนี้
บังคับให้ stage ด้วยการ **ระบุชื่อไฟล์** ซึ่งเป็นสิ่งเดียวที่คนเขียนรู้ว่าตัวเองเปลี่ยนอะไรบ้าง

## บล็อกอะไร / ไม่บล็อกอะไร

| บล็อก | ผ่าน |
|---|---|
| `git add -A` · `--all` · `-u` · `--update` | `git add path/to/file.js` |
| `git add .` · `./` · `:/` · `"*"` | `git add -- a.js b.sh` |
| `git add <โฟลเดอร์>/` หรือชื่อที่ stat แล้วเป็นโฟลเดอร์ | `git add -p` |
| **path ที่ shell ขยายเอง** — `tools/*` · `*.js` · `$(…)` · backtick · `file[0-9].txt` | `git add ../sibling/file.md` |
| `git commit -a` · `--all` · `-am` | `git commit -m "…"` · `git commit -F -` |
| ซ่อนไว้กลาง chain (`cd x && git add -A`) | `git status` · `git diff` · `git log` · `git push` |
| | **ตัวคั่นที่อยู่ในเครื่องหมายคำพูด** เช่น `echo "a | git add -A"` |
| ทุก path ของ binary (`/usr/bin/git add -A`) | คำสั่งอื่นที่แค่มีคำเหล่านี้เป็นข้อความ |

## สองข้อที่แก้เพิ่มหลังรีวิว (2026-09-06)

- **glob และ command substitution ถูกปฏิเสธ** — `git add tools/*` stage ของชุดเดียวกับที่ก่อเรื่องเป๊ะ
  แต่การขยายเกิดที่ shell ก่อน git จะเห็น คำสั่งที่พิมพ์จึงมีอาร์กิวเมนต์เดียวที่ดูไม่มีพิษภัย ·
  สิ่งที่คนตั้งชื่อไม่ได้ในคำสั่ง คือสิ่งที่คนยังไม่ได้ตรวจ
- **ตัวแยกคำสั่งรู้จักเครื่องหมายคำพูดแล้ว** — เดิมตัดที่ `|` ดิบๆ ทำให้ข้อความในสตริงถูกอ่านเป็นคำสั่ง
  และมันบล็อกคำสั่งรีวิวของ repo นี้เอง 2 ครั้ง การ์ดที่ห้ามคนเขียนถึง git คือการ์ดที่ถูกถอด

## จุดที่จงใจเลือก

- **`git add ชื่อเปล่าๆ` ที่ยังไม่รู้ว่าเป็นโฟลเดอร์ไหม → ผ่าน** ในโมดูล กฎไม่รู้ cwd จึงไม่เดา
  ตัว hook เป็นคนฉีด `stat` จริงเข้าไปแล้วค่อยตัดสิน · การ์ดที่บล็อก `git add file.js` ผิดๆ
  คือการ์ดที่ถูกลบภายในบ่ายวันเดียวกัน และมันจะพาการป้องกันหายไปด้วย
- **node พัง = เตือนแล้วปล่อยผ่าน** ความเสียหายที่ชั้นนี้กันคือ "กวาดไฟล์คนอื่น" ซึ่งกู้คืนได้เสมอ
  ต่างจาก secret guard ที่ต้อง fail-closed เพราะ secret ที่ขึ้น GitHub แล้วเอากลับไม่ได้
  การบล็อก `git` ทุกคำสั่งเพราะ node พัง แพงกว่าสิ่งที่มันกัน
- **ไม่มีสวิตช์ปิด** ทางออกคือพิมพ์ชื่อไฟล์ ซึ่งทำได้เสมอ

## คู่กับ pre-push

guard ตัวนี้กัน "กวาดไฟล์คนอื่นเข้าคอมมิต" ส่วน `scripts/hooks/pre-push` กัน "ครึ่งฟีเจอร์ขึ้น main"
โดยกาง worktree ของ commit ที่กำลังจะ push ออกมารันชุดเทสต์จริง **ไม่ใช่รันบน working tree**
เพราะไฟล์ค้างของ session อื่นทำให้ผลตอบผิดได้ทั้งสองทาง
