# investigation-guard

การตรวจสอบปัญหาใน repo นี้ต้องเป็นการ **สืบ** ไม่ใช่การ **เดา** และการสืบใช้สกิล
`superpowers:systematic-debugging` เป็นหลักเท่านั้น กฎนี้เคยเป็นข้อความใน `CLAUDE.md`
อย่างเดียว — ซึ่งถูกทำตามจนถึงนาทีที่มันไม่สะดวก และนาทีนั้นคือนาทีที่มันสำคัญที่สุดพอดี
โฟลเดอร์นี้คือกฎข้อเดียวกันในรูปที่เครื่องบังคับได้

## 4 ชั้น แต่ละชั้นพอตัวเอง

| ชั้น | ไฟล์ | เหตุการณ์ | ทำอะไร | exit |
|:--:|---|---|---|---|
| 1 | `.claude/hooks/investigation-rule.sh` | `SessionStart` | อ่านตัวกฎขึ้นมาทุก session | 0 เสมอ |
| 2 | ไฟล์เดียวกัน | `UserPromptSubmit` | ส่ง prompt ให้ node ตัดสิน · เข้าข่ายก็ติดธง + สั่งเงื่อนไข | 0 เสมอ |
| 3 | `.claude/hooks/investigation-gate.sh` → `check.js --gate` | `Stop` | ติดธงแต่ไม่เคยเรียกสกิล = **ไม่ให้จบเทิร์น** | **2** = บล็อก |
| 4 | `investigation_rules.test.js` | ทุก push (CI) | กันชั้น 1–3 เสื่อมเงียบ | 1 = เสีย |

ชั้น 3 เป็นชั้นเดียวที่มีฟัน ที่เหลือคือคำเตือน — และคำเตือนถูกอ่านแล้วเดินผ่านได้
**การจบเทิร์นไม่ได้ ผ่านไม่ได้** และจุดนั้นคือจุดเดียวในวงจรที่ "สรุปโดยไม่สืบ" ถูกจับได้จริง
เพราะกว่าจะถึงตรงนั้น ข้อสรุปถูกเขียนลงไปแล้ว และ hook เห็น transcript ทั้งเทิร์น

## การตัดสินอยู่ที่เดียว

`investigation_rules.js` ถือกฎที่เครื่องตัดสินได้ทั้งหมด — ชั้น bash **ไม่ถือ regex ของตัวเองเลย**
มันพิมพ์ "ตัวกฎ" (ซึ่ง drift ไม่ได้) แล้วส่งการตัดสินต่อ สอง runtime ที่ถือ pattern ชุดเดียวกัน
คือสองคำตอบที่รอวันไม่ตรงกัน และวันที่ไม่ตรงกัน ตัวที่ตะโกนกับตัวที่บล็อกจะเลิกพูดถึงกฎข้อเดียวกัน
= การ์ดเริ่มโกหก · `test` ข้อ *"the decision lives in ONE runtime"* ผูกเรื่องนี้ไว้

`node` พังเมื่อไหร่ = ตะโกนดังๆ แล้วปล่อยผ่าน การ์ดที่พังแล้วขังงานเอาไว้ คือการ์ดที่ถูกถอดทิ้ง
ภายในวันเดียว

## เส้นที่จงใจตีให้แคบ

`ตรวจสอบ` เฉยๆ **ไม่ติดธง** และการยกเว้นนี้คือหัวใจของดีไซน์ — ที่นี่เป็น QA workspace ที่คำนี้
โผล่แทบทุก prompt การ์ดที่ติดธงทุก prompt คือการ์ดที่ถูกปิดภายในสัปดาห์เดียว (บทเรียน PM-010:
alert ที่เด้งตอนข้อมูลปกติ คือวิธีที่ alert จริงถูกสอนให้คนมองข้าม)

ติดธงเฉพาะถ้อยคำที่บอกว่า **มีอะไรเสียอยู่** หรือ **ให้ไปหาว่าทำไม** เท่านั้น —
พัง · ล่ม · ค้าง · เพี้ยน · ไม่ทำงาน · เฟล · บั๊ก · error · traceback · ทำไม · หาสาเหตุ · root cause
รายการเต็มอยู่ใน `INTENT` และเทสต์ผูกไว้ทั้งสองขา: ขา "ต้องติด" และขา **"ต้องไม่ติด"**

## อะไรนับว่า "เรียกสกิลแล้ว"

นับจาก transcript ตั้งแต่เวลาที่ติดธงเป็นต้นไป — เรียกในเธรดหลัก (`Skill`) หรือส่งให้ subagent
(`Task`/`Agent` ที่ prompt สั่งให้เรียกสกิลนี้) ก็นับทั้งคู่ รวมถึงตอนคนพิมพ์ slash command เอง

เทียบบน **ตัว tool_use ที่ serialize แล้ว** ไม่ผูกกับชื่อฟิลด์ — วันที่ harness เปลี่ยนชื่อฟิลด์
ตัวเช็คที่ผูกชื่อไว้จะเริ่มตอบ "ยังไม่เรียก" เงียบๆ แล้วบล็อกงานที่ถูกต้อง ซึ่งจบลงที่การ์ดถูกถอด
เหมือนกัน · **ของที่เรียกก่อนติดธงไม่นับ** เพราะมันเป็นการสืบของปัญหาคนละเรื่อง

## คำที่กลบการเดา — รายงาน ไม่ใช่บล็อก

`น่าจะ · อาจจะ · โดยทั่วไป · by design · likely · ตามสเปก` ถูกไล่หาในคำตอบของ agent แล้ว
**รายงานเฉยๆ** ทุกคำมีที่ใช้ถูกต้อง — `ตามสเปก` ถูกต้องทันทีที่เปิดสเปกอ่านจริง และไม่มี hook ไหน
มองเห็นว่าเปิดหรือยัง ถ้าเอามาบล็อกจะผิดบ่อยจนถูกปิด แล้วพาชั้นที่บล็อกจริงล้มไปด้วย
การเรียกชื่อมันตอนจบการสืบ คือทั้งหมดที่ชั้นนี้ตั้งใจทำ

## ไม่มีสวิตช์ปิด มีแต่ทางออกที่ถูกบันทึก

```bash
node tools/investigation-guard/check.js --not-an-investigation "เหตุผล"
node tools/investigation-guard/check.js --not-an-investigation "เหตุผล" --session <session-id>
```

**มีธงค้างมากกว่า 1 session = ปฏิเสธ พร้อมบอกชื่อทุกอันให้เลือก** — เดิมมันหยิบไฟล์ที่ถูกแก้ล่าสุด
โดยไม่รู้ว่าใครสั่ง ซึ่งใน worktree ที่มีหลาย session (ที่นี่มีเป็นปกติ) แปลว่าไปปลดการ์ดของคนอื่น
ทั้งที่ธงของตัวเองยังค้าง — พิสูจน์แล้วว่าเกิดจริง

ใช้เมื่อธงติดผิดจริงๆ เท่านั้น (เช่นสั่งแก้ typo คำว่า `error` ในเอกสาร) **ไม่ใส่เหตุผล = ปฏิเสธ**
เหตุผลถูกเขียนลง state file และถูกพิมพ์ออกมาให้เจ้าของงานเห็น — การยกเลิกธงแบบเงียบๆ
ไม่ต่างจากการปิดการ์ด · เทสต์ผูกไว้ว่าต้องไม่มี `--force` / `SKIP_*` / `no-verify` โผล่ในไฟล์ไหนเลย

## กันติดกับ

`Stop` hook เคารพ `stop_hook_active` — ปฏิเสธหนึ่งครั้งต่อหนึ่งความพยายามจบเทิร์น แล้วรอบถัดไป
ปล่อยผ่านพร้อมทวงซ้ำ **ธงยังติดอยู่** จึงทวงใหม่ในความพยายามครั้งต่อไปเสมอ session ที่ออกไม่ได้
คือ session ที่จบลงด้วยการลบ hook ทิ้ง ซึ่งแย่กว่าไม่เคยมี hook

## คำสั่ง

```bash
node tools/investigation-guard/check.js --status                       # ดูธงที่ค้างอยู่
node tools/investigation-guard/investigation_rules.test.js             # 20 เคส ต้องเขียวก่อน commit
```

**อ่าน transcript ไม่ได้ ≠ ไม่เคยเรียกสกิล** — สองอย่างนี้แยกกันแล้ว ยังปฏิเสธการจบเทิร์นเหมือนเดิม
(ตรวจไม่ได้ไม่นับว่าผ่าน) แต่เหตุผลที่แจ้งเป็นเรื่องจริง ไม่ส่งคนไปแก้ของที่ไม่ได้พัง

**ไฟล์ state ถูกล้างเอง** — เฉพาะอันที่จบแล้วและเกิน 7 วัน · ธงที่ยังค้างไม่ถูกลบไม่ว่านานแค่ไหน
(ไม่งั้นการรอให้ครบสัปดาห์จะกลายเป็นวิธีปลดการ์ด) · อันที่ค้างเกิน 30 วันถือว่า session ตายแล้ว

State อยู่ที่ `.claude/.investigation-state/<session_id>.json` — ไฟล์ชั่วคราวต่อ session
ไม่ commit (อยู่ใน `.gitignore` แล้ว)
